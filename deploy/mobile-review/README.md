# 完整课程手机测试站

测试地址：`https://preview.canranstudio.cn/`，2026-11-17已启用。复用 `server/run.js`、课程和纪念册实现，使用独立账号、数据库和 card-key。验收台的演示成绩不能替代这里的真实登录、保存和刷新测试。

## 独立资源

- 服务/用户：`canran-mobile-review`；监听 `127.0.0.1:4404`。
- 不可变源码：`/opt/canran-mobile-review/releases/<已验证版本>`；测试站自己的 `current`。
- 数据：`/var/lib/canran-mobile-review`，严禁指向或复制官网数据目录。
- 配置：本目录的 service 和独立 nginx host；测试账号通过原有登录验证访问课程，匿名不能下载课程包。
- 公网 DNS：`preview` A 记录已指向 `59.110.217.36`，默认线路，TTL 600秒；Google和Cloudflare公网解析均已核验。
- HTTPS：独立证书 `preview.canranstudio.cn`，由已有的`certbot-renew.timer`续期，专用[续期钩子](renewal-hook.sh)在验证nginx配置后重载证书。ACME目录为 `/var/lib/canran-mobile-acme`，与700权限的账号数据目录分离，使nginx可读取验证文件。

## 上线前准备

1. 冻结验收通过的源码与资产清单，记录每文件 SHA-256；发布包只包含运行时文件与锁定依赖，不含 `.data`、数据库、密码、trace 或测试记录。记录分支 HEAD 和未提交差异；不能把工作区快照称为已提交版本。
2. 使用独立用户和目录安装测试版本，以服务专用用户初始化**空的**测试数据目录：`node scripts/setup-mobile-review.js /var/lib/canran-mobile-review`。重复执行会拒绝覆盖。受保护的 `review-credentials.json` 只供验收者查看，不放进 Git 或链接参数。
   安装依赖后，确保测试服务组可读取版本目录和执行依赖程序；依赖以严格umask安装时不能遗漏这一步。以stdin执行维护脚本前先切换到该版本目录，不能让服务用户继承不可读的管理员主目录。
3. 先启动独立服务，检查登录页、匿名保护和测试账号流程。服务有独立资源限制，官网 service、current 和数据目录保持原位。
4. DNS 与有效 HTTPS 就绪后启用独立 host。用实体安卓手机的微信与夸克走完学习、刷新、纪念册保存和返回流程。
5. 记录手机型号、浏览器、测试版本和结果。手机验收通过后，再执行官网 PR、合并、发布；手机测试站可停止或切回上一个测试 release，不改官网。

## 本地验证

初始化一个新的绝对目录后，以该目录作为 `LESSON_DATA_DIR`，设 `LESSON_PORT=4404`、`LESSON_BASE_PATH=/`、`LESSON_ORIGIN=http://127.0.0.1:4404` 运行 `node server/run.js`。本地实例不能被称作公网手机测试站。
