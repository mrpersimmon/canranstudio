# 保存GIF白边修复

2026-10-30，`codex/book-version`。本轮修复正式纪念册及课程内的GIF导出，未提交、推送或发布官网。

## 根因

实际从本地纪念册保存Lesson 1–2的GIF，第一帧四角和四边中点都是不透明浅色`[255,253,245,255]`，向内约4px才出现深色卡框。问题在文件内部，不能通过页面CSS处理。

原`award-card-layout`把卡框缩进源画布6px，缩放后留下约4px外边距；`award-gif`又在每帧先铺不透明浅色底。第一帧没有声明透明，即使后续增量帧使用透明索引、文件元数据报告`hasAlpha:true`，已经画入的浅色底仍一直存在。

此前M17的裁切只遮住历史原型中的显示白边，没有消除实际下载文件中的白边。本轮明确修正该边界，不能把页面观感通过当作导出验收。

## 修复

- 4px深色卡框从1640×880源画布最外沿起画，圆角外保持透明。满星金边紧接深色框，内线再接金边，没有新的浅色隔离带。
- 每帧清空透明画布，不再铺浅色垫底。GIF透明索引固定为0，与逻辑背景索引一致，第一帧和后续帧均声明透明。
- 按源alpha阈值128转换为GIF的一位透明，其他颜色索引独立；没有按“白色”抠图，因此纸张、人物白衣和高光仍不透明。
- 保留固定调色板、静态像素索引稳定、增量帧、取消控制及逐帧释放。导出仍为984×528、60帧、每帧80ms、无限循环；人物、文字、姓名、星数、日期及其排版坐标不变。

实现：[共享画布](../../core/award-card-layout.js)、[GIF编码](../../core/award-gif.js)。两条现有保存路径直接复用修复，不增加另一个导出器，不重生纪念卡素材或改动历史原型GIF。

自动检查共10份GIF／600帧，逐帧验证透明角、四边无外留白、边界无浅色残边、内部完整不透明、透明轮廓一致，以及满星金边紧贴卡框且持续变化。检查直接解码保存后的合成帧，不只看文件元数据或页面截图。

首轮在旧实页文件准确失败于“首帧四角alpha=255”；第一次修改后又检查到金边与新外框间有静态浅色间隙，增加四边金边探针后在候选文件上复现失败，再将框线同心贴合，最终复验通过。旧文件和候选截图保留，不把候选通过的部分透明检查冒称最终完成。
