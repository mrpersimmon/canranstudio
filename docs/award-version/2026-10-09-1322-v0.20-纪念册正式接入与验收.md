# 纪念册正式接入与验收

2026-10-09。用户已确认翻页画面，并授权按推荐方案接入真实账号。本文记录实现范围；提交、合入和上线另列，不能把本地验证当作线上已发布。

## 学生看到什么

- 学生首页和新版纪念卡页都有“我的纪念册”。直接打开 `/awards/` 仍需学生登录；本地子目录部署对应 `/lesson/awards/`。
- 首版接入 Lesson 1–2、3–4、5–6，使用已确认的三张插画。其他单元沿用原证书，不能拿示例数据填满纪念册。
- 每单元恰好五个答题区。每区每题本轮第一次提交都正确，才获得一颗星。订正可以完成学习，但本轮不补发星星；重新挑战整区可再争取。教学阅读不送星，使用提示另作学习记录。
- 获得第一颗星后自动入册。1–4 星显示对应数量；5 星加金边，显示服务器确定的首次满星日期。重练、后续错答、重开本课和换设备都不撤星、不改日期。
- 姓名直接来自当前登录学生，修改账号姓名后跟随更新，不提供卡面填名。没有获星时显示空册和“去我的课程”。本机等待上传的成果明确提示，不能伪造已入册卡片。
- 桌面双页，窄屏单页；支持按钮、方向键、页角滑动、目录、放大和保存 1640×880 PNG。保留用户选定的翻页色彩和动画偏好。图片、字体由客户端绘制，不把学生姓名发送给图片生成服务。

## 存储与权限

获星记录存于现有 SQLite `unit_awards`，以学生、单元、奖励版本为联合主键。服务器校验课程、版本、题目内容和整个回合的首次提交记录；客户端不能仅上传“5 星”。首次满星时间由服务器一次写定。

`GET /api/awards` 只读会话所属学生，返回其已获得的全部已登记版本，不接受客户端指定别人的身份。接口、页面不缓存个人数据。班级关闭课程不会删除已获得纪念卡，也不会因允许看卡而开放课程答案。未来增加收藏版本时保留原登记项及其图片；一般图片修补不自动创造新收藏版本。

退出、切换学生、页面重新激活或从浏览器历史恢复时，先遮住旧身份的画面，再核对登录。不会从匿名本机记录创建学生收藏。账号过期时重新登录；断网不展示无法确认身份的旧收藏。未上传成果仍留在原学生的本机队列中，联网后按原账号同步。

## 加载、缓存与服务器负担

正式源码在 `award-book/`，`poc/award-book/` 保留为历史设计样板，不发布示例账号。账号服务器启动时打包书页，发布检查同时校验其构建。

1. 打开纪念册读取一次个人收藏。若有待同步成果，先尝试上传再刷新收藏。
2. 图片和字体就绪后才显示书页。首次准备当前及相邻页；后续翻到新页前保留旧画面，失败可重试，不露出半张图。
3. 插画、装帧、字体和脚本使用内容哈希地址及长期浏览器缓存。课程 Worker 不把纪念册资源错认成某门课程的资源。个人接口始终 `no-store`。
4. 翻页、放大、PNG 保存均在浏览器完成，不为每次翻页写数据库，不在服务器生成图片。完整字体支持真实中文姓名，不能沿用只包含示例“小雨”的子集。

本机打包总量约 2.18 MB，包含三张插画和完整字体；这不是每次访问的流量，也不是服务器承载人数结论。首次下载主要消耗带宽，复访复用静态资源。生产并发、安卓微信真机翻页与保存仍属发布验收，不能用电脑本地结果替代。
