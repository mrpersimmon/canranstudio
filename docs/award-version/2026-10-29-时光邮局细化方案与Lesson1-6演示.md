# 时光邮局纪念册细化方案与 Lesson 1–6 演示

当前统一入口为[纪念册统一设计标准](纪念册统一设计标准.md)。本记录保留早期方案与过程；其中原图跳转已经取消，最新实现扩展到Lesson1–12，后续按统一标准执行。

2026-10-29，`codex/book-version`。本方案承接最新三选一中的方案 2「时光邮局」。用户要求增加搜索，完成 Lesson 1–6 可操作演示，并保留现有纪念卡主体。

当前交付是独立原型 `poc/keepsake-postoffice/`，没有替换正式 `award-book/`。主题为「每六课一封信，把三张旅程纪念收进邮局」。三个教学单元对应三张主卡；柜台大卡是当前选中卡的展示，不另计一张。

## 产品结构与交互

首页由邮局柜台、搜索入口、本章三卡和章节信箱组成。沿用课程页面的奶油底色、森林绿、暖木与赤陶小镇环境，主角始终是用户已经获得的原纪念卡。保留课程、纪念册、我的三个导航位置。

| 区域 | 展示与操作 | 完成状态 |
| --- | --- | --- |
| 柜台 | 展开信封、完整横版原卡；点卡进入详情并保存，不另设“查看原卡”按钮 | 已实现三张样板 |
| 本章收藏 | 一行三张完整缩略图；绿色框与 Lesson 底色同时标识选中；轻点换卡 | 已实现 |
| 搜索 | 标题旁44px放大镜打开搜索抽屉；结果有缩略图、完整课号、卡名与章节 | 已实现 Lesson 1–6 |
| 原卡查看 | 原图、首次五星日期、上一张／下一张、打开完整原图、下载原 GIF | 已实现 |
| 章节信箱 | 每章收纳三张；显示名称、范围、获得数量；进入后恢复选中卡 | 本演示仅初识小镇；全 24 章待接入 |
| 课程与我的 | 正式版复用现有公共导航和账号入口 | 演示显示范围说明，不接真实账号 |

手机采用纵向阅读。首屏优先呈现搜索、一张完整主卡和三张选择缩略图；短屏允许自然向下滚动，不用压缩卡片或字号来保证所有内容同屏。章节入口位于主操作下方，滚动后始终可达。

用户确认简化入口：移除三张缩略图下面的独立“查看原卡”按钮，章节信箱直接接在缩略图后。信封上的完整主卡是查看和保存的入口；点击后打开原有详情，可保存原卡动图。缩略图只切换所选卡，避免误触即下载。

选择卡片时只改变柜台卡片层，背景、标题、缩略图区域与导航保持挂载。卡片用约 180–220ms 的淡入和 6px 内位移反馈；不让整页白场，不进行 3D 翻书。减少动态效果时关闭容器过渡；已有 GIF 仍是原文件，静态替代属于后续无障碍接入工作。

## 搜索规则

搜索范围是所有当前可访问的主卡，不受当前章节限制。原型只有 Lesson 1–6；正式接入后扩展到全部已授权收藏。可访问但未获得的单元，可以显示「尚未获得」并进入课程，不伪造纪念卡；未授权的课程不从搜索泄漏。

| 输入 | 预期结果 |
| --- | --- |
| `2`、`Lesson 2`、`第２课` | Lesson 1–2 礼貌小帮手 |
| `3-4`、`3–4`、`Lesson ３－４` | Lesson 3–4 认领小达人 |
| `2–5` | 与范围相交的三个单元 |
| `认领`、`新朋友` | 对应卡名包含的主卡 |
| 空白或清空 | 当前可检索的全部主卡 |
| `11` | 不误命中 Lesson 1–2；演示提示尚未接入 |
| 无匹配文字 | 显示无结果及可尝试的输入，可一键清空 |

先做 NFKC 归一化、英文大小写及横线统一。纯数字按课程范围判断，禁止数字子串匹配。结果选中后关闭搜索与键盘、选中所属卡片并定位柜台；只有一个结果时 Enter 可直接定位。查询只在前端处理，不发送到分析服务。

正式索引建议包含 `courseId / lessonStart / lessonEnd / lessonLabel / awardTitle / courseTitle / chapterId`；标题从当前业务数据读取。不要把样板演示姓名、日期或 5 星写进真实数据适配层。记录打开位置使用学生隔离的存储键，登出或切换学生后重新验证授权。

## 原卡与历史数据的保护

本演示直接使用从现有纪念册导出的三份 984×528 GIF；展示、缩略图、原图与下载共用文件。原姓名「预览同学」、五颗星、日期 `2026.10.16`、人物与卡面均未改画。完整校验值在原型 `design/original-cards.json` 和模型测试中固定。

正式实现仍复用 `award-book/App.jsx` 的 `Certificate` 与 `saveCard`，以及 `core/award-card-layout.js`、`core/award-gif.js`。不要以样板 GIF 代替真实账号的动态纪念卡，也不要另建一套文字或星星排版。只把卡片外部的翻页书容器换成邮局承载层。

按 `core/award-collection-view.js` 的 `split` 继续选每课一张主卡。历史版本独立保留其星数、姓名与首次日期，在原卡详情的「历史版本」中查看；旧证书和本机保留副本继续使用现有入口，统一放入「我的」相关区域，不在收藏首页铺开。容器改造不写学习记录、不改变授星规则、不重置首次五星日期。

## 可落地的组件与数据接入

| 建议组件 | 职责 | 复用依据 |
| --- | --- | --- |
| `KeepsakePostoffice` | 页面壳、选中主卡、当前章、搜索与详情状态 | 现有学生公共壳 `server/public/student-shell.js` |
| `PostofficeScene` | 固定比例环境图、统一卡位、装饰与交互隔离 | 本原型已完成的场景和卡位 |
| `ChapterKeepsakes` | 每章三张主卡的缩略图和选中态 | `MAP_CHAPTERS` 的课程分组 |
| `KeepsakeSearch` | 标准化检索、结果与空状态、定位 | 原型模型 + 现有目录检索语义 |
| `KeepsakeViewer` | 原卡、导出、历史版本、焦点回收 | `Certificate` / `saveCard` / 当前历史入口 |
| `ChapterMailbox` | 24 章目录、已获得计数、章节选择 | 从授权后的主卡分组生成 |

适配过程：读取原纪念册集合 → 沿用原来的主卡与历史拆分 → 将主卡按课程 ID 映射到 `course-journey/model.js` 的 `MAP_CHAPTERS` → 派生搜索索引与已获得计数 → 渲染容器。章节名称可以补充美术主题，但课程顺序和范围必须来自模型，不能单独维护另一份 72 单元清单。

搜索结果跳转需要同时设置章节与卡片 ID。准备目标背景和卡片资源、完成解码后再展示新章；准备中保留当前场景，失败展示可重试提示。连续快速选择采用请求序号，只接受最后一次选择，避免旧资源迟到导致串章。没有图片时仍保留 Lesson、名称和按钮，不能只显示数字。

## 响应式与防串位标准

用户标注修订：去掉主卡下方重复的白色课号／计数条，仅在三卡选择区和详情保留对应信息；读屏状态继续播报所选课号。搜索入口收为标题旁放大镜，输入框在需要时展开，避免切断邮筒、信封翻盖和原卡之间的构图。

信封与原卡须按组合画面验收：v3 信封纸张约落在横向7.3%–92.2%，下沿82.7%；主卡横向3%–97%，顶边57.3%，顺时针1.1度，完整盖住下部和侧角，只露出后方翻盖和绿色内衬。不能只分别检查背景与原卡。不得通过裁切卡面或重绘姓名、星星解决承载比例问题。

**卡纸轮廓与导出画布分开验收。** `core/award-gif.js` 为避免GIF单色透明边缘问题，在整个984×528画布先铺不透明浅色底；圆角卡纸之外因此仍有画布像素。将原GIF直接贴进环境、只给容器统一圆角，都会留下外部白边。当前三份样板按真实导出轮廓处理显示：四边遮去4个源像素，圆角约21.2个源像素，按图片比例换算；保留金框、人物、文字、星星和日期。主卡、缩略图、搜索结果、详情共用这一显示规则，阴影跟随真实轮廓。下载与新窗口原图仍使用字节完全相同的原GIF。

该轮廓仅适用于已核对的当前导出模板，旧证书或其他尺寸不能直接套用。验收需放大查看四角和四边，并在环境背景上对照；不得把页码条、信封侧角和GIF画布白边归为同一个问题。当前四角及左右中点像素对照、三原GIF校验见 `poc/keepsake-postoffice/design/evidence/card-edge-20261029/`。

搜索交互还需验证「键盘打开时直接轻点结果」：输入失焦发生在按下阶段时，暂缓改变抽屉位置，等本次点击完成再收起键盘；取消指针及键盘Tab离开仍要正常收键盘，不能出现第一次点中只关键盘、第二次才选中。

1. **场景与卡位共用一个坐标系。** 本样板背景为 1070×1470；按容器宽度等比缩放。卡片位于左 3%、顶 57.3%、宽 94%，保持 984∶528。禁止背景用 `cover` 裁切、卡片却按另一套视口坐标定位。
2. **文字与美术各有安全区。** 标题、章节说明所在左上区域保持低细节奶油墙；第一轮已修正窗框和花叶干扰。搜索是实际交互控件，不写死在背景图里。姓名、日期、星星全部留在原卡内部。
3. **不强制单屏塞完。** 手机主卡只展示一张，三张缩略图表示选择。短屏自然滚动；固定导航必须有等高底部留位，最后一项滚到导航上方。
4. **原卡不能裁切。** 主卡、缩略图、详情用 `contain` 或自然高度；信封、邮戳不覆盖卡面。大图查看提供独立原图与保存通道。
5. **弹层与键盘协作。** 搜索结果出现在键盘上方；关闭、选中、失焦、Escape 和切换弹层时收起键盘。取消旧的延迟回焦任务，禁止新弹层打开后焦点跳到后面卡片。定位只滚动应用内容容器，禁止无边界 `scrollIntoView` 同时移动设备外壳，造成状态栏移位和已关闭键盘残留。
6. **触摸与焦点分开。** 标准 button/link 承载点击，关闭系统蓝色触摸高亮，保留键盘可见焦点；拖动开始后不误触。正式页面继续遵守首页 J45–J47 真机回归要求。

正式网页建议布局：320–599px 保持纵向单主卡；600–1023px 让柜台在 560px 内居中，目录为抽屉；1024px 以上使用 260px 章节列表与最大 620px 柜台分栏。不要将手机画面横向拉满电脑。断点由容器可用宽度决定，景物和卡片仍等比绑定。

本次可运行演示使用保留设备壳的 iPhone 393×852 与 Pixel 10 427×952 两套逻辑尺寸。这不是 320px 原生网页、平板或全部桌面断点已经完成的声明，也不等于 Android 微信、夸克真机通过。正式接入需使用项目固化尺寸矩阵并补充真机测试；95% 覆盖仍是有待访问统计核实的目标。

## 美术与提示词

固定基准图：`poc/keepsake-postoffice/design/selected-reference.png`。生成环境只需要一次邮局柜台素材及局部修订，三张原卡、logo、字体直接复用。采用 `public/art/postoffice-scene-v3.png`；初稿保留用于追溯。

核心约束：温暖细腻的手绘小镇，奶油墙、青绿木窗、赤陶远景、森林绿 POST 邮筒、黄铜邮戳、暖木桌、奶油信封与鼠尾草绿内衬。上方左侧 0–64% 横向、0–35% 纵向留低细节文字区域；信封主体和原卡插入位置固定。画面不生成卡片、人物、姓名、星星、课号、按钮、搜索或设备框；POST 是环境文字，可留在美术内。

完整实际提示词、生成路径与两轮取舍分别保存在 `design/scene-prompt.json`、`design/scene-v2-prompt.json`，本次信封比例修订在 `design/scene-v3-prompt.json`。后续章节优先复用柜台，只改变信封邮戳和窗外小幅季节细节；不要每章重新生成整套人物或不同透视的信封。
