# 进度、评分和音频修复设计

历史设计 · 2026-07-29。审查基线：`8544a1081f4b286cec3f8cda491787221e7e504e`。

当时发现：损坏进度可使页面出错，重试也计首答分，选项打乱后高亮错位，音标星星可无限增加，音频取消后界面不收尾，静态目录与线上路由不一致。

## 保留的规则

| 范围 | 要求 |
| --- | --- |
| 存储 | 读取、保存都校验数据；每关 0–3 星；存储失败时页面仍可用 |
| 旧数据 | Lesson 49、50 保留有效评级；音标旧总分无法还原各关，迁移时归零；新数据成功保存后再删除旧键 |
| 评分 | 允许重试，但首答分只在第一次正确时增加；已完成题不重复计分 |
| 随机选项 | 使用稳定身份判分，不能拿显示位置当答案 |
| 星星 | 每个挑战只保留历史最高评级，不能重复累加 |
| 音频 | 正常结束、取消、失败、超时、不可用都只收尾一次；旧播放不能影响新播放 |
| 证书 | 显示和实际领取、保存、打印分别检查资格 |
| 页面使用 | 词卡可用键盘，弹窗恢复焦点，反馈可被读屏读取 |
| 发布 | 根目录可直接用静态服务器访问，发布文件与提交号一一对应 |

共享模块为 `core/storage.js`、`assessment.js`、`progress.js`、`audio-player.js`。证书图片使用 Blob 并释放临时地址，字体与许可证随网站保存。

音标挑战为 `vs/g1/g2/g3`：辨认题 9–10／7–8／5–6 分对应 3／2／1 星；三个五题小游戏 5／4／3 分对应 3／2／1 星，更低分为 0 星。
