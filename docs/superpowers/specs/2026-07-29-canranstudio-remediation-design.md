# canranstudio 状态完整性与工程加固设计

## 1. 背景

本设计针对 `main` 分支提交
`8544a1081f4b286cec3f8cda491787221e7e504e` 的对抗性审查结论。

调查确认：

- `localStorage` 只处理 JSON 解析错误，没有校验对象结构、字段类型和数值范围；
- Lesson 50 的听音摘果、投喂大作战、魔法锅、Do/Does 分拣仅在答对时推进并计分，导致完成者必然满分；
- Lesson 50 最终考核使用原始选项下标访问洗牌后的 DOM 下标；
- 音标课将星星保存为可无限递增的整数，没有有限成就身份和证书门槛；
- 音频被取消或播放中失败时，不保证调用清理回调；
- 仓库根目录与线上 Nginx 的隐藏映射共同决定路由，普通静态服务器无法还原线上结构；
- Lesson 49、Lesson 50 和音标课的证书条件均未完整验证其证书文案所声明的完成状态；
- Lesson 49 的证书图片和无障碍能力落后于 Lesson 50 的同类实现。

线上站点当前必须继续通过 `http://59.110.217.36` 公网访问。由于域名尚未完成
ICP 备案，本轮明确不实施 HTTPS、HTTP 到 HTTPS 跳转或 HSTS。

## 2. 目标

本轮建立“单机状态自洽”：

1. 损坏、旧版或异常的本地状态不能使页面初始化失败；
2. 分数反映首次作答结果，而不是最终是否纠正成功；
3. 星星来自有限、幂等、可解释的挑战结果；
4. 证书只能由与证书文案一致的完成状态派生；
5. 随机排序不能改变选项的业务身份；
6. 每次音频播放无论以何种原因终止，都恰好完成一次清理；
7. 仓库本身可以通过普通静态服务器还原首页与三个课程路径；
8. 所有修复均由自动化失败用例驱动，并能在 CI 中独立验证。

## 3. 非目标与已接受风险

本轮不包含：

- 用户账号、服务端进度或服务端签名证书；
- 防止用户主动通过开发者工具篡改本机数据；
- HTTPS、TLS 证书、HTTP 到 HTTPS 跳转或 HSTS；
- 视觉重设计或课程内容改版；
- 全面迁移到前端框架；
- MP3 内容的听觉正确性审校；
- 对公网 HTTP 服务作出合规通过结论。

继续使用公网 HTTP 是经确认的暂存风险。即使保留 CSP、`nosniff`、
`Referrer-Policy` 和 `Permissions-Policy`，网络中间人仍可篡改页面脚本并读取儿童姓名或
本地进度。因此审查项 RISK-HTTP-01 在本轮结束时保持为“已接受、延期处理”，不能标记为已修复。

## 4. 总体方案

采用“分阶段收敛”：

- 保留零构建静态站和现有页面表现；
- 新增少量无运行时依赖的共享核心；
- 只迁移与审查问题直接相关的逻辑；
- 应用状态与部署结构分别实施、分别验收；
- 每个任务遵循失败测试、最小修复、定向验证、全量回归、独立提交。

共享核心使用普通 `<script>` 加载，通过单一 `CanranCore` 命名空间提供浏览器接口。
同一份实现可在 Node 测试中加载，避免为测试复制业务逻辑。

### 4.1 共享核心边界

`core/storage.js`

- 解析、校验、归一化和持久化版本化进度；
- 捕获读取、解析和写入异常；
- 非法值修复后回写；
- 存储不可用时返回可工作的内存状态。

`core/assessment.js`

- 维护每题是否首次作答、是否已经解决；
- 支持“答错后继续纠正，但仅首次正确计分”；
- 为洗牌选项保存稳定的原始选项 ID；
- 不直接访问页面 DOM。

`core/progress.js`

- 将原始得分映射为 `0–3` 星；
- 只允许同一挑战的历史最高星级覆盖旧值；
- 计算总星星和证书资格；
- 不负责存储或页面渲染。

`core/audio-player.js`

- 统一预录音频、合成语音和主动取消的生命周期；
- 保证一次播放只终结一次；
- 向调用者返回明确的终结原因；
- 不包含课程专属的界面或关卡推进逻辑。

## 5. 版本化进度

### 5.1 新存储键

- `canran:l49:progress:v2`
- `canran:l50:progress:v2`
- `canran:soundmark:progress:v2`

Lesson 49 和 Lesson 50 的数据结构：

```json
{
  "version": 2,
  "ratings": {
    "l1": 0,
    "l2": 0,
    "l3": 0,
    "l4": 0,
    "l5": 0
  }
}
```

音标课的数据结构：

```json
{
  "version": 2,
  "ratings": {
    "vs": 0,
    "g1": 0,
    "g2": 0,
    "g3": 0
  }
}
```

所有 rating 必须是 `0–3` 的有限整数。未知字段被忽略，缺失字段补为 0，数组、
`null`、字符串、布尔值、非有限数字和嵌套对象均不能直接进入业务状态。

### 5.2 迁移

Lesson 49 和 Lesson 50：

1. 新键不存在时读取旧键 `l49-stars-v1` 或 `l50-stars-v1`；
2. 仅提取 `l1` 至 `l5`；
3. 将每个值转换为有限整数并限制到 `0–3`；
4. 成功写入 v2 后再删除旧键；
5. 写入失败时继续使用内存中的归一化结果，并保留旧键供下次迁移。

音标课：

1. 旧键 `phonics-magic-stars-v1` 只有总数，无法恢复星星来源；
2. 不将旧总数转换为新成就；
3. 首次成功写入 v2 空进度后删除旧键；
4. 仅显示一次“进度规则已升级，请重新挑战”的提示；
5. 存储写入失败时不删除旧键，当前会话仍从 0 开始。

任何 v2 数据损坏时都执行同样的归一化和修复回写。修复失败不得阻止页面继续初始化。

## 6. 评分与选项身份

### 6.1 统一作答语义

受影响的 Lesson 50 关卡采用允许纠错制：

- 每道题初始为 `firstTry=true`、`solved=false`；
- 首次答错后设置 `firstTry=false`，保留当前题并显示提示；
- 最终答对后设置 `solved=true` 并进入下一题；
- 只有 `firstTry` 仍为 true 时才增加分数；
- 同一题解决后不再接受重复输入。

该规则应用于：

- 听音摘果；
- 投喂大作战；
- 魔法锅分拣；
- Do/Does 分拣。

Lesson 50 的照妖镜挑战已经采用同一语义，迁移后与共享核心保持一致。

Lesson 49 最终考核的 0 星路径必须真实存在，0 分不能再自动获得 1 星。

### 6.2 洗牌选项

每个渲染选项保存：

```javascript
{
  id: originalIndex,
  text: optionText,
  correct: originalIndex === correctIndex
}
```

随机排序只改变条目顺序。评分、反馈文本和正确答案高亮均使用 `id` 或 `correct`，
禁止使用洗牌后的 DOM 位置表达业务身份。

## 7. 音标课有限挑战

音标课固定为四项挑战，每项最高 3 星：

- `vs`：元音与辅音判断；
- `g1`：听音小侦探；
- `g2`：左耳右耳；
- `g3`：拼读小达人。

`vs` 每轮完整覆盖 10 题，按首次作答得分评星：

- 9–10 分：3 星；
- 7–8 分：2 星；
- 5–6 分：1 星；
- 0–4 分：0 星。

三个小游戏每轮固定为 5 题，按首次作答得分评星：

- 5 分：3 星；
- 4 分：2 星；
- 3 分：1 星；
- 0–2 分：0 星。

重玩只能提高该挑战的历史最高星级，不能重复累加。页面显示值、首页进度和证书状态均从
四项 rating 派生，总星星范围固定为 `0–12`。

## 8. 证书语义

Lesson 49 和 Lesson 50：

- `l1` 至 `l5` 必须全部至少为 1 星；
- 证书入口的显示状态和点击处理均重新调用同一资格函数；
- 修改 DOM 使按钮可见不能绕过业务资格检查；
- 证书显示最终考核星级和五关总星星。

音标课：

- `vs`、`g1`、`g2`、`g3` 必须全部为 3 星；
- 总星星必须为 12；
- 未满足条件时按钮保持禁用，并显示还差多少星；
- 满足条件且姓名非空时才执行庆祝和打印；
- “打印我的证书”必须调用 `window.print()`。

本轮证书只保证页面自身的状态一致性，不声明其可以抵抗本机数据篡改。

## 9. 音频生命周期

共享播放器的单次播放结果只能是：

- `ended`：自然播放结束；
- `cancelled`：被新播放或显式停止打断；
- `error`：预录音频或合成语音失败；
- `timeout`：浏览器未产生结束或错误事件；
- `unsupported`：浏览器没有可用播放方式。

每次播放创建唯一记录和幂等 `finish(reason)`。`finish` 必须：

1. 拒绝第二次终结；
2. 停止当前媒体；
3. 移除事件监听；
4. 清除超时；
5. 释放活动播放引用；
6. 恰好调用一次完成回调。

预录音频的 `ended`、播放前失败、播放中 `error`、超时和主动取消均进入该函数。
合成语音的 `onend`、`onerror`、超时和取消也遵守相同合同。

Lesson 50 的播放令牌继续负责阻止旧播放回调污染新队列，但资源清理和调用者通知统一交给
播放器。所有 `.playing` 样式通过完成回调移除；依赖播放完成推进的关卡在取消、错误或超时后
也必须解除阻塞。

## 10. 确定性目录与 HTTP 部署

目标目录：

```text

/lesson49/index.html
/lesson49/audio/
/lesson50/index.html
/lesson50/audio/
/soundmark/index.html
/soundmark/audio/
/core/
/deploy/nginx/
```

- 根目录 `index.html` 是欢迎页；
- 原根目录 Lesson 49 页面与 `audio/` 移至 `lesson49/`；
- `/home/` 保留兼容入口，只跳转到 `/`；
- 页面导航继续使用 `/`、`/lesson49/`、`/lesson50/` 和 `/soundmark/`；
- 普通静态服务器不需要重写规则即可访问四个主路径。

仓库新增当前 HTTP 部署使用的 Nginx 配置：

- 监听 `80`；
- `server_name` 包含 `59.110.217.36`；
- 静态根目录与仓库发布目录形成唯一映射；
- 保留 CSP、`X-Content-Type-Options`、`X-Frame-Options`、
  `Referrer-Policy` 和 `Permissions-Policy`；
- 不包含 TLS、HTTPS 跳转或 HSTS；
- 配置文件与部署说明明确记录 HTTP 暂存风险。

## 11. 工程加固

### 11.1 Lesson 49 证书图片

- 使用 `canvas.toBlob()` 和 `URL.createObjectURL()`；
- 下载文件名移除 `\ / : * ? " < > |`；
- 关闭保存遮罩后撤销 Blob URL；
- `toBlob()` 不可用时才使用受控降级路径。

### 11.2 无障碍

- Lesson 49 翻卡支持 Tab、Enter 和 Space；
- 翻卡状态通过 `aria-expanded` 或等价状态暴露；
- 三套证书弹窗使用 `role="dialog"` 和 `aria-modal="true"`；
- 打开时移动焦点，Tab 焦点留在弹窗内，Esc 关闭；
- 关闭后将焦点返回触发按钮；
- 答题反馈和音频错误使用合适的 `aria-live` 区域。

### 11.3 字体

- 将 Baloo 2、ZCOOL KuaiLe 和 Fredoka 的所需 WOFF2 字重及许可证纳入仓库；
- 页面通过本地 `@font-face` 加载；
- 删除 Google Fonts 的运行时请求；
- HTTP CSP 相应移除 Google Fonts 域名。

## 12. 测试与 CI

运行时继续保持零依赖。开发环境增加：

- Node 内置 `node:test`：测试共享核心；
- Playwright：测试真实页面行为；
- 仓库内 Node 静态服务器：提供不依赖 Nginx 的测试站点。

最低自动化覆盖：

1. 负数、字符串、极大值、数组、`null`、非法 JSON 和写入异常均不会中断初始化；
2. 修复后的进度被回写，且总星星始终处于合法范围；
3. Lesson 50 四个纠错关卡首次答错后再答对不会获得该题分数；
4. 每个课程的 0、1、2、3 星分支均可达；
5. 任意洗牌顺序下，高亮的都是语义正确选项；
6. 音标课同一挑战不能重复累加，最大总数为 12；
7. 三套证书在条件不足时均不能签发；
8. 音标打印按钮调用打印流程；
9. 快速播放两个音频后，第一个组件解除 `.playing`；
10. 音频自然结束、失败、超时和取消均只回调一次；
11. 普通静态服务器下四个主路径返回 200 且导航闭环；
12. Nginx 配置语法和 HTTP 安全响应头通过检查；
13. Lesson 49 证书保存使用 Blob 且文件名经过清理；
14. 翻卡和证书弹窗完成键盘与焦点回归测试。

CI 顺序：

1. 共享核心单元测试；
2. 三个课程的 Playwright 回归；
3. Nginx 配置与静态路由检查。

线上 `http://59.110.217.36` 作为手动发布门槛，验证首页、三个课程、响应头和仓库文件
哈希。线上 HTTP 验收通过不等于 RISK-HTTP-01 已修复。

## 13. 分期交付

### 阶段 1：测试底座

建立 Node 单元测试、Playwright、静态服务器和 CI，不改变页面行为。

### 阶段 2：P0 状态完整性

交付存储归一化、Lesson 50 首次作答评分、稳定选项身份、三套有限进度、
三套证书门槛和音标打印。

### 阶段 3：P1 生命周期与部署

交付共享音频控制器、确定性目录、仓库内 HTTP Nginx 配置和线上 HTTP 验收脚本。

### 阶段 4：P2 工程加固

交付 Lesson 49 Blob 证书、安全文件名、键盘与弹窗无障碍、自托管字体。

### 阶段 5：收尾

删除已被共享核心替代的重复实现，更新 README、迁移说明、测试命令和已接受风险。

每个阶段都必须形成独立可测试的提交。任何业务断言失败均直接阻止阶段完成，不通过重试掩盖。
