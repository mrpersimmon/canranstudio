# 音频播放修复计划

历史计划 · 2026-07-29。本文保留当时目标与完成标准，不代表今天已经测试或上线。

让播放结束、取消、失败和超时都能正确收尾，避免按钮或播放队列卡住。

## 主要工作

1. 用 `core/audio-player.js` 管理同一时刻的一次播放。
2. 优先播放录音，失败时在同一次请求内尝试浏览器朗读。
3. 新播放先取消旧播放；旧请求的迟到事件不能影响新请求。
4. 每次请求只报告一次结果：`ended`、`cancelled`、`error`、`timeout` 或 `unsupported`。
5. Lesson 50 的连续播放队列保留在课程页，其余课程直接使用共享播放器。
6. 检查中断、失败与超时后，发声状态、按钮和等待中的操作都能恢复。

## 状态与后续变化

播放成功开始不等于播放结束。验收重点是每次请求恰好结束一次，取消后队列不锁死，页面不残留播放中样式。
