# V1 Map 08 移动发布 QA

## 结论

Map 08 的自动化发布面已覆盖手机、平板竖屏、平板横屏和桌面；地图仍保持暖色儿童故事书图鉴，而不是退化成通用卡片列表。真实微信、iPhone Safari 和 Android Chromium 仍为人工证据，见 [`docs/mobile-release-smoke-checklist.md`](../../mobile-release-smoke-checklist.md)。

## 视觉方向

- 主题对象：孩子课后回到“暖灯集市”，先理解推荐地点，再沿纵向路线看到 Lesson 49–60。
- 主要任务：在手机首个稳定视口内看见当前城区、推荐理由和主要进入动作。
- 视觉签名：固定地点框中的水彩肉铺按阶段累计成长；其他界面保持安静的暖纸、棕色描边、灯笼红和地图金。
- 字体：地图标题继续使用 `ZCOOL KuaiLe`，英文与工具文字使用 `Baloo 2`，中文保留系统字体降级。
- 响应式：手机使用原生纵向页面滚动与两列路线；平板只改变列数，不改变地点顺序或语义。

## 已批准锚点与六状态复核

锚点来自仓库中的正式资产：

- 初始锚点：`assets/adventure-map/lesson49/base.png`
- 最终锚点：`assets/adventure-map/lesson49/mobile-preview.png`
- 累计状态：基础肉铺，依次增加遮阳棚、肉品陈列、无文字肉铺徽记、配送车与货箱、灯串彩旗及金色徽章。

`tests/e2e/mobile-release.spec.js` 会在 390×844 下生成六张 `.published-marker` 证据图并附加到 Playwright 测试结果。复核结果：

1. 0/5：温暖、完整、等待探索的基础肉铺可辨认。
2. 1/5：红白遮阳棚是第一处清楚变化，没有遮住入口。
3. 2/5：肉品陈列位于左下，和肉铺主体保持清楚层级。
4. 3/5：无文字肉铺徽记位于右上，不与标题或状态文字混淆。
5. 4/5：配送车与货箱位于右下，仍保留肉铺主体轮廓。
6. 5/5：灯串、彩旗和金色徽章形成完成反馈；食物篮子仍作为地点框外的独立纪念物显示。

复核过程中曾尝试取消五层的 CSS 合成位移，以验证“固定画布”解释。真实截图显示这会让居中的配送车盖住肉铺，偏离批准的最终预览，因此该尝试已撤销。最终实现锁定的是地点框、基础肉铺和点击区域不随 0–5 阶段移动；五张部件图继续使用稳定且逐层唯一的合成位置。

## 人工证据边界

以下项目不能由 Chromium 桌面模拟替代，当前不得声称已通过：

- 微信内置浏览器真实音频、返回和安全区；
- iPhone Safari 刘海 / 圆角、方向切换和用户手势音频；
- Android Chromium 的字体、音频、触控和系统返回；
- 真实课堂投屏设备的全屏策略。

执行时使用空白演示设备并填写移动烟雾清单；不要导入或记录真实儿童数据。
