# 老师体系设计与验收

更新：2026-10-09。开发分支：`codex/debug-login-version`。

目标：管理员统一管理老师；老师在自己负责的班级内具有班级管理员权限。一个班级可有多名老师，一名老师可负责多个班级，同班老师权限相同。老师账号只能启用或禁用，不提供删除功能。

## 1. 工号和密码

工号由“已核对姓名拼音的首字母＋固定 1＋七位全局递增序号”组成，共 9 位。所有老师共用一个流水号，和学生流水号独立；没有按姓氏重新从 1 开始的计数。

| 姓名 | 核对的拼音 | 工号 |
| --- | --- | --- |
| 段晓东 | duanxiaodong | d10000001 |
| 韩秋婉 | hanqiuwan | h10000002 |
| 韩肖肖 | hanxiaoxiao | h10000003 |

学生仍为“拼音首字母＋固定 0＋七位学生流水号”，如 `d00000001`。字母后的数字首位固定区分老师 1 和学生 0；任一序号达到 9,999,999 后拒绝继续发号，不进入对方编号区间。工号创建后不可编辑，改名、改拼音、重置、禁用和重新启用都不会改变，不回收复用。多音字由管理员核对；使用本地拼音库，不向外部服务发送姓名。

初始密码和每次重置密码都是“已核对的姓名完整小写拼音＋3 位随机数字”，数字允许前导零，如 `007`；不使用固定默认密码。新密码不得和该账号旧密码重复；相同拼音的待领取老师凭据避免重复。创建后查看账号；管理员之后也可单独查看仍有效的初始密码。

初始密码 7 天内只能登录一次，兑换后 15 分钟内必须设置自己的密码。未完成改密只能进入改密页，不能查询班级、学生、课程资源或做管理操作。正式密码为 8–64 位，包含字母和数字，不得等于姓名拼音、工号或原密码。已设置的正式密码仅保存哈希，管理员无法查看。重置会撤销全部旧登录，再次强制改密。忘记密码、已使用但未改密、初始密码过期均由管理员重置；重启服务器不延长有效期。

编辑姓名或拼音不会偷偷改变当前密码；新的拼音从下一次重置起生效。工号和初始密码沿用本地 Maple Mono NL 字体，便于区分 `I/l/L/1` 和 `O/0`。

## 2. 权限范围

| 操作 | 管理员 | 老师 |
| --- | --- | --- |
| 创建、编辑、启用、禁用老师，重置老师密码 | 全部 | 不允许 |
| 给老师分配班级、给班级分配老师 | 全部 | 不允许 |
| 创建班级 | 允许 | 不允许 |
| 改班名、开放课程、班级预览 | 全部 | 负责的班级 |
| 添加、编辑、启用、停用学生 | 全部 | 负责的班级 |
| 查找学生、查看学习情况／星星／最近学习时间 | 全部 | 负责的班级 |
| 查看／打印学生账号，单人／批量重置 | 全部 | 负责的班级 |
| 转班 | 任意班级 | 来源和目标班级都必须负责 |
| 修改自己的密码 | 沿用现有管理员维护方式 | 当前密码验证后修改 |
| 删除老师 | 不提供 | 不提供 |

允许老师暂时没有班级，显示“尚未分配班级，请联系管理员”，返回的学生、班级和学习结果都为空。老师的学习页显示“我负责的班级”，查询范围仅为其负责班级的集合。全站课程名称目录可以展示，课程内容和学生记录按权限开放。

管理员禁用老师时立即撤销全部登录；重新启用保留原工号、密码和班级关系，但旧登录不能恢复。删除老师与班级的关联后，下一个请求即失去该班的权限，不影响其他老师。老师页和权限以服务端为准；已经显示或下载的内容不能从用户设备上远程收回。

学生转班后，旧班老师失去对该学生的权限，新班老师可以查看该学生的学习记录，包括此前学习过的课程。转班不改学号、密码和成果。

## 3. 页面操作

管理员和老师都从 `/admin/` 登录，分别填写管理员账号或老师工号。管理首页保留现有班级管理与学习进度入口；管理员额外拥有“老师管理”，老师有“修改密码”。

“老师管理”列表包含姓名、工号、负责班级、状态和操作；支持按姓名／工号查找和状态筛选。新增时填写姓名、核对建议拼音、勾选多个班级。提交成功才生成工号并显示账号弹窗。编辑保留固定工号；禁用和重置分别说明影响并确认；没有删除按钮。

分配班级可以从两个方向完成：编辑老师时勾选班级；班级设置中点击“分配老师”，勾选多名老师。同班负责老师名单显示禁用状态。负责班级为空是合法状态。

班级名称和课程分别保存、分别检测并发修改：另一位老师只改名字时不阻止课程保存；同一项已被修改时返回明确冲突提示，不覆盖，当前草稿保留，刷新核对后再保存。老师资料和班级分配也检查版本或原关联列表。成功保存显示弹窗；失败不显示成功，保留当前输入；提交期间阻止重复操作。

学习列表延续精简方案：姓名／学号、未开始／学习中／已完成、星星、最近学习时间；筛选和星星排序留在表头。最近学习时间是服务端收到有效学习提交的时间，不是登录时间或打开课程的时间。没有提交记录显示“暂无学习记录”；已有旧成果但时间未知显示“未记录”，不据此断言从没学过。

## 4. 实现边界

新增 `teachers`、`teacher_numbers`、`class_teachers`、`management_audit` 表。已有管理员、学生 UUID、学号、课程进度和成果不重建。初始密码使用原 `card-key` 加密，正式密码使用独立随机盐的 scrypt 哈希；备份仍需数据库和配套密钥。

老师拥有独立的 `teacher`／`teacher-setup` 会话角色，复用管理入口 Cookie；完整会话有效 12 小时，初次改密会话最多 15 分钟。每次请求重新检查启用状态和当前班级关系。登录失败限流按规范化工号处理，大小写和首尾空格不能绕过限流。

后端集中检查管理身份和班级范围。状态页、学习统计／分页／学生详情、账户查看与打印、单人和批量重置、转班、班级设置、预览入口、课程索引、清单及资源都受限制。批量请求中混入一个越权学生就整批拒绝；异步生成密码后，在事务内重新检查老师登录和每个学生的当前班级，避免期间撤权或转班造成部分越权重置。老师只能预览负责班级已开放课程，不授予全站管理员资源权限。

管理审计记录操作者、操作、对象、必要的变更内容和时间，不记录密码、会话令牌或密码哈希。不新增学生督促／跟进业务，不改变学习成果判定。

### 验证中发现并修复

老师首次改密原本增加了资料版本号，导致管理员原先打开的列表在禁用老师时误报资料冲突。此前存储测试主动读取了新版本，漏掉了“管理员列表保持打开、老师在另一窗口改密”的真实状态。现在自行改密不改变资料版本，姓名、班级关系、启禁用和管理员重置仍有冲突保护；补了版本不变断言，并在两个独立浏览器身份间复验改密后立即禁用。

班级保存使用各表单自己的原值检查冲突。保存课程时即使返回最新班名，也不替换未保存名称草稿的原值，避免随后覆盖其他人的改名。老师与学生同时在一个浏览器登录时，资源权限取各自合法范围；学生 Cookie 不扩大老师的管理查询范围，接口回归已覆盖。
