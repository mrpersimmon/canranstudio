# 学习功能不规定儿童端固定五幕流程

课程设计继续检查情境建立、理解、主动调用、变化迁移和成长反馈等必要学习功能，但不再要求所有教学单元按“发现问题 → 听懂线索 → 教会小猫 → 换个情境使用 → 建造地标”显示五幕，也不要求五个页面、五类题或一项功能对应一个微任务。每个教学单元可以根据教材内容编排自己的场景、微任务数量、功能组合和叙事节奏；本决策取代 ADR-0034 的固定五幕表述，避免孩子感知到重复的教学模板。

## Considered Options

- 学习功能作为内部检查表、儿童体验按内容创作：保留课程完整性，同时允许自然故事节奏，因此采用。
- 所有单元展示固定五幕：结构容易解释，却会把 72 个冒险逐渐做成换皮流程。
- 不保留任何共同学习功能：创作自由最大，但容易遗漏理解、主动调用或迁移证据。

## Consequences

- 课程蓝图必须说明必要学习功能在哪里发生，但不能用五个标题代替真实的儿童动作和学习证据。
- 儿童端的场景数、微任务数与过渡节奏由内容决定，不从五幕数量自动推导。
- 同一微任务可以自然结合多项学习功能；同一功能也可以跨多个微任务逐步完成。
- 现有以固定 beat 标识组织的运行时与 Lesson 49 蓝图只是待迁移实现，不能反向约束新课程设计；具体数据模型在设计树完成后另行决定。
