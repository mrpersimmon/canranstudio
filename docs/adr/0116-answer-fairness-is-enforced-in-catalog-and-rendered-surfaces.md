# Answer fairness is enforced in catalog and rendered surfaces

Every answer-bearing surface declares its target evidence channel and any intentional pre-submit support in the catalog, including mainline challenges, stage replay, same-day recap, optional practice and later teaching-unit story stages. Catalog validation compares titles, prompts, visible and accessible candidate names, translations, hints, answer relationships and round ordering with that declaration; mutation tests must prove that an injected direct answer makes validation fail, browser acceptance checks the final composed child-facing surface, and human walkthroughs remain the last check for visual or narrative leakage. This layered contract replaces keyword blacklists or manual-only review because any one layer can miss answer leakage.

An action whose prompt intentionally names the correct person or object is a guided story action: it may remain clear, but it cannot create a target result, change the adventure-heart pool or count as learning evidence. If the action is intended to measure retrieval or comprehension, its pre-submit surface must instead remain answer-neutral. Lesson 1–2 therefore covers all 29 formal challenges plus all three case-recap questions, and each later teaching unit requires equivalent catalog, mutation, rendered-surface and walkthrough evidence before the answer-leakage class can be described as resolved.

For English textbook-source candidates, answer fairness also includes an English-only candidate surface across the full response lifecycle: initial, wrong, correct, audio-playing, completed and accessible candidate names. Chinese may remain in the prompt when it is the declared semantic input, and actionable Chinese recovery copy may remain outside the candidate layer; source translations stay in the catalog but do not re-enter English candidate cards after submission. Entity or role candidates that are not English textbook sources keep the neutral names required by their own task, so the rule is source-semantic rather than a page-wide English-only switch. Catalog validation, renderer-state tests and browser walkthroughs must enforce this distinction; CSS hiding or a one-question exception is insufficient.

The catalog declaration for this boundary is `candidateLanguageBoundary: source-text-only`. A shared candidate renderer always uses the textbook source text for such controls and never appends the source translation after a correct response. Correct confirmation belongs outside the candidate group as the English answer and its required audio state; a generic translated success sentence does not duplicate that confirmation. Validation rejects a translated source-option set that omits or changes this boundary, so future courses cannot reintroduce the leak by copying only the visual component.
