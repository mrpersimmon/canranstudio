# Teaching units install atomic course packages before instruction

Each teaching unit publishes a versioned manifest for every reachable primary code, style, font, image, icon and audio resource; a minimal entry shell reports real byte progress while a Service Worker stores and verifies that unit package in Cache Storage, and instruction cannot start until the complete revision is atomically activated. Same-version reopenings reuse the complete package, course interaction permits no resource network misses, and the browser keeps only the current and next stage decoded rather than holding the whole visual package in memory. New revisions download separately and retain the old complete package until activation, while interrupted verified progress is resumable and leaving the preparation surface stops unfinished background transfer; this accepts a longer but truthful first installation and cache-management complexity, does not silently install every later unit, does not promise persistence after stored data is cleared or a revision changes, and does not by itself constitute an accepted offline-learning feature.
