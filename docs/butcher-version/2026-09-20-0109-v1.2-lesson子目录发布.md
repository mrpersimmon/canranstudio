# lesson 子目录发布

用户已确认正式入口为 **https://www.canranstudio.cn/lesson/**。目标分支为 `codex/butcher-version`。本文记录部署方法；实际上线提交以该地址的 `release-manifest.json` 和本次发布验收结果为准。

## 访问与隔离

- `/lesson/` 直接显示“我的课程”导航，组合单元位于 `/lesson/unit49-50/`。
- 原单课、图片、录音、字体和返回导航都留在 `/lesson/` 内。
- 官网根目录继续使用原课程，发布时不切换它的内容目录。
- 子目录使用独立的浏览器进度键。重开这里的冒险不会删除另一套课程的记录。
- 如果浏览器已经受官网根目录的离线缓存控制，会为 `/lesson/` 注册更具体的网络直通服务工作线程，随后刷新进入课程。它不缓存新课程，也不注销或修改官网原有缓存。

## 检查与发布

1. 运行 `npm run check:plan` 和 `npm run check:commit`，记录实际范围；正式发布还需完整页面、发布规则与静态包检查。
2. 提交当前分支，推送后比较本地与远端提交号。
3. 从该提交构建：`npm run build:static -- --base-path /lesson/`。发布清单记录转换后文件的校验值，不能上传本地开发目录。
4. 把发布包上传到服务器独立目录 `/var/www/canranstudio-lesson/releases/`，核对清单与全部文件后再切换 `current`。
5. 在现有 HTTPS 配置中加入 `deploy/nginx/canranstudio-lesson-location.conf` 的引用，先备份，再检查配置并重新加载。
6. 运行 `node scripts/verify-subpath.js https://www.canranstudio.cn/lesson/`，逐文件核对线上内容、导航、旧入口跳转、非公开路径和音频分段响应。
7. 在正式页面检查导航、点读、答题、刷新继续、手机布局和证书；另核对官网根目录内容仍为原版本。

第一次发布没有旧的 `/lesson/` 版本：回退时恢复发布前的 HTTPS 配置并重新加载。后续更新可以原子切回旧 `current`。旧官网发布目录、原配置备份均保留。

## 防止再次出现的问题

- `lesson-deployment.spec.js` 覆盖子目录入口、当前 11 个课程入口、返回导航、进度隔离、完整单元领奖、旧缓存下的原生录音和手机布局。
- 检查缓存的输入加入 `unit49-50/`，避免只改组合单元时错误复用旧检查。
- 教材 PDF 的临时提取文件放在忽略的 `tmp/` 中，不进入 Git 或网站。
- 密码和私钥只用于本次服务器连接，不写入代码、发布包或文档。

发布准备中，5 项子目录真实页面检查已通过。另发现旧检查样本漏了 `unit49-50` 目录、课程预期漏了已存在的学习记录字段，以及进度条注释中的普通英文单词触发统计工具关键字扫描。已补齐样本和边界覆盖，并调整注释；没有放宽安全扫描或未提交代码不能打包的限制。最终检查与上线状态以本次执行结果为准。

扩展页面检查还发现部分旧测试仍查找已移除的地图、表情图标和独立播放按钮。对应检查改为现行导航、SVG 图标和点击词卡，并保留星星、纪念物、刷新恢复与同源录音的验证。边界检查纳入组合单元及其学习记录。证书下载等待统一为 15 秒，仍必须实际生成并下载 PNG；这只是检查等待预算，不代表优化了导出速度。此前专项检查未包含这些旧测试，因此正式发布继续要求完整浏览器检查。

## 子目录录音地址补充修复

发布包复核发现：在 `/lesson/` 内实际点击词卡，录音仍请求 `/lesson49/audio/…`，答题音效也请求根目录资源。两个课程的真实点击检查都重现了地址错误，尚未切换正式入口。

原因是三处调用通过字符串拼接生成根目录地址，静态路径转换没有覆盖。原来的录音检查直接播放预先写好的正确地址，完整答题检查又替换了录音边界，因此未检查到真实按钮生成的地址。

单课录音、组合单元录音和反馈音效统一使用目录模块的公开资源地址方法。该方法校验相对路径，并随发布目录一起转换。防御检查从真实词卡、听音按钮和检查答案按钮触发，验证实际请求地址和原生播放结束；旧官网缓存场景也改为点击词卡。另检查了同类根目录拼接，保留路径校验、字符串分隔符和音标中无关的斜杠。

修复后，7 项子目录页面检查全部通过，包括单课与组合单元的真实词卡录音、听题、答对音效、旧缓存场景和整轮领奖。
