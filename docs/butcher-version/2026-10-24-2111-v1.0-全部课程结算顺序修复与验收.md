# 全部课程结算顺序修复与验收

2026-10-24。用户在 Lesson3–4 发现：完成练习后先显示答对／答错统计，随后弹出纪念卡与飞星，关卡后统计又播放动画。本轮按用户确认的方案修复全部 Lesson1–144（72 个配对单元）的共用结算，并提供独立本地体验。源码尚未提交、推送或部署，线上仍使用此前正式版本。

## 根因与修复

原 `unit1-2/completion.js` 只等待奖励关闭后才启动统计动画，却已把整张统计页及操作按钮渲染为可见。账号奖励另等服务端确认，两个展示阶段因此交错。真实账号延迟确认的红测稳定复现：统计应不可见，实际提前可见。

现在每轮完成都有仅存于内存的展示状态，统一由 `core/award-reveal.js` 与共用结算页交接：

- 本轮全对：先显示纪念卡；确认尚未返回时展示当前真实已获星数和确认提示，不预发新星或日期。确认后飞入本轮新星，落星完成后才允许点击、Enter、Space 或 Esc 关闭；关闭后才呈现统计内容和一次动画。
- 本轮有错：不显示纪念卡或飞星，直接呈现一次统计。订正仍按原提交次数计数，不能把订正后的全部正确改成“本轮零错”。
- 已获星的全对复练：显示已有卡片和星光，不再飞入新星、不重复加星、不改变首次领取时间。入场结束后可关闭，再播放本轮统计。
- 过早的点击或按键被忽略，不排队到落星后执行；关闭输入不会穿透到结算按钮。程序发起的导航、切换身份或隐藏页面仍可立即中止奖励展示。
- 离线、同步失败或视觉资源准备失败时，原作答保留并允许继续结算。本机保存失败也释放前台等待，保留原有“暂未保存”告警，不宣称未落盘的数据已经保存。已经结束的流程收到迟到确认只更新账本，不再次弹卡或播放统计。一次确认包含旧区补传及当前区时，旧区静态补星，仅当前区飞入一颗新星。

72 个单元均调用同一奖励及结算实现。逐课构建清单已核对，全部包含当前的奖励脚本、样式和结算脚本，并校验资源 SHA-256；这是共享接入和资源完整性验证，不冒称逐课所有题目均重新作答。

## 历史数据保护

没有更改获星判定、账本结构、学习存储键、服务器同步协议或旧证渲染器，也没有修改真实用户数据库或原本地预览数据。新增状态只控制本轮界面的出现顺序，不写入学习记录。

Lesson37–38 的真实旧版15星升级回归通过：旧姓名、原领取ISO、历史证书、跨设备读取与新版首星独立保留。Lesson49–50 的真实旧证回归通过：原内容、原领取时间、PNG逐像素、打印样式和跨时区显示保持；新版获星后旧归档仍一致。既有账号奖励回归还覆盖五星首次日期、复练不改日期、纪念册一致及身份切换。

现有测试的正常关卡操作同步改为等待真实可关闭状态；原点击／按键、星数、日期、隐藏和跨设备断言保留。76个相关文件的80处正常关卡操作进行了这一兼容调整，仅其中明确列出的专项做了浏览器复验，不把语法检查写成76文件全部运行通过。

保留的中间失败包括原统计提前可见红测、WebKit 页面拦截未命中 Worker 请求、刷新后在课程加载完成前读取初始星数，以及旧测试过早关闭卡片。分别改用测试服务器真实 HTTP 暂挂／恢复、真实页面就绪边界和落星完成边界；不延长原断言、不注入成绩或奖励。HTTP故障装置仅在测试服务器启用。

手机统计专项还暴露了旧测试先读取统计、后等待加载层消失的前置顺序问题。改为先检查实际课程呈现边界，再执行原统计／几何／日期断言后，短屏、延迟呈现和旧包五星升级3项通过。最后的重复同步用例两次独立运行均完成全部业务断言（87,595ms／89,483ms），但在关闭两个浏览器上下文并保存trace时达到原90秒期限；并行关闭后仍未通过，故明确保留这一项失败，不记为测试全绿，也没有继续放宽时限或关闭trace。

新增保存故障专项只作用于测试账号待同步队列的真实写入，确认`failed`能释放奖励等待、原练习book保留和恢复后的真实补传；不把这一有限注入推广为整个浏览器存储完全不可写的全场景验证。

本机完整单元检查为140项中134项通过、6项未通过，涉及 Windows 的 POSIX权限模式、符号链接权限及SQLite临时目录清理；原失败日志保留。本轮未更改这些实现，也未将该命令记作全部通过。未运行完整全站课程／账号套件，未进行实体手机、实体打印或生产发布验收。
