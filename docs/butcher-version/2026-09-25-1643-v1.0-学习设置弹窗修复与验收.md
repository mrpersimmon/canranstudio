# 学习设置弹窗修复与验收

分支：`codex/login-version`。本次只修复课程共用设置弹窗；未提交、推送或部署。访问规则继续以[现行设计](publish/2026-09-25-1151-v1.1-班级课程访问设计与验收.md)为准。

## 问题与原因

用户在 Lesson 1–2 打开学习设置时，弹窗挤在左上角，四个按钮的文字几乎看不见。这是新增弹窗没有使用完整的共用样式造成的：

- 全局清零样式把浏览器默认的弹窗自动边距清成了零；新弹窗没有像既有弹窗一样显式居中。
- 按钮只用了 `.btn` 的白色文字，没有搭配背景色，最终变成白字叠在近白色背景上。

真实登录后的浏览器检查在修复前失败：1180×720 窗口中弹窗坐标为 `(0, 0)`，按钮文字对比度约 1.02∶1。单独恢复自动边距后位置正确，文字仍看不清；单独改深色文字后对比度约 11.34∶1，位置仍错误。弹窗直接位于页面主体，且新建浏览器环境也复现，排除了容器嵌套和旧缓存假设。

此前的页面用例验证了登录、切换与重开功能，但只按按钮名称点击，没有检查打开后的实际位置和可读性，因此功能通过没有发现这次视觉问题。

## 本次修复

复用已有 `unit-dialog` 与 `workspace-back` 样式，并添加仅作用于学习设置的尺寸和分组规则。标题旁为关闭按钮，账号操作并排，重开本课在下方单列并保留再次确认。窄屏标题按词组换行，过高内容可内部滚动。错误提示使用独立状态文字，不再覆盖弹窗标题。关闭与 Escape 把焦点交还原入口。

新增回归检查通过真实登录和页面点击打开弹窗，检查居中、对比度、按钮大小、横向溢出、关闭与取消确认保留当前选择。测试沿用临时数据库，不使用真实学生的重开、退出或改密操作。十六个课程共用同一段实现，无需逐课复制。

## 验证与证据

最终页面行为运行：

```sh
npm run test:login -- tests/login/settings.spec.js tests/login/access.spec.js -g '学习设置|窄屏与横屏|完整无配音课程成果与证书同步'
```

结果：**4 项页面行为用例通过，用时 27.9 秒**；其中十六单元检查逐一覆盖 32 个窗口场景。

范围包括：原 Lesson 1–2 桌面场景；十六个单元各自 1180×720 和 390×844 窗口；320×568 窄屏与 740×360 横屏的重开确认；取消不丢草稿、切换学生、退出登录；已有无配音整课完成与证书同步后，明确重开仍能清空本课且旧设备不能恢复旧成绩。
