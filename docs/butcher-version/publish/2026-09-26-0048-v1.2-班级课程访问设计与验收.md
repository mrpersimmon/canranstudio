## 2. 学生怎样使用

1. 第一次打开网站时，填写学号和初始密码。初始密码由系统随机生成，由老师交给本人或家长；7 天内仅可成功登录一次。验证成功后只能进入改密页，15 分钟内设置新密码后才能进入课程，且不能超过初始密码的原有效期。原浏览器刷新可继续改密；丢失待改密会话、切换学生或超时后，请老师重新重置发放。
2. 核验成功后，首页显示自己的名字、班级和该班开放的课程。没有开课时显示“老师还没开放课程”，不给出无效卡片。
3. 点击课程，先核对当前资格，再准备完整画面。缓存齐全时只核验资格和必要元数据，不重新下载整课。
4. 进入后，词卡、作答、重试、灯泡、进度和证书继续沿用统一标准，不把登录步骤插进每道题。
5. 完成一个活动后保存个人成果。换设备登录同一学号，可看到已同步的成果；正在选但未提交的答案不跨设备带过去。
6. 顶部可查看当前身份并“切换学生”或“退出登录”。切换前保存待同步记录，新学生看不到上一位的星星、草稿与证书。

学习设置使用课程共用的居中弹窗和浅底深字按钮，不能依赖浏览器默认居中，也不能单独使用白字按钮而遗漏背景色。关闭放在标题旁，切换学生和退出登录并排；重开本课放在分隔线下方，明确只清空本课成果，仍需再次确认。手机窄屏允许标题合理换行，按钮至少 44 像素；弹窗过高时在内部滚动。关闭或按 Escape 回到原活动和原焦点，不清空未提交答案。

旧链接的目标限定为站内合法课程：未登录先登录，核验通过再回到目标活动；无资格显示“这节课还没向你的班级开放”和“返回课程”。下架地址直接显示下架页。

学号是公开的账号标识，不是秘密；密码用于验证身份，不承诺阻止主动转借。丢失纸质账号单不丢失账号：老师按姓名或学号查找。忘记密码由老师核对学生后重置；不能仅输入姓名就自助重置。

## 3. 管理员怎样使用

管理页与学生页面分开，保留网站标志和按钮风格，主要提供三个区域：

- **班级**：创建、改名；进入班级后勾选开放单元并保存；可以暂时不开放任何课程。
- **学生**：输入姓名或课堂称呼、指定班级；支持逐个添加和多行粘贴；查看、改名、转班、停用与恢复。允许同名学生，但用独立编号区分。
- **学生账号**：可按学生或班级打印姓名、班级、学号和网站地址；仅在初始密码未使用且未过期时展示密码和截止时间；已使用或过期时提示重置，不自动重发。已设置的密码不展示、不导出，老师也不能查看。后台支持全班级按姓名或学号查找，重名时以学号、班级辨认。
- **密码重置**：选定学生，核对姓名拼音，确认重置。系统生成全新的随机初始密码，旧密码、旧初始密码和旧登录会话失效，下次登录必须改密。班级、学号和已完成成果保持不变；不是删除后重建账号。

普通转班不换学生身份、不清空成果。停用使用状态代替删除记录；首版不提供批量删除学生数据的快捷操作。管理员可以预览各班实际看到的课程，但预览不写入学生成绩。

管理员账号单独登录，不与学生账号混用。首次设置和账号恢复由站点维护者在服务器侧完成，不新增短信、邮箱或微信授权依赖。系统只需要课堂称呼和班级，不要求学生身份证、手机号或地址。

### 学号和姓名拼音规则

- 使用**已核对姓名拼音的第一个字母＋八位递增数字**；数字在全站统一计数，不按姓氏或班级重新计数。空库首位段晓东为 `d00000001`，随后李明为 `l00000002`，再录入段晓东为 `d00000003`。这对应本轮推荐方案；用户如果补充不同前缀要求，另行调整，不能暗中改已发出的号码。
- 添加成功时由数据库事务分配；同名允许、号码唯一。改名、纠正拼音、转班、停用、恢复或改密码都不重新分配。序号与数据库一同备份恢复，不由页面人数推算，不复用号码。
- 拼音在服务器本地转换，不向外部服务发送姓名。先用姓氏读法生成建议，老师确认多音字或生僻字；没有可靠结果时必须手填后才能添加。小写、不带声调和空格，`ü` 用 `v`。依据：[pinyin-pro 姓氏与无声调参数](https://pinyin-pro.cn/use/pinyin.html)。
- 拼音用于核对姓名及学号首字母，不作为密码。初始密码来自 12 字节安全随机数（96 位随机性），以 16 位大小写字母、数字或 `-`、`_` 显示；与姓名和学号无关。新密码为 8–64 位，含字母和数字，不得等于姓名拼音、学号或当前密码；两次输入必须一致。常用设备改密后保持登录，无需每次重新输入。
- 首次验证在同一数据库事务中消费初始密码、清除可打印密文并签发唯一“待改密”会话；并发重复领取只有一个成功。会话最多 15 分钟，同时受初始密码截止时间约束，不能读取课程清单、课件、受保护资源或提交成果。改密成功更换会话，撤销该学生其他旧会话；普通学习身份仍记住 30 天。
- 后台重置也采用“待改密”流程；学生首页可以主动修改密码，主动改密需要当前密码。普通登录错误不区分账号不存在、密码错误或停用，避免提供账号探测信息。
- 仅知道姓名、拼音和学号不能激活账号。随机初始密码在创建／重置时获得固定 7 天有效期；查看、打印、重启和备份恢复都不能延长有效期，也不能使已使用密码重新生效。纸质账号单仍只交给本人或家长。

## 4. 缓存与一次学习的边界

下列默认值已随整体方案确认。2 小时和 30 分钟均触发静默重新核验，不是限制学习时长或要求学生重新输入密码。

| 场景 | 建议规则 |
| --- | --- |
| 记住学生身份 | 常用浏览器最多保留 30 天登录状态，过期重新输入学号和密码。 |
| 新进入 | 首页点课、直接链接、新标签及页面刷新均先联网核验；失败时保留进度并显示重试，不先闪现课件。 |
| 同课内部操作 | 换题、换活动、阅读历史对白不算重新进入，不逐题等待联网。 |
| 一次学习 | 核验后 2 小时自动重新核验；有效资格且联网时保持题目和操作不变。短时断网可使用当前内容；核验失败保留操作，等待重试。 |
| 长时间放到后台 | 后台连续超过 30 分钟，返回时先重新核验；短暂切换应用不打断。 |
| 修改开放或转班 | 下次进入或重新核验按新范围执行，已经有效进入的本轮不突然清空。 |
| 退出、换学生、重置密码 | 旧身份不得继续新开课程；改密与重置使旧密码及旧登录失效。已经进入的本轮按上述有效期结束，不冒用新身份提交。 |
| 完全离线打开课程 | 不新开课，显示“联网后再进入”，允许重试和返回；资源和学习记录继续保留。 |

进入顺序固定为：确认学生身份 → 核验当前班级与课程 → 准备并核对完整资源 → 显示课件。保存资源与保存资格是两件事，命中资源缓存不能代替核验。

公共字体、标志和共用图片可以按文件内容复用；登录响应、个人课程清单和个人成果不得作为跨学生的公共缓存。活动草稿、待同步成果和个人显示状态按学生隔离。新学生无权进入上一位已缓存的课程；退出不删除其他学生的成果。

## 5. 学习成果怎样同步

每个成果包含学生、课程、活动及内容版本，保留现有各课程的真实完成条件。题目没做、答错或仅看过提示不能被同步成完成，证书仍受现有活动要求约束。

- 完成活动后先保存到本机的该学生记录，再同步服务端；网络失败排队重试，页面如实显示待同步状态，不谎报已经同步。
- 两台设备重复上传同一完成事件只算一次；一台较旧设备不能把另一台已完成活动改回未完成，也不能叠加星星超过上限。
- 本机未提交草稿只归本机当前学生，返回课程按已有恢复规则处理。重练和主动重置使用明确操作，不能被旧上传覆盖；冲突以对应重置代次和活动版本处理。
- 断网期间完成的本轮记录回网后仍归最初的学生；转班、课程收回和停用不把既有成果删除或转给其他人。
- 新登录前的匿名记录单独保留为“本机旧记录”，可查看原有摘要，不自动认领、上传或计入个人成果；已下架课程的旧摘要不提供重新进入课件的入口。

同步的是课程已有学习成果，不是新增考试认证或教师成绩统计系统；暂不加入逐题分析报表、排名和考勤。

## 6. 实现边界

现有静态课件保留，增加独立的班级访问服务和持久化数据存储。服务负责管理员、班级、学生、开放清单、登录、课程进入核验和个人成果。数据放在发布包之外，换版本或回退不能覆盖学生记录；上线前验证备份与恢复。

服务端是资格判断的最终依据。浏览器传来的班级号、本机标志、隐藏卡片和 Service Worker 不能授予权限。每个受保护请求都需有效身份及相应课程进入资格，访问另一学生的记录也必须拒绝。依据：[OWASP 授权指南](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)。

入口、课包清单、教学内容、原始资源地址和固定资源地址使用一致规则。资源资格从课程的资源依赖清单派生：授权 49–50 教学单元应允许其所需的单课目录音频，不应顺带允许进入 Lesson 49 单课。共享文件不能按目录名粗略封禁。

学生密码使用带随机盐的 scrypt 单向摘要保存；学生自设密码不保存明文或可逆副本。未领取的随机初始密码另使用现有 `card-key` 做 AES-256-GCM 加密，只有管理员可查看／打印，首次领取后清除密文。数据库和密钥均保持私有权限并一起备份；完整性检查同时核对历史卡列和待领取密码密文。学生及管理员登录使用 HttpOnly 会话、登录限速、会话过期与管理写操作来源校验。初始改密会话独立于学习会话，直接调用接口也不能绕过。管理接口不能用学生登录调用。会话防护依据：[OWASP 会话管理指南](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)；本方案中的各有效期是产品选择。

旧库原位升级：旧学习卡账号按原创建顺序分配永久学号；已有拼音账号保留原学号。尚未激活且拼音已核对的账号一次性换成随机初始密码，同时撤销旧学生／待改密会话。已设置的正式密码、内部学生标识、班级和成果保持不变。无法可靠转拼音的历史账号仍需老师核对并重置后才能发放。旧码与二维码不再授予登录；查看、重启和备份恢复不再次轮换有效初始密码。升级前备份数据库及 `card-key`，老师需重新发放待激活账号单。恢复以所选快照为准，不能还原备份之后的改密／领取；回退较早快照后，老师应核对并重置重新发放待激活账号。

### 登录来源与限流

- 本地直连默认不信任任何转发头，按真实连接来源计数；客户端伪造 `X-Forwarded-For`、`X-Real-IP` 或 `Forwarded` 不能换额度。
- 生产明确设置 `LESSON_TRUST_PROXY=loopback`，且只监听 `127.0.0.1`。Nginx 必须用 `$remote_addr` 覆写 `X-Forwarded-For`，不可拼接客户端输入。
- 应用仅在直接对端为可信 loopback 时接收一个合法 IP；缺失、重复、多跳、端口、方括号或非法地址直接拒绝。IPv4 映射和 IPv6 等价写法归一后计数；其他对端的转发头不受信任。
- 每来源 120 次／分钟与每账号 12 次／分钟分开执行。一个来源耗尽额度，不阻断其他来源的正常学生、管理员和改密操作；同一网络共用公网 IP 时仍共享该网络的来源额度。
- 生产缺少明确代理设置时拒绝启动；生产本机健康检查可直连，但登录验收须经过代理。本地开发直连模式继续可用。

正式地址按已确认的[根目录发布与迁移](2026-09-26-0134-v1.0-根目录发布与迁移.md)执行：新版服务根目录，原首页迁至 `/exercise/`，旧 `/lesson/` 下线；本地子目录预览仍可用于检查。关闭脚本或入口脚本未加载时，禁用表单提交，不能将密码作为查询参数写进地址；只提供入口提示或下架页，不能回退到未经核验的完整课程。现有公开 V1 对身份接口的禁止需要按新边界正式修订，并新增相应验收；不能直接关闭检查。

### 已核实的改造重点

- 全部十六个教学单元都从 `requirePublishedCourse('lesson49')` 读取共用反馈定义，49–50 还读取教学数据。必须先将共享教学定义与公开路由状态分开，不能把 Lesson 49 从发布表一删了之。依据：[组合单元定义](../../../unit49-50/content.js)、[1–2 单元定义](../../../unit1-2/content.js)及其余各 `unit*/content.js`。
- [现有构建](../../../scripts/build-static.js)要求所有 `lesson*/index.html` 注册并复制相关目录；[课包生成](../../../scripts/course-packages.js)会扫描单元；[测试服务器](../../../tests/support/static-server.js)对未生成的路径会回落读取源码。下架需要同时明确公开入口与内部源码的边界。
- [资源发布](../../../scripts/stage-course-resources.js)保留历史文件，[Nginx 配置](../../../deploy/nginx/canranstudio-lesson-location.conf)目前公开提供旧固定资源与清单。新授权边界不能只套在最新版本的 HTML 上。
- `withdrawn` 目前只认精确的 `课程@版本`；旧加载器及 Worker 都先读缓存再检查更新。[旧缓存测试](../../../tests/e2e/course-cache-updates.spec.js)允许已撤回版本先显示到下一次操作，这一预期必须与“进入前核验”的新规则一并修订。既有测试通过不代表新边界已经满足。

## 7. 旧公开版本怎样过渡

1. 先在本地和测试环境完成新目录、下架页、学生入口、管理流程与真实课程验收；管理员身份、班级和学生账号准备就绪后，才具备发布条件。
2. 新发布清单只登记十六个教学单元；七项下架课程保留明确的不可用状态，不被自动扫描重新加入。
3. 发布时处理旧 Service Worker、旧课包、旧直接地址及固定资源入口。旧版本清单不能继续充当公开后门；新客户端在显示旧缓存课程前完成联网核验。
4. 迁移只调整课程资源缓存和访问路径；匿名记录单独保留，个人成果数据不随清缓存或发布回退丢失。
5. 已经离线保存的旧公开课件无法被远程即时收回。迁移验收分别验证“收到更新的在线浏览器”与“完全离线、未收到更新的旧浏览器”，不把后者说成可即时撤销。
6. 开启班级访问后的故障回退仍保持访问控制，不能直接回退成任意人公开可访问的旧官网；权限服务不可用时保留记录并提示稍后重试。

## 9. 实施与发布顺序

完整方案确认后依次完成：统一课程目录与七项下架 → 服务端身份和班级开放 → 学生入口与管理员管理 → 缓存迁移和成果同步 → 页面及访问边界验收。每步维护同一份课程范围，避免多个清单分别生效。

本次设计不包含收费、作业批改、多教师管理、自助注册、短信认证、招生试听或新的配音改造。正式实施时同步统一标准与缓存设计的适用边界，保留旧公开版本的历史验收记录。

开发、检查、提交、推送、正式部署和真机验收分别报告。完整方案确认只启动获准的实施范围，不把文档放入 `publish` 当成已经发布，也不自动执行 Git 推送或生产切换。
