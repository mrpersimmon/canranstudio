## 2. 学生怎样使用

1. 第一次打开网站时，看到灿然英语工作室标志和“输入学习码”；也可以直接扫描自己的学习卡。
2. 核验成功后，首页显示自己的名字、班级和该班开放的课程。没有开课时显示“老师还没开放课程”，不给出无效卡片。
3. 点击课程，先核对当前资格，再准备完整画面。缓存齐全时只核验资格和必要元数据，不重新下载整课。
4. 进入后，词卡、作答、重试、灯泡、进度和证书继续沿用统一标准，不把登录步骤插进每道题。
5. 完成一个活动后保存个人成果。换设备登录同一学习卡，可看到已同步的成果；正在选但未提交的答案不跨设备带过去。
6. 顶部可查看当前身份并“切换学生”或“退出登录”。切换前保存待同步记录，新学生看不到上一位的星星、草稿与证书。

旧链接的目标限定为站内合法课程：未登录先登录，核验通过再回到目标活动；无资格显示“这节课还没向你的班级开放”和“返回课程”。下架地址直接显示下架页。

学习卡是个人进入凭证，但仍可被转借；首版不把它当作真实身份认证，也不通过多端限制承诺防止分享。

## 3. 管理员怎样使用

管理页与学生页面分开，保留网站标志和按钮风格，主要提供三个区域：

- **班级**：创建、改名；进入班级后勾选开放单元并保存；可以暂时不开放任何课程。
- **学生**：输入姓名或课堂称呼、指定班级；支持逐个添加和多行粘贴；查看、改名、转班、停用与恢复。允许同名学生，但用独立编号区分。
- **学习卡**：按学生或班级生成可打印的学习卡；每张含学生称呼、班级、二维码与个人学习码。遗失时重发，旧卡失效；不通过聊天自动发送给学生。

普通转班不换学生身份、不清空成果。停用使用状态代替删除记录；首版不提供批量删除学生数据的快捷操作。管理员可以预览各班实际看到的课程，但预览不写入学生成绩。

管理员账号单独登录，不与学生学习卡混用。首次设置和账号恢复由站点维护者在服务器侧完成，不新增短信、邮箱或微信授权依赖。系统只需要课堂称呼和班级，不要求学生身份证、手机号或地址。

## 4. 缓存与一次学习的边界

下列默认值已随整体方案确认。2 小时和 30 分钟均触发静默重新核验，不是限制学习时长或要求学生重新输入学习码。

| 场景 | 建议规则 |
| --- | --- |
| 记住学生身份 | 常用浏览器最多保留 30 天登录状态，过期重新扫码或输入学习码。 |
| 新进入 | 首页点课、直接链接、新标签及页面刷新均先联网核验；失败时保留进度并显示重试，不先闪现课件。 |
| 同课内部操作 | 换题、换活动、阅读历史对白不算重新进入，不逐题等待联网。 |
| 一次学习 | 核验后 2 小时自动重新核验；有效资格且联网时保持题目和操作不变。短时断网可使用当前内容；核验失败保留操作，等待重试。 |
| 长时间放到后台 | 后台连续超过 30 分钟，返回时先重新核验；短暂切换应用不打断。 |
| 修改开放或转班 | 下次进入或重新核验按新范围执行，已经有效进入的本轮不突然清空。 |
| 退出、换学生、重发学习卡 | 旧身份不得继续新开课程；重发使旧卡及旧登录失效。已经进入的本轮按上述有效期结束，不冒用新身份提交。 |
| 完全离线打开课程 | 不新开课，显示“联网后再进入”，允许重试和返回；资源和学习记录继续保留。 |

进入顺序固定为：确认学生身份 → 核验当前班级与课程 → 准备并核对完整资源 → 显示课件。保存资源与保存资格是两件事，命中资源缓存不能代替核验。

公共字体、标志和共用图片可以按文件内容复用；登录响应、个人课程清单和个人成果不得作为跨学生的公共缓存。活动草稿、待同步成果和个人显示状态按学生隔离。新学生无权进入上一位已缓存的课程；退出不删除其他学生的成果。

## 5. 学习成果怎样同步

每个成果包含学生、课程、活动及内容版本，保留现有各课程的真实完成条件。题目没做、答错或仅看过提示不能被同步成完成，证书仍受现有活动要求约束。

- 完成活动后先保存到本机的该学生记录，再同步服务端；网络失败排队重试，页面如实显示待同步状态，不谎报已经同步。
- 两台设备重复上传同一完成事件只算一次；一台较旧设备不能把另一台已完成活动改回未完成，也不能叠加星星超过上限。
- 本机未提交草稿只归本机当前学生，返回课程按已有恢复规则处理。重练和主动重置使用明确操作，不能被旧上传覆盖；冲突以对应重置代次和活动版本处理。
- 断网期间完成的本轮记录回网后仍归最初的学生；转班、课程收回和停用不把既有成果删除或转给其他人。
- 新登录前的匿名记录单独保留为“本机旧记录”，可查看原有摘要，不自动认领、上传或计入个人成果；已下架课程的旧摘要不提供重新进入课件的入口。

同步的是课程已有学习成果，不是新增考试认证或教师成绩统计系统；暂不加入逐题分析报表、排名和考勤。

## 6. 实现边界

现有静态课件保留，增加独立的班级访问服务和持久化数据存储。服务负责管理员、班级、学生、开放清单、登录、课程进入核验和个人成果。数据放在发布包之外，换版本或回退不能覆盖学生记录；上线前验证备份与恢复。

服务端是资格判断的最终依据。浏览器传来的班级号、本机标志、隐藏卡片和 Service Worker 不能授予权限。每个受保护请求都需有效身份及相应课程进入资格，访问另一学生的记录也必须拒绝。依据：[OWASP 授权指南](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)。

入口、课包清单、教学内容、原始资源地址和固定资源地址使用一致规则。资源资格从课程的资源依赖清单派生：授权 49–50 教学单元应允许其所需的单课目录音频，不应顺带允许进入 Lesson 49 单课。共享文件不能按目录名粗略封禁。

个人学习码使用不可预测的随机值，服务端不明文保存可直接登录的学习码；扫码兑换登录后移除地址中的凭证，访问日志和文档不记录它。学生及管理员登录使用受保护的服务器会话，包含登录频率限制、会话过期与管理员写操作校验。管理接口不能用学生登录调用。会话防护依据：[OWASP 会话管理指南](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)；本方案中的 30 天、2 小时和 30 分钟是本产品建议值，并非指南给出的固定标准。

功能仅服务 `/lesson/`，不改变主官网。关闭脚本时只提供入口提示或下架页，不能回退到未经核验的完整课程。现有公开 V1 对身份接口的禁止需要按新边界正式修订，并新增相应验收；不能直接关闭检查。

### 已核实的改造重点

- 全部十六个教学单元都从 `requirePublishedCourse('lesson49')` 读取共用反馈定义，49–50 还读取教学数据。必须先将共享教学定义与公开路由状态分开，不能把 Lesson 49 从发布表一删了之。依据：[组合单元定义](../../../unit49-50/content.js)、[1–2 单元定义](../../../unit1-2/content.js)及其余各 `unit*/content.js`。
- [现有构建](../../../scripts/build-static.js)要求所有 `lesson*/index.html` 注册并复制相关目录；[课包生成](../../../scripts/course-packages.js)会扫描单元；[测试服务器](../../../tests/support/static-server.js)对未生成的路径会回落读取源码。下架需要同时明确公开入口与内部源码的边界。
- [资源发布](../../../scripts/stage-course-resources.js)保留历史文件，[Nginx 配置](../../../deploy/nginx/canranstudio-lesson-location.conf)目前公开提供旧固定资源与清单。新授权边界不能只套在最新版本的 HTML 上。
- `withdrawn` 目前只认精确的 `课程@版本`；旧加载器及 Worker 都先读缓存再检查更新。[旧缓存测试](../../../tests/e2e/course-cache-updates.spec.js)允许已撤回版本先显示到下一次操作，这一预期必须与“进入前核验”的新规则一并修订。既有测试通过不代表新边界已经满足。

## 7. 旧公开版本怎样过渡

1. 先在本地和测试环境完成新目录、下架页、学生入口、管理流程与真实课程验收；管理员身份、班级和学习卡准备就绪后，才具备发布条件。
2. 新发布清单只登记十六个教学单元；七项下架课程保留明确的不可用状态，不被自动扫描重新加入。
3. 发布时处理旧 Service Worker、旧课包、旧直接地址及固定资源入口。旧版本清单不能继续充当公开后门；新客户端在显示旧缓存课程前完成联网核验。
4. 迁移只调整课程资源缓存和访问路径；匿名记录单独保留，个人成果数据不随清缓存或发布回退丢失。
5. 已经离线保存的旧公开课件无法被远程即时收回。迁移验收分别验证“收到更新的在线浏览器”与“完全离线、未收到更新的旧浏览器”，不把后者说成可即时撤销。
6. 开启班级访问后的故障回退仍保持访问控制，不能直接回退成任意人公开可访问的旧官网；权限服务不可用时保留记录并提示稍后重试。

## 9. 实施与发布顺序

完整方案确认后依次完成：统一课程目录与七项下架 → 服务端身份和班级开放 → 学生入口与管理员管理 → 缓存迁移和成果同步 → 页面及访问边界验收。每步维护同一份课程范围，避免多个清单分别生效。

本次设计不包含收费、作业批改、多教师管理、自助注册、短信认证、招生试听或新的配音改造。正式实施时同步统一标准与缓存设计的适用边界，保留旧公开版本的历史验收记录。

开发、检查、提交、推送、正式部署和真机验收分别报告。完整方案确认只启动获准的实施范围，不把文档放入 `publish` 当成已经发布，也不自动执行 Git 推送或生产切换。
