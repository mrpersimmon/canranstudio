# 性能设计标准与验收清单 v1.0

2026-10-23 · 适用分支：`codex/release-canranstudio`。本文汇总现有性能要求和本轮课程更新检测优化，作为性能目标、测量口径与验收范围的统一入口；不降低原有门槛，不把历史结果当作本轮实测。资源协议、访问资格及恢复实现仍分别维护在[网页加载缓存设计](2026-09-24-2031-v1.0-网页加载缓存设计.md)、[班级访问设计](2026-09-26-0048-v1.2-班级课程访问设计与验收.md)；教学与历史成果边界仍按[统一设计标准 v1.54](2026-10-18-0843-v1.54-教学单元设计标准与验收清单.md)。

适用于登录目录、单课加载、缓存复访、普通更新与紧急撤回。生产入口为根目录 `/`；`/lesson/` 是本地兼容测试前缀，`/exercise/` 为独立旧站，不得把旧子目录时代的路径或公开离线规则当作当前生产规则。文档位于 `publish` 不代表已经提交、推送或上线；本轮执行结果在第8节单列。

## 1. 不能以性能优化牺牲的边界

性能优化须同时保留完整课件、正确权限和真实学习成果。减少响应体、合并重复工作、复用已核验文件都可以；删除必需素材、裁剪中文姓名／旧证字库、绕过授权、延长原测试门槛、伪造准备完成或重置学习记录不能作为提速方案。

课程缓存单位是一门课，例如 Lesson1–2。目录不是所有课程的合并课包，不能预下载未选择课程的题目、场景和人物。当前课所有必需资源进入同一构建清单，包含动态图片、CSS背景、实际字体、完成页、纪念卡、旧证所需素材及导出资源；不能仅以第一屏可见作为完整就绪。

进入课程依次执行身份与班级资格核验、完整资源准备、画面就绪检查。已缓存资源不能代替本次授权；个人身份、课程授权清单、学习记录与成果不能跨学生公共缓存。新进入需联网核验，当前已核验学习只在原有效期内允许短时断网，权限续核周期沿访问规范执行，不与普通更新轮询合并或放宽。

## 2. 已有性能目标与准确计时边界

| 指标 | 保留的要求 | 验收边界 |
| --- | --- | --- |
| 点课反馈 | 点击后100毫秒内出现按下／准备状态。 | 不插入额外确认；无强制播放完成的等待动画。小于200毫秒的准备不刻意展开完整加载层，错误及时显示。 |
| 参考课包首次点课 | 10 Mbps下载、150毫秒往返延迟，**小于5000毫秒**。 | 从已完成真实目录准备后的实际点击，到加载层消失、实际字体和图片就绪、课程按钮可操作且完整画面已渲染。记录实际下载字节，不把自动滚动或测试工具轮询计入用户耗时。 |
| 完整缓存复访 | 至少20次真实重新打开导航并点课，**P95小于1500毫秒**。 | 同一浏览器与持久缓存，恢复保存位置；当前专项按20个耗时排序的第19个值计算P95。不能以同页返回或20次刷新替代。 |
| 缓存复用 | 完整缓存复访的图片、字体、脚本不重新下载；无变化文件零重复资源下载。 | 资格请求、版本元数据请求与资源请求分列。304没有响应体，但仍是请求，不能写成“所有网络请求为零”。 |
| 课程独立性 | 改另一门课不让本课失效；更新本课只补变化或缺失的文件。 | 核对内容地址与真实请求，不只比较总文件数；共用资源按内容摘要复用。 |
| 进入后完整性 | 阻断网络后，已准备课程的换题、人物状态、完成页、纪念卡与旧证仍完整。 | 不出现破图、空背景、缺图选项、无脸人物；后续切换先本地解码再替换，不闪回整页加载层。 |
| 浏览器重启与刷新 | 重启后另测续学；同一标签连续刷新20次另验。 | 记录位置、完整画面、真实按钮与零重下载；刷新压力结果不冒充点课P95。 |

上述5秒门槛是原参考课包、固定网络与目录已准备条件下的专项，不是任意课程、设备、直链或从登录开始的总时长保证。高图片量课程须逐课报告完整字节、实际耗时与预算，超出先优化并保留未达标事实，不能删图、删字体或把超出结果直接改判通过。

必须分别记录四个时间，不能相互替代：

1. **目录可选耗时**：从登录完成后的目录导航开始，到授权课程入口真实可用。此时不要求全班插画和共用字库完成。
2. **共用字体准备耗时**：从本次目录开始准备，到已授权共用字体完成下载、校验和可用性确认。记录是否已缓存、完整字节及失败。
3. **点课完整加载耗时**：从真实点击，到所选课完整可操作；注明点击时字体是否已准备。原5秒专项保持“已准备目录”条件，同时另验目录尚未准备时立即点课。
4. **冷直链与全流程耗时**：空资料直接访问课程，以及从空缓存登录再选课的总耗时单列。不能把等待字体的时间移到点击前后便宣称总耗时下降。

## 3. 目录与资源准备

目录在身份、授权与成果读取后即可选课。插画按视口准备并预留正确比例，图片失败只在该卡片提供局部重试，保留名称、学习进度和入口，不显示破损图标、不隐藏全班课程。目录可渐进呈现，课内仍执行完整进入；不能把目录容错扩展为缺图课件也可以开始学习。

保留2026-10-20用户确认的目录共用字体预备方案，采用2026-10-21修正后的后台、不阻断入口方式：只准备当前授权课程实际使用的共用字库，无开放课程则跳过；失败可独立重试，孩子也可直接选课，由本课加载流程补齐。完整中文姓名覆盖、当前纪念卡及旧证原字体都保留，逐文件长度／SHA-256校验与课程必需声明不删除，总下载量不能因挪动时序而记为减少。

前台资源下载最多6个并发，按既有大小优先调度；后台准备最多2个并发，图片解码继续有界。调整并发须有目标设备与负载证据，不能无限并发挤占用户正在进入的课程。缓存以内容摘要去重，相同文件和同课包的并发任务复用，取消无消费者任务；关闭一个页面不能取消其他页面仍需要的工作。

目录后台准备必须有明确的页面生命周期。普通同页点课或离开目录时，取消该目录的排队锁、缓存读取及下载；取消后的只读结果不得继续删除、写入缓存或更新就绪标记，已经开始的不可中断写入完成后再释放其锁。浏览器从页面缓存返回目录时应重新准备；新标签和修饰键导航保持原生行为。不能让已离开的目录长期占用同一字体的资源锁，也不能通过拦截点击后无限等待后台任务转移阻塞。共享加载层变更时，以真实“目录尚未准备就点课、返回目录再进入”、Worker不可用及缓存回收路径复验，保留原计时起点、完整字库、逐文件校验、成果和日期断言；后续新课复用该能力，不重复实现取消逻辑。

资源就绪须同时满足两个条件：文件状态、类型、长度与摘要正确；实际字体、当前图像解码和布局完成。200错误HTML、半截文件、解码失败均不算成功。首次检查完整课包图片，后续已校验的同内容图片不反复整课解码；切换画面仍核对真实使用地址的图像就绪。只保留当前课需要的解码资源，离开后可释放，不把全站插图常驻内存。

配音版启用录音默认随课准备，但文件保存不等于真实听完，失败不阻断无声音依赖的阅读；无配音版不预载历史英语音频。反馈音尽力准备且失败不阻断作答，不以忽略声音请求掩盖重复下载。外部教师材料按需加载，不能把课内必需图归为外部可选文件。

## 4. 更新提醒与服务器请求预算

### 普通版本检查

普通更新不要求秒级生效。可见课程页正常轮询采用**180–300秒（3–5分钟）随机错峰**，避免整班同时登录后固定同一时刻发请求。首次进入及时检查；进入、恢复联网（online）、页面重新可见（visible）的触发共用30秒最小间隔，短时间多次事件合并，存在进行中的检查时复用它。事件不能绕过失败退避。隐藏或离线时不继续普通轮询，恢复时不补发错过的每一次定时任务。

普通检查只请求**当前课程且经过授权的轻量版本元数据**：`course-status/{id}.json`，使用ETag条件请求，未变化返回304，无需每次返回全部72课索引。端点随应用挂载路径提供，生产根目录及本地 `/lesson/` 共用协议，静态预览／测试服务亦支持。服务器须先确认身份与该课权限再判断304，不能凭旧ETag绕过转班、撤课、退出或禁用；普通学生、教师／管理员合法预览仍沿各自原权限规则。账号响应使用 `Cache-Control: private, no-cache` 与 `Vary: Cookie`，不作为跨学生公共缓存。完整 `course-index.json` 仍用于目录及首次／明确重试最新加载，定时检查不再请求它。

普通定时检查在无变化时不重新取完整课包、不重做图片解码。第一次发现候选版本后，按“课程＋候选版本”合并准备任务；**同一候选完整准备成功后，本页后续检查不再次准备**。并发事件不能重复启动同一准备，选择继续旧版后也不反复为该候选读清单、扫缓存和解码。准备失败不记成功，可以按退避策略重试；发现另一个新版本可启动它的一次准备。去重只在当前页面内生效，重新进入仍完整核验；切回页面时原有的当前课缓存完整性检查继续保留，不能声称“完全不读缓存”。每次进入或点击“刷新课程”仍须确认目标包完整有效，不能依赖过期的内存标记跳过缺失检查。

普通检查连续失败按**6–8 → 12–14 → 24–26 → 28–30分钟**延长重试间隔，达到上限后仍在28–30分钟范围错峰；成功后恢复180–300秒常规周期。一次元数据请求的15秒期限覆盖响应头及完整响应体，完成后释放计时器和事件监听；进入、联网、可见事件不绕过失败退避。用户主动刷新重试不受后台退避限制；失败不能阻塞当前有效课程，也不能当成“没有新版”。元数据检查完成事件只承载检查状态，不含学生身份、学习成果等个人数据。

2026-10-24按用户确认统一最新版：后台准备不能混入当前已打开页；每次进入及刷新核验最新授权课包，复用未变资源，不再提供继续旧版。省流量、Worker不可用仅影响可选后台下载，不取消最新版本核验、可见刷新提示或完整性检查。一次性epoch数据切换不是性能优化副作用，不在每次更新时重复重置。

### 紧急撤回检查

普通更新降频不能把教学错误撤回也拖到3–5分钟。紧急撤回通过 `course-withdrawals/{id}.json` 独立轻量检查，**正常联网、页面可见且定时器正常调度时，每45–60秒随机错峰检查，最多约1分钟**；连续失败按15–20 → 30–35 → 55–60秒重试，达到上限仍错峰。单次请求同样有覆盖响应体的15秒期限，先鉴权再ETag304，使用相同私有缓存头。端点按当前课程核验访问资格，但响应保留全局撤回表，避免局部结果覆盖其他课程已知的撤回状态。首次进入与已有权限续核规则仍保持；已得知撤回的版本不能继续新开或作为“继续当前版本”选项。收到撤回后保存当前位置，在下一次相关操作前按原规则拦截、准备替代包，不半途拼接新旧题目。

隐藏、断网、请求失败或系统冻结页面时无法保证一分钟内得知撤回，必须如实说明这一区别；不能把轮询间隔当作所有设备的消息送达保证。普通检查的退避、候选准备或用户收起提示不能暂停独立撤回检查。撤回请求也须轻量、可条件验证，不取整班索引或触发课程下载。

### 请求量和容量结论

当前元数据检查按每个可见页面独立调度，没有跨标签合并。假设每人只有一个可见课程页、网络正常且没有额外切换事件，普通检查平均约每240秒一次，紧急撤回约每52.5秒一次，平均请求率约为 `N/240 + N/52.5`；多标签、首次进入、重新可见事件与请求耗时另行计算。普通版本请求频率降低，保留独立撤回后总请求次数不保证比旧“一分钟一次”更少，不能宣称整体请求直接减少三至五倍。

优化主要减少每次响应体、服务端索引序列化及客户端重复准备／解码。ETag304仍有连接、鉴权与响应头成本；单课响应变小也不证明任意在线人数都能承载。容量验证须分别列普通／撤回／权限请求数、200与304比例、字节、失败率、响应延迟、CPU／内存和并发用户模型。没有真实并发测试，不给服务器承载人数保证；现有学习过程和成果同步优先于可选后台下载。

## 5. 缓存、恢复与学习成果保护

| 约束 | 保留要求 |
| --- | --- |
| 版本完整性 | 当前页面锁定一个完整课包；候选先全部核对，再原子标记可用。包版本、文件摘要与学习内容版本分开，更新图片或缓存不能当作重置成绩的理由。 |
| 中断恢复 | 完整核对过的文件可复用，只补缺失／损坏项；半包不标完整。Worker内存不作永久真相，关闭、重启及存储被回收后仍检查实际缓存。 |
| 存储预算 | 原128 MiB是待真机验证的资源软预算，不是浏览器容量承诺。先清中断残留与未使用旧包，保护活动包、切换中的完整旧包和共用文件引用。 |
| 缓存清理 | 仅本应用、本挂载作用域的资源缓存及包索引；不清同源其他站点，不注销无关Worker，不调用全站清除。学习记录、草稿、星星、旧证、姓名与原领取ISO及显示日期全部保留。 |
| 会话降级 | Worker不可用、存储禁用或持续拒写时，可在当前会话完整准备后学习，但不声称已持久保存；不能承载完整课包则保留明确失败与恢复入口。 |
| 超时与重试 | 保留15秒请求期限和既有有限重试边界，覆盖完整响应体；8秒慢网提示、超过30秒可重试等原长等待设计继续按加载规范验收。不得只增超时掩盖性能问题。 |
| 失败恢复 | 手动重试重新取当前清单；无有效新包时只可继续授权且未撤回、完整可用的旧包。成功后还验刷新、返回目录再入与继续答题，不只验首次重试。 |
| 发布与回退 | 先保存并核对固定资源再原子切换入口，旧包所需资源按原保留策略继续可取；代码回退不回滚学生数据库，不全域清缓存解决版本问题。 |

旧证必须能实际打开、显示、导出／打印，不能只保留一行元数据。姓名、原领取ISO、约定时区显示日期、历史星数与新版独立成果按原规则核对；性能优化不得改领取日或代答新题。故障验收使用真实旧版作答与领取证书，再升级验证，不向数据库或页面注入假成绩。

历史原件与PNG对照须明确原页面使用的时区，并在不同时区的新设备核对现行固定北京时间显示。冻结旧页依设备时区显示时，不能将其任意设备的日历日直接当作现行标准日；原ISO／姓名必须另行逐字核对，同时用固定跨日时刻验证约定时区与数据库归档。该验收前提不改变原产品日期规则、原领取时间或冻结旧渲染器，也不放宽原图、查看及导出断言。

上述历史原件约束同时覆盖静态课程与账号入口，查看、PNG和打印分支按实际影响分别检查；不能用一套通过代替另一套。共享日期显示或验收基础设施变化时按渲染器与存储格式找调用方，无历史的新课程仍按原适用范围验收，不固定追加全站历史回归。

## 6. 统一测量方法

每次报告记录源码／构建版本、环境、CPU、浏览器及版本、挂载路径、网络限制、完整课包字节、首次或复访、缓存状态与测试并发。性能计时独立运行，不与其他浏览器任务抢占机器；冷加载与复访分别启动浏览器。复访不强制垃圾回收、不额外预热其他课，计时用例关闭trace，其余故障用例保留追踪。

点击起点来自页面实际事件，终点包括加载层结束、正确恢复位置、实际字体／图片和真实按钮可用后的渲染帧；工具驱动耗时另列。保留20个原始样本、导航耗时、部分失败样本、失败步骤和浏览器错误，不只保存最后一次成功值。延迟、503、错误类型、损坏文件和Worker请求的故障必须证明实际命中。

新增调度规则可以用受控时钟验证3–5分钟、节流、退避和撤回边界，真实HTTP验证ETag／304、授权变更及实际请求量；受控时钟不能替代网络真实性或5秒／P95性能专项。需覆盖真实页面的升级、打开页保持完整、最新版失败重试、无变化周期和同一候选不重复准备；记录请求与解码／准备次数，不只看提示卡仍在。

请求次数须限定到本次访问的测量窗口与对应课程；共享测试服务中的前序历史、其他课程请求分别保留，不能混入当前页计数。用真实历史条件请求验证计数隔离，同时保持准确次数、条件头和响应体字节断言，不能靠放宽次数掩盖重复轮询。2026-10-24远端回归发现并修正这一观测范围问题，未改变应用调度与性能预算，复现方法见测试说明。

CI环境准备时间与页面加载时间须分开记录。2026-10-24在GitHub Ubuntu runner上发现系统镜像持续低速导致安装阶段超时，实际性能测试未执行；因此仅调整该CI环境中已有官方镜像的优先级，保留依赖、签名验证及原期限。该环境处理不属于课程资源裁剪或性能目标调整，未知runner布局沿默认安装并记录；最终仍须看到性能用例实际运行和通过。镜像吞吐是否改善以对应远端日志为准，不作为未来下载速度保证。

按受影响范围验证根目录与测试子路径、Chromium与WebKit；320／390／768／1280宽度及短屏的提示、加载和失败操作可达，尊重减弱动态及键盘操作。自动化手机尺寸和WebKit不替代iPhone／Android／微信真机：首访、重启复访、弱网、保存纪念卡与实际设备内存边界单列待验。线上容量、真实部署后HTTPS普通用户目录也须单列，不以服务健康或管理员登录成功代替。
