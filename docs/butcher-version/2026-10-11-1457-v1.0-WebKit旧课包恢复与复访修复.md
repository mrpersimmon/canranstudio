# WebKit 旧课包恢复与复访修复

日期：2026-10-11。分支：`codex/debug-reward-version`。基线：`0a9646e`。

## 问题与证据边界

本轮处理「旧包缺图 → 发布新版 → 重试能进入 → 再次进入又失败」。用户的 iPhone 系统版本和现场日志未知，因此不把本地复现直接等同于该用户所有打不开的原因；也不要求用户清空学习记录。

在 WebKit 的 Worker 不可用路径，先用真实账号完成单词寻宝取得一星，再在下一活动答错、订正、推进到第二题。让旧包的一张图返回 404，发布内容不变但图片地址更新的合法新包。旧实现重试能进入，刷新又停在加载失败页。

诊断观察到：失效前有 107 项必需资源，移除一项后剩 106 项；失败恢复期间资源缓存变空，但页面已经读入其余资源。重试仅下载新版图片，画面使用内存正常显示；`commit()` 发现缓存缺项便返回失败，IndexedDB 仍指向旧包。下次打开又请求旧图片。这是「内存已就绪」与「课包已保存」之间的缺口。

已把网络故障从页面拦截移到临时服务器的 HTTP 边界；正常 Worker 和不可用 Worker 分别测试。无 Worker 的复访失败在真实 HTTP 故障下仍可复现，并非仅凭一次 `page.route()` 结果判断。另在 Chromium 主动回收课件缓存，复现同一问题。只回收资源字节，不制造或重写学习状态。

## 修复

1. 保存课包前发现缓存缺失，从当前已校验的内存补齐；再次核对长度和 SHA-256，资源齐全后才原子更新新版索引。已有完整资源不重复下载。
2. 补测发现持续拒绝缓存写入时，仍只能会话内显示新版。因此下次进入若旧缓存包的资源已失效，加载器最多尝试一次服务器的不同新版本；仍执行权限、完整性和画面准备检查。新版也失败则保留恢复入口，无自动刷新循环。
3. 完整的原有离线包继续可用，用户手动重试仍先取当前清单。课程、作答标识、学习记录结构、获星算法、首次满星日期规则和账号存储不变。

产品修复只涉及 `core/course-cache.js` 与 `core/course-loader.js`。没有删除账号、学习草稿、成绩、星星或纪念册数据的操作，也没有线上数据操作。

## 页面测试与防回退

`tests/login/course-loading-recovery.spec.js` 共 15 项，全部使用临时班级与虚构学生，从管理页建号、登录和真实答题开始。测试服务器结束后删除自己的临时数据目录；不接触本地完整预览或线上学生。

- Worker 正常、Worker 不可用且资源回收、缓存持续拒写三条路径：重试 → 刷新 → 课程列表 → 再次点课 → 继续答题。保留一星、第二题位置与一次错答，订正后不得误发零错星。
- 全五区真实零错获五星：资源失效、重试、刷新、复访后，姓名、五星、首次满星日期不变；纪念册仍可打开。
- 禁用较新取消接口后的进入、超时恢复、查看纪念册；L01–L06 错误分类；缺图返回课程；无法解码的图片和中断的脚本恢复。
- HTTP 故障在测试服务器生效，覆盖 Worker 发出的实际请求；生产 `server/app.js` 不加载故障模块。浏览器资源回收与拒写模拟仅作用于课件缓存边界。

`playwright.recovery.config.js` 使用 WebKit 与 iPhone 13 视口、触摸设置。`npm run test:recovery:webkit` 是固定入口；CI 在 `/`、`/lesson/` 各运行一次，结果纳入最终必需检查。相关本地检查计划也收录 WebKit，检查复用指纹使用相应浏览器的可执行文件。

## 实际验证

修复前：真实 HTTP 故障下的 WebKit 复访失败；Chromium 资源回收场景失败。第一处修复后，持续拒写场景仍失败；补充有限新版本恢复后该场景通过。记录红灯和绿灯，不能只保留最终成功。

本地使用 Playwright 1.62.0、WebKit 26.5（build 2336）、Chromium 151.0.7922.34，Node 26.5.0。最终场景结果：

| 范围 | 结果 |
| --- | --- |
| WebKit 手机视口，根目录 `/` | 15 个场景通过：整组 14 项通过；五星场景专项复测通过，见下方时限说明。 |
| WebKit 手机视口，`/lesson/` | 15 / 15 通过。 |
| Chromium，根目录与 `/lesson/` | 各 15 / 15，共 30 项通过。 |
| 共享缓存、课包更新／撤回、离线课程、图片切换与加载失败界面 | 72 / 72 通过。 |
| 缓存复访 20 次、连续刷新 20 次、10 Mbps／150 ms 首次点课 | 3 个场景通过；复访 P95 247.7 ms，无必需资源重复下载；冷加载专项 4,455 ms。 |
| 检查流程自身的回归 | 10 / 10 通过。 |

WebKit 根目录整组中的五星场景，在最后打开纪念册时达到原 90 秒总时限；此前的恢复、姓名、五星和日期断言已经通过。该场景包含建号、五区完整作答、重试及新增的两次复访，现给完整流程 120 秒预算；单步操作和页面断言的时限未放宽。专项复测通过，`/lesson/` 整组也通过。首次超时保留在证据中，不抹去或算作第一次就通过。

冷加载第一次紧接连续刷新压力检查运行，测得 5,662 ms，超过原有 5 秒门槛；随后单独启动浏览器进程复测为 4,455 ms，通过原门槛。两次结果均保留，没有修改性能阈值。以上计时均为本地模拟，不是线上 iPhone 的加载速度。

机器可读结果及源码校验值：[verification.json](evidence/2026-10-11-1457-webkit-recovery/verification.json)。已目视核对[WebKit 恢复后继续作答的页面](evidence/2026-10-11-1457-webkit-recovery/webkit-iphone-recovered.png)：图片完整，原有一星保留，错答仍为一次，没有因恢复而误发新星。

Safari/WebKit 自动页面测试不等于用户原手机、旧版 iOS 或微信真机验收。远端 CI 对根目录和 `/lesson/` 分别运行 WebKit，执行状态以 PR 当前提交的检查为准。

## 提交与 CI 补强

提交前核对 PR #17 的上一版检查，发现 5 项滚动恢复检查仍定位已删除的重复章节标题，另有 1 项冷加载计时达到 5 秒。滚动检查改为定位页面保留的唯一“语法小工坊”标题，继续验证同址续学、浏览器返回、已选草稿和星星不变。冷加载与缓存复访使用独立浏览器进程，CI 和本地计划均保留检查，原来的 5 秒与 P95 1.5 秒门槛不变；连续刷新压力检查仍在课程行为组运行。

原始失败与专项复测结果保留在上面的验证记录中，不将重试后的成功写成首轮通过。最终提交检查使用 `npm run check:plan` 与 `npm run check:commit`；当前远端检查可在 PR 查看。
