## 为什么旧检查漏掉，如何防止回退

此前主要验证文件能播放、页面能收到结束事件；引导语、半个人名和错误的词尾同样可以通过。excuse 即使词尾错误，两套识别也都能写出正确拼写。原来仅检查“音素非空”的条件过弱，历史例外规则也未全部保留实际内容。

本次在[生成工具](../../scripts/media/render-lexeme.py)和页面回归中落实以下防护：

- 保存完整生成配方、例外规则、引擎与模型版本、实际音素、词级时间边界、音色和语速。使用原来的 Kokoro 模型及 `af_heart`／`am_michael`，不另换声音。
- 例外必须命中完整词，并核对命中次数；实际音素串改变就停止。对齐裁切不得侵入前一个词，输出必须使用新文件，禁止直接覆盖已有录音。
- 四段录音使用 `-v2.mp3` 新路径，更新页面脚本版本。旧问题样例仅保留在测试资料中，退出课程音频目录；对比页与回归仍可追溯其指纹。
- 页面测试从真实控件取得网络响应并核对独立保存的修订指纹，同时等待原速原生结束。指纹用于阻止缺陷文件回流，不能代替发音判断，也不能为通过检查而随意改写预期。
- 相关课程、声音播放器、生成工具或原问题样例发生修改时，检查计划会纳入 `browser-pronunciation`。完整发布验收和人工听审仍分别执行。

还修复了换文件名可能清空旧课文进度的问题：Lesson 5–6 的课文签名包含音频路径。本次只接受与此次替换完全对应的旧签名，迁移已听位置与完成记录；不放宽其他题稿变更的校验，不生成新作答。
