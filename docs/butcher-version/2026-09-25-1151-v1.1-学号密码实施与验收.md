# 学号密码实施与验收 v1.1

2026-09-25 11:51 起实施，分支 `codex/login-version`。已在本地完成并更新 4182 预览；**未提交、未推送、未部署**。正式规则见[访问设计 v1.1](publish/2026-09-25-1151-v1.1-班级课程访问设计与验收.md)。

## 新开发

- 学号密码登录、首次强制改密、学生主动改密、老师重置密码。
- 姓名首字母加全站统一递增序号；同名独立，改名、转班不换号。此处按本轮推荐的首字母方案实施，数字不是按姓氏重新计数。
- 老师批量录入后核对拼音，支持修正多音字，ü 使用 v；服务器本地生成，不对外发送姓名。添加事务整体成功或整体失败。
- 管理页跨班级查找姓名或学号；查看和打印账号。学生自设密码仅存摘要，老师不能查看，打印仅展示尚未更改的初始密码。
- 学生入口提供“忘记学号或密码”，明确由老师找回/重置，保留个人成果。

## 已修复和兼容处理

- 取消旧二维码/学习码直接登录，旧链接移除地址中的码后提示领取学号。
- 初始密码只建立待改密会话，阻止直链、课件清单和受保护资源绕过改密页；改密与重置撤销原登录。
- 原学习卡库原位升级，内部学生标识不变，班级、星星、草稿归属不改变；旧登录会话不能继续新进入课程。待同步的已完成活动在原学生重新登录后仍可尝试同步，不转给其他人。
- 保留旧库加密列和配套密钥的恢复能力；它们不再用于登录。升级前本地数据已备份在 `.data/before-student-accounts-2026-09-25-1140`，备份不进 Git。
- 已有学生按原创建顺序占用序号；本地前两位示例学生已占用 1、2，因此实际页面里段晓东为 `d00000003`。不会为了符合空库示例重排已分配学号。

## 无脚本入口的补充修复

复查发现初始 HTML 里的登录表单没有提交方法，浏览器默认采用 GET。脚本未加载时，原表单仍可填入和提交，因此有把密码写入网址的风险。之前的无脚本用例只检查“看不到课件、看得到入口”，没有验证输入与提交是否被禁用。

新增用例先观察到按钮仍可用的失败：[原始结果](evidence/2026-09-25-1151-student-accounts/no-script-red.txt)。修复为脚本加载前禁用整个字段组，并保留页面准备失败提示；正常脚本渲染后才出现可提交表单。登录、改密、管理员重置这些凭据表单也明确使用 POST，避免未来事件处理失效时回退成 GET。回归验证正常登录/改密仍可用，无脚本时密码框与提交按钮禁用、网址没有查询参数。

## 防止回归

- 新增账号用例保留在 `tests/login/student-accounts.spec.js`，原权限用例改为走真实学号/首次改密；不保留自动输入旧学习码的测试捷径。
- `tests/fixtures/learning-card-before/` 只用于迁移，重现真实旧行为；不作为产品入口发布。
- 新密码不能等于姓名拼音、学号或原密码；两次输入一致；错误登录限速。已修改的密码不能通过管理列表、打印或 API 取出。
- 数据库唯一索引和事务保证学号不会因重名、并发录入、重启而冲突；未来不能通过“当前人数＋1”推导号码。
- 重置只针对明确学生标识，不以姓名批量匹配，避免同名误操作。

## 仍待验证与限制

- 正式发布前另验安卓微信、iPhone 微信及真实移动键盘/密码管理器体验，本轮未做真机验证。
- 拼音初始密码可被猜到；本次按要求保留规则，首次改密前不提供强身份认证保证。老师应核对本人并尽快安排激活。
- 已经打开且缓存的课程不能被服务器远程抹去；撤销会话后，新进入、刷新或重新核验会阻止访问，遵守既有 2 小时／后台 30 分钟边界。
- 用户自设密码无法找回明文，只能重置。学生学习成果不因丢卡、改名、转班或改密码自动清空。
- 本次没有运行/声明正式发布验收，没有提交、推送或生产切换。
