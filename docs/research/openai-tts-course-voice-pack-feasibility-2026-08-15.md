# OpenAI 文本转语音作为课程语音包的可行性

> 核验日期：2026-08-15
> 状态：技术与治理事实；不表示课程已经决定用 AI 语音替代真人默认包

## 结论

技术上可行。课程制作阶段可以把 catalog 中已经审核的英文台词、词项和英文提示逐条提交给 OpenAI Speech API，生成 MP3、WAV 等静态文件，再按语音包版本随课程交付。孩子学习时播放已经验收的文件，不需要实时请求模型，也不向模型发送儿童输入。

这不能描述成“Codex 本人的真人录音”或“真人老师录音”。Codex 没有一套可导出的专属真人声纹；实际声音来自 OpenAI 文本转语音模型的内置语音，由课程团队选择语音并提供美式口音、语速、语调和角色表演指令。OpenAI 官方文档说明 Speech API 可以生成文件，并允许通过指令控制口音、语速、语调和音色表现；内置语音针对英语优化，当前文档建议 `marin` 或 `cedar` 获得较高质量。[OpenAI Text to speech](https://developers.openai.com/api/docs/guides/text-to-speech)

## 必须保留的边界

- 每个教学单元离线批量生成并冻结为完整语音包；运行时不临时合成，不因网络、模型升级或随机性改变同一句教材输入。
- 语音包记录生成模型的精确版本、voice、统一指令、生成时间、文本 Source ID、文件哈希和人工验收状态。生产时使用当时仍受支持的 Speech 模型，不把当前模型别名写死为永久课程合同。
- 美式口音指令不能代替验收。AI 可以生成自然英语，但“教材文字完全正确、归属角色正确、发音地道且适合教学”仍需逐条检查；有问题的单条重新生成，整单元全部通过后才发布。
- 面向家长和孩子提供年龄适当、清楚但不打扰学习的说明，例如在课程信息中注明“英文语音由 AI 生成并经课程审核”。OpenAI 官方文档要求最终用户清楚知道听到的是 AI 生成语音而非真人。[OpenAI Text to speech](https://developers.openai.com/api/docs/guides/text-to-speech#quickstart)
- 产品面向六至八岁儿童，需要采用适龄披露并避免把儿童个人数据发送给生成服务。拟议的离线生产流程只处理 catalog 中的课程文本，不处理孩子声音、姓名或互动数据；若未来改为面向儿童实时调用，必须重新评估未成年人保护、隐私和零数据保留要求。[OpenAI Under 18 API Guidance](https://developers.openai.com/api/docs/guides/safety-checks/under-18-api-guidance)
- 自定义克隆某位真人老师的声纹是另一件事：官方能力只向符合资格的客户开放，并要求声纹所有者的同意录音和匹配的样本录音。当前方案不需要克隆任何真人，可直接选择内置语音。[OpenAI custom voices](https://developers.openai.com/api/docs/guides/text-to-speech#custom-voices)
- OpenAI 生成能力不自动解决教材文字、角色、美术或教材配套音频的产品授权；这些权利边界仍分别管理。

## 当前工作区能力

本次核验时，当前 Codex 工作区没有可直接调用的音频生成工具，也没有配置 `OPENAI_API_KEY`，因此现在不能在不新增凭据的情况下真实生成并交付试听文件。若课程确认采用此路线，应由项目安全配置一个有额度限制、仅供离线制作的 OpenAI API 项目密钥；密钥不得写入仓库或粘贴进课程 catalog。

实际生产前先生成一个极小试听包：Lesson 1 七句对话、`handbag` 词音和一条儿童提示，使用两至三种候选内置语音及统一美式英语指令。试听只用于选择角色和校准节奏，不进入正式发布；选定后再生成完整教学单元。
