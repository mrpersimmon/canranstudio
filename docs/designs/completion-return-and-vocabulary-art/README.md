# 每关返回路线与词汇图片修复

2026-09-06 · 用户反馈驱动。沿用 Duolingo 作为首要课程与交互参考，迪士尼手绘动画作为 imagegen 插画方向。用户此次明确要求每关结束后退出到路线，由学习者主动选择后续关卡。

## 用户看到的问题

1. “换个地方问问”的西装呈现写实布料和无头模特，学校是细节密集的塔楼建筑，与同屏老师猫的手绘风格不一致。原图保存在 `qa/user-vocabulary-before.png`。
2. 完成第六关后，完成页底部主操作为“下一关”，点击会直接进入下一关。原图与当前浏览器的复现分别保存在 `qa/user-completion-before.png`、`qa/completion-before-native.png` 和 `qa/completion-before.json`。

## 原因、漏检与防护

| 问题 | 原因 | 旧检查为什么没拦住 | 本次修复与持续防护 |
| --- | --- | --- | --- |
| 西装和学校画风不一致 | catalog 沿用了 Lesson 3–4 的旧 AVIF 素材，素材迁入新主题时没有逐张进行同屏风格验收 | 能加载、透明背景和图片可见性，只验证技术可用性；上一轮雨伞素材验收不能覆盖这两张旧图 | 通过 imagegen 重新绘制完整西装、简洁学校；保留原始生成稿、透明母版和提示词；96px 对照老师猫，再看实际题目；已审图像的文件指纹和 catalog 绑定进入检查，替换后必须重新验收 |
| 完成一关后直接跨关 | 完成页根据未完成节点渲染 `continue-course`；运行时接收后直接 `startNode` | 浏览器脚本点击了顶部“休息一下”的 `map` 操作，避开了用户实际会点击的底部主操作 | 完成页统一“回到路线”；移除直接跨关事件，选关只能从地图启动；所有 11 关、重练和今日复习均点击真实底部主按钮，检查回到地图、无新音频、没有额外进度写入 |

先在旧实现运行回归用例，两次均复现：底部按钮是 `continue-course`，旧事件使状态由完成页变为活动页，证据见 `qa/completion-red.txt`。修复后同一检查通过。

另检查了“出口掉出屏幕”和“恢复记录自动跳关”两种可能：本次实际 1055×1058 浏览器中，底部主按钮位于 y=985–1041，仍在视口内；未把用户裁切截图当作布局故障证据。恢复后的初始状态为地图。防护另要求完成页主按钮在短屏中可见，并故意移出屏幕确认能被拦截。

## 最终交互约定

关内继续 → 本关完成并保存 → 简短完成页 → **回到路线** → 路线停留 → 主动点击关卡、打开介绍并开始。

这个边界同样适用于主线复习节点、已完成关卡重练和今日复习。回到路线不会启动音频，不会将下一关记录为开始或完成。结算、地图进度和重新打开后的保存记录必须一致。

## 本次素材

- 西装：简洁轮廓、完整上衣与配套长裤，去掉模特和写实布料质感。初稿在实际深色页面偏暗，被目检拦下后再次用 imagegen 调整为更明亮的蓝色；中间版本见 `qa/native-vocabulary-heard-intermediate.png`。
- 学校：低层砖墙、教室窗户、校铃、书本标识，去掉城堡式塔楼和繁复金色装饰。
- 两张素材均由内置 imagegen 生成。原稿含烘焙棋盘格，之后只做已获授权的透明背景整理；完整保留原始结果，没有用代码重绘图像。
- 素材、提示词、原始稿与文件指纹见 `poc/learning-path/assets/vocabulary-v2/manifest.json`。`qa/vocabulary-art-contact.png` 保存 160px/96px 与老师猫的同屏对照。
- 本次对两张被指出的图片完成美术整改。旧目录仍有其他历史素材；文件加载通过不代表它们全部通过相同的美术验收，不把本次结论扩大到所有插画。
