# 结算界面重构 · 2026-09-09

本次依据用户提供的 [Duolingo 结算截图](../../references/duolingo/2026-09-09/settlement/user-reference.jpg)，统一主线、重练、今日复习、输入挑战和跳级成功/失败结果。课程题目、音频、跳级抽题与五次错误规则不变。

## 画面与操作

- 使用共同深色画布 `#141f23`，收起结算页的答题顶栏，保留课内真实进度条。
- 庆祝猫在中央完整展示，灰猫与黄围巾的身份保持一致；跳级失败使用原有温和招手姿态。素材、imagegen 提示词与透明验收在 [art](art/cat-celebrate-generation.md)。
- Lesson 标签、简短标题与一句鼓励形成清晰层级；三张表现卡以黄色、青色、绿色区分。
- 底部只有一个主要操作“回到路线”。输入挑战可选择“再挑战一次”，仍先确认重置；跳级失败可选择“再试一次”。
- 角色只在结果进入时做短暂位移动效；减少动态效果设置关闭该动画。保留按钮键盘焦点，非交互标题不显示无意义焦点边框。

## 数字的来源

| 场景 | 第一张卡 | 第二张卡 | 第三张卡 |
| --- | --- | --- | --- |
| 普通关卡 / 重练 / 今日复习 | 界面显示“完成题目”；计数沿用本次完成单元，故事每个实际完成的段落算一个 | 当前练习最佳独立连对；没有判分题时显示真实 ended 的词句数 | 本次打开练习到完成的前台用时 |
| 输入挑战 | 本次完成题目 | 本次最佳独立连对 | 本次前台用时 |
| 跳级测试 | 本次测试答对题数 / 已答题数 | 从这次持久化答题记录计算最佳连对 | 五次机会减去本次已错题数 |
| 全册回顾 | 实际完成关卡 | 全册课程数 | 实际完成输入挑战 |

普通关卡与输入挑战的“本次”从点击开始/继续练习起算。刷新后仅统计恢复后新完成的内容，用时也重新开始，不把历史成绩拼进本次成绩。跳级结果基于完整的同一次测试，因此刷新恢复后仍包含此前已答题目；不显示无法准确恢复的前台用时。全册回顾明确属于历史总览。

计分只发生在保存成功的回调；重复点击、失败重试、页面重绘和停留在结算页均不增加数字。错误或借助提示完成不能延长独立连对。真实音频 ended 才增加听读记录，重听同一个引用不重复统计。用时在切到后台时暂停，在完成时冻结，不奖励越快越好，也不伪造经验值。

## 原因与复发防护

| 问题 | 原因 / 旧检查遗漏 | 修复 / 防护 |
| --- | --- | --- |
| 不同结算缺乏统一层级，显示历史聚合信息 | renderer 分支各自拼接，成绩直接来自累计 record；旧检查只要求返回按钮与满进度条 | 共用结算组件与本次统计；检查三卡结构、运行时数值、标题区域及返回边界 |
| 标题出现额外描边 | 程序聚焦 H1 后浏览器默认焦点绘制；旧自动检查不判断参考图的视觉层级 | 仅移除结算非交互 H1 的描边，继续保留按钮 focus-visible；同尺寸截图复核 |
| 底部按钮继承旧最大宽度 | 公共按钮旧限制令新版宽按钮没有铺满操作区；可点击检查不能判定设计宽度 | 结算按钮局部取消 max-width，限制在内容最大宽度内；320px、手机和桌面目视检查 |
| 后台计时事件令答案框失去焦点 | 首版将只更新时钟的事件也交给全页 render；单独的运行时计时测试无法检查 DOM 和光标 | 已用真实控制器复现。计时事件只更新内部状态，不重绘；输入框节点、连接状态、焦点与光标须原样保持，并作为浏览器证明必需项 |
| 全矩阵最后的进度条故障注入报空对象 | 旧脚本先完成关卡再改进度条；本次结算移除答题栏后，该步骤不再位于正确页面。40,960 个页面检查无违规，但四个尺寸都在最后的检查自检失败，因此不能判为通过 | 同一负向注入移至实际答题页，并先断言活动状态和进度条存在；结束后恢复原属性。该检查提前到全课程遍历前执行，避免跑完整套才暴露错误前提；完整矩阵按新指纹重跑，失败记录保留在 evidence/guard-state-failure.json |
| 未来可能把历史总量填回结算 / 恢复答题顶栏 | 样式快照本身不能验证数值来源 | 浏览器主动注入 `999` 历史总数和答题顶栏，两种错误必须被拦截；发布证明要求这些负向对照 |

`learning-settlement.test.js` 覆盖本次统计、前台计时、冻结、重复点击、续练、提示、保存失败和重试。`learning-session.test.js` 继续遍历全部关卡并检查关内从零到完成，结算改为三卡而非进度条。浏览器全量矩阵保留所有原有对比度、图片、边缘、按钮遮挡、滚动条、跳级与故障注入检查。
