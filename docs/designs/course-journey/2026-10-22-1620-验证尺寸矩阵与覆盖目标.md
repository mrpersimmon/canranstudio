# 验证尺寸矩阵与 95% 覆盖目标

2026-10-22 · 矩阵版本 2026-10-22.1 · 适用 codex/fronted-opt-version 的学生旅程首页、地图入口和课程目录。

**尺寸清单已固化并接入检查；真实访问覆盖率尚未测得。** 用户已确认没有本站尺寸统计，先固化矩阵与覆盖目标。95% 是需要真实数据和执行证据核实的目标，不是对这份尺寸清单的市场覆盖承诺。

## 1. 唯一尺寸来源

机器可读清单为 [journey-viewports.json](../../../tests/support/journey-viewports.json)，读取与去重由 [journey-viewports.js](../../../tests/support/journey-viewports.js)负责。测试扩充或调整尺寸时先改该文件，再同步本文；不在多个几何用例中各自维护一份列表。

- 去重后 **63 个宽高组合**，单位为 CSS 像素。
- 完整地图几何档 **59 个组合**；紧凑目录另有 **4 个高度组合**。
- 日常几何档 **13 个代表组合**；它只缩减地图批量几何检查，关键交互、同宽变高、旋转及目录边界仍保留专项，不能用日常档代替完整矩阵结论。
- 布局范围含手机、平板双方向、电脑、断点两侧、长短屏和分屏样本。设备标签用于组织检查，不作为网页判断设备类别的依据。
- 浏览器模拟宽高不等于真实软键盘、刘海安全区、DPR／系统缩放或实体微信验收。

测试宽度指浏览器布局视口；地图还需扣除侧栏、标题、学习区等占位。面板的物理像素、英寸或某个设备名称不能替代该尺寸。采集方案会同时记录布局视口和视觉视口。

## 3. 维度以外的场景要求

| 场景 | 当前检查方式与边界 |
| --- | --- |
| 零星／部分星／满星 | 首段专项使用隔离的 0／2／5 星读取响应样本，在 59 个地图尺寸测归属与完整金章范围；不写成绩，不代替真实授星。其他段的各星级仍须按实际改动范围选择现有专项和目视。 |
| 普通／当前／焦点 | 完整课名、标记不压字、当前状态唯一、焦点可见，选择不改成绩。不能仅验默认状态。 |
| 人物／平台／信息 | 所有已实现地图分别检查人物可见边界、完整字框、比例与平台；星章按可见地标中心及脚下间距检查，课名单独避让。 |
| 旋转／同宽变高 | 保留专门的顺序操作，等待图片源与最终布局稳定；不只打开各个孤立尺寸。 |
| 搜索与可见高度 | 390×500／519／520／521 覆盖紧凑模式两侧，结果容器大于 100px，进入和定位操作可用。它们模拟可用高度，真实软键盘另验。 |
| 点击／键盘／滚动 | 保留选择、返回、短屏逐课可达和地图内部不滚动等真实操作；触摸取消与动效继续由原专项负责。 |
| 图片失败／恢复 | 明确恢复到预定交互视口后拦截实际图片请求，再验证搜索和重试。不能假设矩阵最后一项一定是桌面。 |
| 浏览器和其他环境 | 自动几何至少 Chromium、WebKit；实体 iOS／Android／微信、DPR、页面缩放、平板分屏与安全区单列执行结果。未运行的项目保持待验。 |

各项按实际影响选择，不能把“59 尺寸 × 星级 × 两引擎”的算术结果称为同等数量的独立业务场景，也不能据此推断真实访问覆盖率。

## 4. 运行入口

在仓库根目录执行：

```powershell
npm run check:journey:viewports
$env:LOGIN_TEST_PORT='4198'
$env:AWARD_TEST_BASE='/'
$env:JOURNEY_REVIEW_BROWSER='chromium'
$env:JOURNEY_VIEWPORT_TIER='full'
npm run test:journey:layout
```

WebKit 复验时将浏览器设为 `webkit`；本轮使用 `AWARD_TEST_BASE=/lesson/` 验证子路径。日常几何档将 `JOURNEY_VIEWPORT_TIER` 设为 `smoke`。未设置时默认 full；未知档名直接报错，不能静默降为少量尺寸。

`check:journey:viewports` 只检查清单结构、引用并打印数量和覆盖状态，**不执行浏览器检查**。`test:journey:layout` 当前执行带 `@journey-layout` 标记的 11 个场景（第三段时为 9 项，本轮新增两段）。清单或读取器变动已纳入提交检查选择逻辑，会触发账号浏览器检查，成功记录的输入指纹也包含这些文件。

## 5. 95% 的定义与数据闭环

目标：最近 30 天，本站学生首页有效访问上下文中，具有对应尺寸、环境及必要交互验证证据的比例不低于 95%。手机、平板和电脑分别报告，不能用总体比例掩盖某一端缺口。

校验命令当前输出包含：

```json
{
  "coverageTarget": 95,
  "measuredTrafficCoverage": null,
  "coverageStatus": "pending-first-party-viewport-data"
}
```

分母包含未识别和未覆盖的有效上报上下文。缺数据、未测试、失败或过期证据不能计入分子；“落在这个宽度区间”不是验证通过的证据。基于规则区间推算的比例若有需要，单独称为估算覆盖率。

[网站访问尺寸采集方案](2026-10-22-1620-网站访问尺寸采集方案.md)定义采集、去重、聚合、保留期限和按高频环境补测的流程。后续已完成[本地实现](2026-10-22-1930-尺寸采集与第三段入口实施记录.md)，生产仍未开启；本节矩阵本身不读取生产数据，不自动更新为 95%。

## 6. 选样依据

候选样本参考 [Statcounter 中国手机统计](https://gs.statcounter.com/screen-resolution-stats/mobile/china)、[平板统计](https://gs.statcounter.com/screen-resolution-stats/tablet/china)、[电脑统计](https://gs.statcounter.com/screen-resolution-stats/desktop/china)，以及 [Apple 逻辑尺寸说明](https://developer.apple.com/design/human-interface-guidelines/layout)。本次手机／电脑页面返回 2026 年 9 月，平板页面返回 2026 年 8 月；这些数据只作选样依据，不拼接为一个覆盖率。

Statcounter 是其网站网络中的访问样本，且电脑分类合并笔记本和台式机，不能替代本站的浏览器窗口分布。[统计方法说明](https://gs.statcounter.com/faq)

断点、495×1188、390×1024 等压力尺寸来自本项目布局风险，而非对应某个具体在售机型。CSS 像素与实际窗口口径见 [MDN innerWidth](https://developer.mozilla.org/en-US/docs/Web/API/Window/innerWidth)。

## 7. 矩阵初次固化的结果与修复

完整矩阵在 Chromium 根路径和 WebKit 子路径各通过 8 项相关场景，另有 8 项模型／完成提示单元检查及 11 项检查流程用例通过。没有将重复复验累计成新的功能数量。

扩大矩阵后的首轮出现 4 个失败，分别处理如下：

| 类型 | 发现与根因 | 处理 |
| --- | --- | --- |
| 产品边界 | 390×520 搜索只有一条结果时，60vh 面板仅 312px 高，标题／搜索／筛选挤压后结果区仅 41px。 | 短结果面板改为 clamp(400px,60dvh,560px)，仍受实际可见高度上限约束；500／519／520／521 四档通过。 |
| 产品边界 | 1024×768 窄桌面横构图，9–10 课名与前景 7–8 人物的保守可见包围范围相交约 399 平方 CSS 像素。 | 横构图信息组中心从画布 53% 调至 55%，人物、脚底和素材不动；两段全矩阵人物／文字边界通过。 |
| 测试上下文 | 几何清单结束在手机布局，后续缺图恢复仍寻找桌面搜索框，导致超时。 | 恢复专项显式切回 1440×1024，再执行桌面搜索；没有延长超时来掩盖问题。 |
| 测量精度 | 40px 规则得到 40.000012px 浮点结果。 | 几何算术规范到千分之一 CSS 像素后再比较，不增加可见像素的容差。 |

宽屏问题最终定位在 **1024×768 横构图**；排查时检查过 1024×1366 竖构图，但未把它当成已复现的遮挡证据。此处按最终证据修正早期排查描述。
