# 网站访问尺寸采集方案

2026-10-22 · 当前状态：已按用户后续要求完成本地实现；生产及常规本机预览默认关闭，尚无真实访问统计。本文保留原方案结构，实际配置、验证及与建议的差异见[实施记录](2026-10-22-1930-尺寸采集与第三段入口实施记录.md)。

目标：知道访问当前网站的人实际给网页多大空间，并用真实高频环境补充[统一验证矩阵](2026-10-22-1620-验证尺寸矩阵与覆盖目标.md)。用户已确认目前没有本站尺寸统计，所以现阶段不能把 63 个固定尺寸的通过率称作真实访问覆盖率。

## 1. 推荐方案

采用同站点轻量采集、独立聚合存储、管理端汇总，不接入第三方追踪服务。全站尺寸分布与学生首页的验证覆盖率分开报告：前者覆盖接入采集的正常页面，后者只计算当前已有验证证据的页面范围。

```mermaid
flowchart LR
  A[页面稳定后的实际可用尺寸] --> B[前端去重与限频]
  B --> C[同站点接收接口]
  C --> D[校验与短期请求去重]
  D --> E[每日尺寸聚合]
  E --> F[最近30天高频环境]
  F --> G[补充真实尺寸并执行验证]
  G --> H[按证据计算覆盖率]
```

一期按页面类别记录 login／home／album／lesson／admin／other，避免储存完整地址、课号、查询参数和来源链接。接入尚未覆盖的页面必须单列，不以“全站模块已上线”推断所有页面都收到数据。服务器根据已有有效登录态给出 student／staff／anonymous 的粗分组，统计行不保留账号身份；客户端标签不得用于授予权限。

## 2. 采什么，分别用来回答什么

| 字段 | 取得方式／粒度 | 用途 |
| --- | --- | --- |
| layoutWidth、layoutHeight | CSS 像素，记录布局视口整数尺寸；以 window.innerWidth／innerHeight 为主。另记录 clientWidth，以区分滚动条占位。 | 重现真正影响布局的窗口尺寸，不能以面板的 2K／4K 分辨率替代。 |
| visualWidth、visualHeight | visualViewport 的可见宽高，整数；不支持时为 null，并记录能力缺失。 | 判断软键盘、浏览器工具栏和可见区域收缩。 |
| visualScale | visualViewport.scale，有限精度 | 区分双指缩放后的可见区域，不当作桌面浏览器缩放百分比。 |
| dprBucket | 1／1.25／1.5／2／3／4／other 等有限档 | 检查高密度图像和缩放环境；不能据此推算用户用了“150% 页面缩放”。 |
| orientation | 根据布局视口宽高归为 portrait／landscape | 表达当前布局方向；分屏窗口的方向不一定等于机身朝向。 |
| browserFamily、engineHint、platformGroup | 服务端把请求已有的浏览器信息归一为有限类别；无法可靠判定就保留 unknown。 | 分别检查 Chromium／WebKit／微信等环境，平板伪装桌面时不强行分类。 |
| pageKind、audience、buildVersion | 页面类型枚举、服务端粗身份分组、部署构建标识 | 避免把后台尺寸、旧版本证据或其他页面混入首页覆盖率。 |
| reason | initial／layout-change／visual-change | 分开看首次访问与旋转、分屏、可见区域变化。 |
| eventId | 每次报告随机生成的 UUID，重试复用；只供接收去重 | 防止重发重复计数，不作跨页面、跨设备识别。 |

布局视口和视觉视口并不相同，软键盘可能只改变后者。[MDN VisualViewport](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport)

DPR 受屏幕像素密度及页面缩放影响，双指缩放又有不同表现；不能只用一个 DPR 值反推缩放百分比。[MDN devicePixelRatio](https://developer.mozilla.org/en-US/docs/Web/API/Window/devicePixelRatio)

默认不采集屏幕物理像素、精确机型、地理位置、姓名、学号、班级、成绩、页面正文、输入内容、完整 URL、原始 User-Agent 或持久访客 ID。宽高只作聚合分析，不尝试拼成设备指纹。请求本身仍经过既有登录 Cookie 和服务器访问日志，不能宣称整个请求“绝对匿名”；既有日志的权限及保留策略应独立核对。

## 3. 何时报告与如何去重

1. 页面实际可见、公共字体／主要界面准备好后，等待尺寸稳定约 750ms，发送一次 initial。后台标签页不提前记作已展示。
2. 旋转、分屏或窗口调整后，同样等待稳定再测。仅当布局宽高发生实质变化，或跨越实际布局断点时，发送 layout-change。
3. 视觉视口变化独立报告 visual-change，并要求稳定；仅 visualHeight 小幅变化不反复增加首次访问数量。只标记“可见区域收缩”，不凭高度差就断言一定是软键盘。
4. 同一页面激活周期内，用内存 Set 对“页面类别＋布局尺寸＋归一后的视觉状态”去重；旋转回来不重复计相同上下文。BFCache 返回可视为新的激活周期，但要明确记录。
5. 每页最多记录 10 个变化上下文；超过上限只增加 capped 计数，不持续发送。该上限是一期控制值，实际使用后再调整。
6. 不持续监听滚动上报，不记录点击轨迹，不写永久访客 Cookie。刷新是一次新页面访问，因此指标不是独立设备数或独立人数。

第一期对符合范围的可见访问全部尝试报告，避免先随机抽样又把结果解释成全量。失败或被浏览器拦截仍可能丢失，管理报表须标明“有效上报样本”的口径，不能把未收到的数据当作不存在。

## 4. 传输与本站接入

已实现同源 POST `<BASE>api/client-viewports`，兼容根路径和 `/lesson/`；BASE 归一方式见[server/app.js](../../../server/app.js)。管理员汇总为 GET `<BASE>api/admin/viewport-metrics?days=7|30|90`，普通教师和学生拒绝访问。

- 正常报告使用 keepalive fetch；页面进入 hidden 时用 sendBeacon 补发尚未确认的单个事件，每次请求最多 4KB，不依赖 unload／beforeunload。
- JSON Blob 的 Content-Type 与现有服务器 JSON／Origin 校验保持一致；增加独立的小体积限制，不能改变学习成果接口现有的请求上限。
- sendBeacon 返回 true 只表示浏览器接受排队，不代表数据库写入成功；一般请求以 204 确认接收，重试沿用 eventId，最多一次，统计失败不提示学生、不阻塞进课。
- 接收端严格校验字段、枚举、数值范围和同源请求。登录态只用于服务端粗分组及防滥用，不写入尺寸统计表；匿名登录页也可报告，但单独分类。
- 使用独立的限频器，不复用会锁定账号的登录失败计数。限制每个短期来源的频率，来源标识仅在内存短期保留。
- 开发、本机预览、自动化测试、教师班级预览默认不计入生产统计；生产开关默认关闭，启用环境与构建版本可追溯。

sendBeacon 的排队语义、可用载荷及页面隐藏时机参考 [MDN sendBeacon](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/sendBeacon)。采集失败不得影响学习体验属于本产品约束。

独立[客户端模块](../../../server/public/viewport-metrics.js)已由账号首页／登录入口、纪念册入口和授权课程通用加载层接入，管理页沿用账号入口。拒绝访问提示页、旧 `/exercise/` 静态站及教师班级预览不在范围内，不能声称全站所有 HTML 都已采集。初始化幂等，并提供停止后的监听、定时器和请求清理。

## 5. 存储、权限与保留期限

已使用独立 `viewport-metrics.sqlite`，尺寸统计与成绩、收藏账本分开，默认停用时不创建统计库。

| 数据 | 保存方式 | 建议期限 |
| --- | --- | --- |
| 报告载荷 | 校验并聚合后丢弃，不保存逐条原始事件 | 不落盘 |
| 请求去重 | 仅 eventId 的摘要与过期时间，不含账号、IP、尺寸明细 | 有效期 24 小时；运行中每分钟及接收／查询时清理，停服期间不执行物理清理 |
| 每日聚合 | 日期、页面类别、粗身份分组、构建、归一浏览器、布局／视觉尺寸、DPR 档、原因、计数 | 90 天滚动 |
| 质量指标 | received／invalid／duplicate／limited／capped 日计数；数据库异常的 dropped 只在内存累计 | 日计数 90 天；dropped 仅本次服务启动以来 |
| 覆盖率报告 | 统计窗口、样本量、矩阵版本、验证证据版本、比例与未覆盖列表 | 随验收记录留存 |

每日按 Asia/Shanghai 自然日聚合。用于自动复验的尺寸保留整数；管理界面可以分桶，但不能跨 360／600／1024 等实际断点合并，也不能把分桶展示误当该区间全部已验证。

首期仅已有最高管理权限可查看／导出汇总，不自动开放新教师权限。少量样本的细分显示可合并为“其他”，总计必须保留；未识别环境不能从覆盖率分母中静默剔除。

当前直接作短事务聚合写入，数据库等待上限 5ms，异常丢弃统计；独立限制为单短期来源 120 次／分钟、全局 1200 次／分钟、每日最多 5000 个不同聚合上下文。来源使用服务端验证的会话摘要与地址做进程随机密钥 HMAC，只留内存；限频计数有界缓冲后汇总，不复用登录失败冷却。期限与基数上限已验，生产写入压测尚未执行，不能把“独立数据库”当作性能影响为零的证明。

## 6. 怎样核实 95% 目标

**先定义范围，再计算。** 当前矩阵只验证学生旅程首页及目录，不能据此宣称纪念册、所有教学页面或全站交互已达到 95%。

核心口径建议为最近 30 天内，学生首页去重后的有效访问上下文。首次访问覆盖率、旋转／分屏上下文覆盖率、视觉收缩场景分别报告，避免用户拖动窗口产生的大量事件淹没普通访问。

```text
访问上下文覆盖率 =
有对应页面、尺寸及环境验证证据的上下文计数
÷ 全部有效上报上下文计数
```

- unknown、尚未验证、验证失败的上下文仍留在分母；未收到的访问不在样本中，须另外说明采集缺失与可能偏差。
- 总体、手机、平板和电脑分别报告，目标各自不低于 95%；样本不足时标记“参考／不足”，不通过加权掩盖某一端的缺口。
- 从频率最高的实际尺寸＋浏览器组合开始，累计选择至目标占比，生成“真实数据补充矩阵”，沿用同一套页面断言执行。
- **只有执行通过并保存证据后，才进入已验证分子。** “落在 320–2560 宽度范围内”“接近某个手机型号”或“同一个浏览器内核”都不能自动算通过。
- 若采用经过评估的尺寸等价区间，必须单列为估算覆盖率，保留区间定义及边界检查证据；不能与直接验证覆盖率混报。
- 每个报告写清统计起止日期、样本量、收集范围、过滤／丢失计数、未知比例、版本和证据日期。没有数据时返回 null／待统计，不显示 0% 或伪造 95%。

管理端建议展示：当前样本覆盖率、各类设备覆盖率、高频未覆盖尺寸、未知环境占比、采集质量，以及可下载的补充测试清单。高频但未覆盖的环境先补测；失败的环境进入问题清单，修复复验后再更新覆盖率。

## 7. 分阶段实施与验收

| 阶段 | 交付内容 | 完成条件 |
| --- | --- | --- |
| A · 采集基础 | 客户端模块、同源接口、独立聚合存储、默认关闭开关 | 字段最小化、去重、限频、期限、缺失计数、根／子路径与关闭行为通过。 |
| B · 汇总与复验 | 管理端统计和真实数据补充矩阵导出 | unknown 留在分母，测试失败不计已覆盖，无数据展示待统计。 |
| C · 生产观察 | 按用户授权部署启用，观察真实访问 | 首轮数据核验采集范围与偏差；完整 30 天后形成正式窗口报告。 |
| D · 持续校准 | 用高频未覆盖上下文更新固定及补充矩阵 | 保留版本、旧失败与复验，验证达标后才报告 95%。 |

必要验收包括：同尺寸不重复、旋转后再返回的去重、BFCache 激活、分屏、可见高度变化、离线／失败不影响学习、批量重发不重计、关闭开关完全停止上报、非法或过大载荷拒绝、匿名与学生访问分组、开发预览不混入生产、汇总中没有学生身份字段、管理员权限隔离及过期清理。

A 的本地采集与 B 的管理汇总、候选导出已经完成。候选清单不会自动转为验证证据，真实环境复验和 C／D 仍待后续部署与数据。设备样本量在界面明确显示；尚未建立统计置信度或最小样本量判定，不能把小样本结果当作稳定覆盖结论。开发、提交、推送和发布按用户要求分别执行。
