# 故障注入的动画时序修复

2026-09-06，在提交 `42a48f4` 的首次 GitHub Actions 发布检查中发现。正式站点尚未切换，防护网阻止了带失败检查的版本上线。

## 现象与复现

云端在 39 个状态后失败：`Negative control escaped: completion-button-offscreen`。实际完成页正常，失败发生在主动把完成按钮移出视口的负向测试。

使用仓库同一命令 `npm run test:browser`，在本机安装该锁定版本的 Chromium Headless Shell 后复现相同失败。保留 CI 的失败报告与本机复现，不将浏览器启动器缺失与产品/检查失败混为一谈。

## 原因

真实按钮的 `transform` 有 120ms 过渡。测试写入 `translateY(200vh)` 后立即测量，读取到动画起点，按钮此时仍在视口中。关闭动画的环境则会立即到达终点，因此先前在另一浏览器中的通过没有覆盖这个时序条件。

在同一个真实按钮上仅切换动效设置，结果为：

| 动效设置 | 过渡时间 | 原始 top | 写入后立即 top | 动画结束后 top | 视口高度 |
| --- | --- | --- | --- | --- | --- |
| 开启 | 0.12s | 499 | 499 | 1635 | 568 |
| 减少动态效果 | 0s | 499 | 1635 | 1635 | 568 |

这排除了目标元素错误或布局把按钮重新拉回原位的可能；终点位置在两种模式中一致。

## 修复与复发防护

- 注入后调用已有的渲染/有限动画等待，再执行同一可读性检测，不降低规则或删除负向对照。
- 先断言注入确已使按钮完全移出视口，再验证防护规则检出错误；将当时的坐标与视口高度写入故障证据。不能用“注入尚未生效”冒充规则没有问题。
- CI 明确使用 `reducedMotion: no-preference`，持续覆盖动画开启时的真实过渡，避免继承机器动效偏好。
- 修复后继续执行完整矩阵，另发现驱动把 `waitForFunction` 的超时选项放在了第二个参数（实际是页面函数参数）。原计划的 300 秒未生效，驱动在默认 30 秒中断；现按当前 Playwright 签名放到第三个参数。完成的状态数和八类负向对照仍必须全部通过，不能用等待结束代替通过结果。
- 检查其他故障注入：图片解码、颜色/主题和间距注入本来就有等待；这次缺口位于新增完成页注入函数。恢复完成页后仍需再次通过正向检查。

改动只影响检查代码。页面设计、题目、音频、素材及学习记录保持原样。完整浏览器检查和 GitHub Actions 必须重新通过后才允许激活本次发布；发布后另核对正式域名的内容和交互。
