# 播放声音时闪出准备提示

2026-09-13。用户原话：“在官网中，点击播放声音，屏幕会闪烁，出现正在准备...”。本轮修复播放过程中的瞬间布局变化，保留已确认的进入关卡前素材准备机制。

## 复现与原因

官网基线 `e6a266941e111e84f92737b6feac511f6bd31ed2`。在隔离的浏览器记录中恢复实际抽中的听音找图题，等待本关素材准备完成，再连续三次点击播放。官网与相同源码的本地发布预览均为 3/3 复现：每次起播插入“正在准备声音…”整条提示，再撤掉，390×844 下底部操作栏从 y=658 到 y=602 再返回，位移 56px。题目图片节点不变，没有重新进入“正在准备本关”页面。

最小命令：`node scripts/check-playback-stability.js`。修改前在真实控制器路径报错：`playback cannot insert a full-width preparation banner`。临时诊断原型及官网/本地观察放在忽略目录 `output/playwright/playback-flash-debug/`，不进入发布包。

按顺序验证三个假设：

1. 起播的 loading 状态无条件插入提示。预测：预热完成与重听也会插入。官网与本地均符合。
2. 原生 waiting 事件导致重复显示。预测：仅取消该事件向控制器的传递，问题应消失。单变量探针仍为 3/3、56px，排除它作为必要原因。
3. 播放时重建题目或重新进入关卡准备。预测：图片节点改变或出现 `.lp-preparation`。两者都未发生，排除本次图片题路径上的该原因。

直接原因是场景渲染器把正常、短暂的 `loading` 状态画成额外的底部通栏。运行时立即进入 loading 本身是必要的，可抑制重复请求；错误在于把这一瞬间的状态变化变成页面布局变化。故事重听还把原播放按钮替换为宽度不同的普通文字。

## 为什么旧检查通过

之前的完整浏览器检查在测量之前等待 `.lp-preparation` 消失且音频状态不再是 loading；真实音频检查等待最终 playing/ended，并验证慢起播时有提示。它们分别证明了稳定状态与播放事件，未证明点击到起播之间的布局连续。

本次初始按动画帧采样也可能漏掉两帧之间只有数毫秒的变化。因此回归在每次 DOM mutation 后立即记录位置、提示、滚动和图片节点身份，不能用最终截图或最终播放成功替代这项断言。

## 修复

- 取消起播时额外插入的底部准备通栏。错误提示及重试入口仍保留。
- 保持原播放按钮的内容占位；持续等待超过 300ms 才在同一按钮内显示“准备中…”，图标按钮使用局部省略点。300ms 只延后视觉提示，不延后播放请求，也不伪造 playing。
- 立即保留 loading 与重复点击保护，实际听完仍以原生 ended 为准。
- 等待计时按播放请求和句子序号区分；起播、失败、切换页面和离开页面清理旧状态。
- 同一渲染入口覆盖主线练习、挑战、复习和跳级；补查故事重听、听音配对、单词卡与课本单句。词卡沿用原提示位置，队列机制保持原有行为。

参考继续使用仓库的 [Duolingo 深色题型截图](../../references/duolingo/2026-09-06/lesson-dark/README.md) 中稳定的题目、选项和底部操作区域。截图不证明播放时序；300ms 阈值是本项目防止瞬间闪动的实现选择。

## 回归与验收边界

`scripts/check-playback-stability.js` 通过正式首页、安装器、Service Worker、控制器和原生播放器检查，新增到 `npm run test:loading`，并由既有 `npm run test:browser-media` 持续执行：

- 320×568、390×844、820×1180、1440×900 的听音找图，分别检查正常起播、150ms 与 1200ms 起播，共 12 例。
- 故事重听两例，课本单句和词卡各一例，共 16 例；未合成 playing/ended。延迟探针只延后调用浏览器原生 play。
- 瞬间通栏、题目/操作栏坐标与尺寸、图片节点、滚动均受检查；较短起播不得闪出等待提示。
- 较长等待有局部提示，不能提前显示播放中；重复点击、失败重试、离开页面的旧请求另行检查。
- 旧加载检查继续验证必需素材门槛、进度、断网、重试、解码窗口和后台准备。慢起播断言改查局部状态，没有删除该要求。

专项 16 例与两项直接相关单元检查已通过；真实媒体集成检查通过（42 段录音、4 种音效、7 组加载及播放回归）。本地起播样本为 16.4–20.8ms，后台准备期间 47.5ms。完整页面矩阵 41,456 状态无违规，72 次故障注入均被检出；163 项单元检查、51 项复习流程和存储恢复检查通过。当前源码指纹为 `204fd06a8aa86fde2cb75e245a327289698caaf1b621b66d8661ce0945a7a292`，见[验证摘要](playback-flash-validation.json)。发布与官网复查独立记录在 `output/playwright/playback-flash-release/publication.json`；不能将本地通过等同于已经上线。设备模拟是 Chromium 视口验证，不等于 iPhone/iPad 真机试听或儿童试做。
