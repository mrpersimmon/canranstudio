# 按关卡准备素材：实施方案

状态：设计决策已确认，产品实现已在本地完成；验证进展见 [实施记录](implementation-report.md)。依据用户对 Q1 的“按你推荐的来”和对 Q2、Q3 的“都按照推荐的来”整理。原始诊断和测量见 [现状记录](README.md) 与 [证据](evidence.json)。

## 已确认的体验

| 决定 | 结果 |
| --- | --- |
| 准备范围 | 进入前准备本关，学习时提前准备下一关 |
| 失败处理 | 必需素材失败先重试或返回；辅助素材失败允许降级 |
| 设备优先级 | 手机和平板优先，兼容电脑 |

正常情况下，图片、教学语音和反馈音效都提前准备。允许辅助素材失败时降级，不表示平时可以不准备音效。题图或教学语音没有准备好时，不显示一张需要等待素材才能作答的题目。

## 学生实际经历的流程

1. 点击开始或继续关卡，优先复用已经准备好的素材。
2. 需要等待时沿用准备页面，展示“正在准备本关”和真实进度；不向学生展示缓存、校验值或网络请求等实现信息。
3. 本关必需文件完成获取与校验，首个活动的图片可显示、教学语音可播放后，自动进入关卡。进入关卡不替代已有的“开始故事”或播放操作，也不凭预加载登记听过。
4. 学习期间提前准备下一步需要显示和播放的对象；文件下载范围保持本关完整覆盖。切题时先确认下一题必需图片可显示，避免先插入空白图片再补画。
5. 当前关卡的必要准备完成后，再以较低优先级准备下一关；当前播放、重听和切题优先。学生改选其他关卡时，取消不再需要的后台工作，保留已完成的有效缓存。

快速命中缓存时直接进入，避免为了展示进度而添加固定等待。准备页面不提前显示 100% 或声称已经就绪。

## 素材范围和播放器安排

- 从当前课程数据及实际活动引用提取素材，覆盖所有可能出现的答案选项、教学角色、物品图片、故事句子和反馈音效。不能继续只读取入口角色名单或固定预热 D01。
- 将下载就绪与展示、播放就绪区分开：完整准备本关文件；优先持有当前与下一步的解码图片及播放对象，避免在手机上同时保留全书或多关的解码对象。
- 复用真正预热过的播放对象，避免预热结束后另建一个完全没有准备的对象。普通语音在浏览器实际开始播放后才显示播放中的状态；如果仍出现等待，显示准确的准备状态并抑制重复触发。
- 音效播放失败不修改答案、分数或机会数，文字和颜色反馈始终保留。教学录音必须收到实际播放结束事件，才能更新相应学习证据。
- 复习、挑战和跳级沿用同一准备原则，以本次已经确定的实际题组为边界。准备过程不重新抽题、不改变跳级取题范围，不因为退出准备页面而登记完成。

## 网络慢、失败及恢复

- 有持续下载进度时继续等待；一段时间没有进展时显示简短的网络提示并提供重试、返回入口，避免无反馈地停在准备页。
- 必需素材失败：保留已准备内容，重试缺失或无效部分；未就绪时不进入依赖它的活动。返回路线不扣机会、不清除已有进度。
- 辅助素材失败：允许进入，使用完整的文字与颜色反馈；后台可重新尝试，但不反复弹出干扰学习的错误提示。
- 中断、刷新或重新进入时，恢复原来的关卡、题组和已保存作答，再检查其实际素材是否就绪。缓存内容必须与当前版本匹配。
- 本关准备完成后再断网，应能继续使用该关已准备的必要图片和录音。新版本或未准备关卡需要联网时明确展示准备状态。

## 验收要求

| 检查 | 必须记录或满足的结果 |
| --- | --- |
| 首次进入 | 空缓存也先完成本关准备；活动出现时必需题图已经可显示 |
| 同关连续学习 | 正常准备完成后，不再等到出题或点击播放时才向源站获取必需素材 |
| 语音起播 | 分别记录点击、请求、canplay、playing、ended；首次、重听、刷新后的播放单独统计 |
| 图片出现 | 观察活动切换时的实际图片状态和解码时序；不靠测试先等待图片加载完来掩盖补图 |
| 下一关准备 | 当前关卡操作和播放优先；后台下载不能造成明显新的停顿 |
| 失败分级 | 必需图片和教学语音失败阻止错误进入；辅助素材失败仍可正常答题和结算 |
| 恢复 | 重试复用有效缓存；刷新保留原题组、作答和机会数 |
| 离线 | 准备后实际断网验证本关完整流程，不能仅检查 navigator.onLine |
| 原有行为 | 最后一题先显示对错再手动进入结算，听音证据仍依赖真实 ended |
| 设备 | 优先检查手机、平板尺寸和浏览器行为，再覆盖桌面；自动化模拟与真机结果分别列出 |

起播测量要公开样本、环境、最慢值和失败次数。不能再用“最终能播完”代替“播放及时”，也不能把 Chromium 的移动视口当作真实 iPhone 或 iPad 验收。

## 实施顺序

1. 建立覆盖实际关卡和题组的素材收集与就绪检查，补上手提包、后续语音等漏项的回归场景。
2. 在进入活动前接入准备状态、取消、重试和按重要性降级的流程。
3. 接入播放对象复用、准确的等待状态、下一步预热及下一关后台准备。
4. 使用首次加载与重复使用的真实浏览器测量，对照现有 2.79 秒补图和 1.16 秒首次起播的基线，再验证布局、进度恢复和末题反馈。

本方案没有选择全书一次下载、CDN 迁移或整体播放器重写。首页启动包体积优化也不作为本轮解决关内补图、延迟起播的前置条件。
