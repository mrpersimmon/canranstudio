# 按关卡准备素材：实施与验证

产品代码已在 `codex/placement-feedback-repair` 实现。准备流程、真实媒体、页面回归和完整单元测试均通过。用户于 2026-09-13 确认提交、推送及官网发布。下文保留实施阶段的验证；本次发布结果、提交号、完整矩阵和线上复核独立记录在 `output/playwright/loading-release/publication.json`。本地预览地址为 `http://127.0.0.1:42879/`。

## 已实现的行为

- 开始关卡前，从本关实际活动引用收集题图、角色和教学录音，通过现有 Service Worker 按当前版本的大小和 SHA-256 校验完整文件。当前活动的图片解码与播放器就绪也通过后，才显示活动。
- 文件准备覆盖整关；解码对象保留当前和下一步，离开后释放。下一关使用单请求、低优先级的后台下载，播放或离开时取消剩余任务。
- 普通关卡、挑战、跳级、到期复习和书本录音使用同一模块。跳级使用已保存的题目 ID；复习直接使用运行时已经选出的队列，准备过程不重新抽题。
- 播放复用已预热的对象。收到实际 `playing` 后才显示播放状态；等待时显示“正在准备声音…”并禁用重复播放。只有实际 `ended` 能获得听音证据。
- 8 秒没有文件完成进度时显示慢网提示，允许继续等候、重试或返回。必需素材失败阻止进入，重试复用已校验的缓存。辅助素材正常准备，单项 3 秒超时或失败时允许降级，文字与颜色反馈保留。
- 不用固定延时展示准备动画；也不在播放器还没准备好时显示 100%。准备时间不计入学习用时，准备、返回和刷新不扣机会或登记通关。
- 准备完成后实际断网，仍可完成本关；最后的答题反馈保留到学生手动继续，才进入结算。

实现集中在 `core/learning-media.js`；页面负责准备状态、取消和操作调度，运行时负责实际播放状态与学习记录。课程内容、题目答案和既有跳级取题规则没有在这个模块中重新定义。

## TDD 验收边界

沿用已确认方案中的页面操作、可见状态、原生媒体事件、真实 HTTP、离线与刷新行为，作为本轮已确认的测试边界。对应用户对 Q1 的“按你推荐的来”、对 Q2/Q3 的“都按照推荐的来”，以及本轮 `$tdd` 实施请求。新增测试没有直接调用素材模块的内部方法。

下列失败在实现相应行为前实际运行并出现，再逐项变绿：

| 场景 | 修复前的红灯 |
| --- | --- |
| 延迟手提包请求 | 故事先出现，没有准备页 |
| 准备后断网进入第二句 | 第二句没有原生 `ended` |
| 整关离线答题 | 正确音效没有准备，无法播完 |
| 恢复跳级题组 | 题图未就绪就显示题目 |
| 复用实际播放器 | 下一句的 `canplay` 晚于点击 |
| 延迟实际起播 | 没有等待文案，却已经显示暂停按钮 |
| 返回路线 | 旧准备任务继续请求后续句子 |
| 无进展 | 没有慢网提示和重试入口 |
| 挑战与完整复习队列 | 没有准备挑战；较后的复习录音未提前请求 |
| 必需文件失败 | 失败提示被其他任务的进度回调覆盖 |
| 解码对象释放 | 离开关卡后仍保留并预热 7 个播放器 |
| 下一关后台准备 | 当前关空闲时，没有准备下一关 |
| 准备时间 | 人为推进准备时钟 2 分钟后，结算错误计入这段时间 |
| 重复播放 | 等待时仍可重复触发播放 |
| 书本入口 | 打开课文后没有准备后续录音 |
| 进度准确性 | 必需播放器未就绪时已经显示 100% |
| 辅助请求一直不返回 | 音效阻塞进入题目 |
| 解码窗口 | 为较后活动的图片解码阻塞当前活动；随后切换时又没有等待该图就绪 |

测试本身也修正了三个旧假设：播放命令不等于原生播放；重听次数应数 `ended` 事件，不能数新建播放器；预热对象的绝对地址与课程中的相对地址需要规范化后比较。另一个复习测试最初只看到了短暂的准备页，已增加“较后录音的真实请求已经发生且仍被阻塞”的条件，避免虚假的通过。

## 验证记录

- `npm run build:course`：重新生成并校验课程包，入口加载新的素材模块。
- `npm run test:loading`：6 组真实浏览器专项回归通过。包含 HTTP 延迟/失败、解码等待、整关实际断网、重试与取消、原生起播、对象释放、跳级恢复、复习和书本入口。
- `npm run test:browser-media`：42 段跨课次录音实际播完，验证媒体校验头、Range、离线重听与旧进度恢复；四类原生反馈音效和末题反馈恢复也通过。
- 五种窗口尺寸的听音找图几何回归通过；多种随机序列的选项身份、位置、滚动与听音证据保留检查通过。
- 准备页在 390×844、820×1180、1440×900 下没有横向溢出，axe WCAG A/AA 检查没有违规；已查看手机准备页与首个活动的截图。
- 完整单元测试：最终复核 163 项通过（534.6 秒）；随后准备页的焦点保留微调通过页面控制器、课程包和安装器相关复核，加载专项也重新运行。

新的题图就绪测试在 DOM 插入时读取 `complete` 与 `naturalWidth`，没有先替产品等待 `decode()`。布局测试仍允许等待布局稳定；它不代替加载时序测试。

机器结果在 `test-results/learning-media.json`、`native-media-proof.json`、`feedback-audio-native.json`、`loading-visuals.json`。截图在 `output/playwright/loading-implementation/`。这些运行产物被仓库忽略，结论与可复现命令保留在此文档。

## 测量和验收边界

本轮使用 macOS 上 Chromium 153、真实浏览器音频事件和本地 HTTP，使用手机、平板、电脑视口。没有模拟 `ended` 来通过新的加载专项测试；延迟和失败只注入网络、解码或原生播放边界。

官网原来的 2.791 秒补图、1.162 秒首次起播来自自然公网测量。本地结果没有公网往返，不能据此宣称官网已经提升了某个倍数。起播指浏览器 `playing`，不等于声卡首个非静音采样。

实施阶段的局部验收不代替完整全书、全视口视觉发布矩阵。正式发布须通过与当前源码指纹一致的完整矩阵和发布构建，实际结果与官网复核另记。尚未进行真实 iPhone/iPad、Safari 和课堂设备验收。

2026-09-13 发布预检发现，旧短题库检查在运行时已经选定题目、页面仍显示准备状态时，就开始断言题型、机会数与进度。已先运行得到失败，再让检查等待实际准备页退出；原有断言全部保留。四尺寸 12 个场景、44 个状态重新通过，覆盖短题库、空题库、末题反馈、刷新恢复和剩余机会图标。旧进度、恢复与复习浏览器检查 51 项也通过。该测试适配不修改产品行为。
