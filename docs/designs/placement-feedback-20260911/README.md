- 修复前：变化随机序列的单元回归失败；三个尺寸 × 三个随机种子的浏览器用例 9/9 失败。
- 单变量探针：从 `git show HEAD:core/learning-path-runtime.js` 读取原实现，只停止判分反馈时的重复初始化，图片顺序与听音记录即保持。[探针](evidence/shuffle-probe.json)

## 2. 最后一题跳过正确/错误反馈

原 `grade()` 在最后答对或第五次答错时立即改变测试状态，`loadPlacement()` 随即选择结算页；末题只播放结果音效。旧测试把这种直接跳转当作期望，因而通过。主线与挑战已有反馈/继续阶段，这个遗漏在跳级专用分支。

现在末题先持久化判分，并进入 `feedbackPending` 阶段：

1. 显示这道题的正确/错误反馈，播放对应音效。
2. 停留等待“继续”；连点检查不能重复判分。第五次错误立即停止继续答题，但保留错误反馈。
3. 刷新或退出后重进，恢复末题反馈，不重复播放已保存答案音效。
4. 手动继续保存成功后才进入结算、播放完成/未通过音效，并在通过时开放目标路线。保存失败仍停留在反馈。

用时在最终判分时冻结，阅读最后反馈和等待继续的时间不延长成绩。旧的已结束记录没有新标记，保持原判分与已开放路线。

重进说明页也区分“恢复最后反馈”和“重新测试”：恢复第五次错误时仍显示零颗心，不能短暂误显示五颗心。先补失败回归，再修正该说明页条件；真实首页也核对恢复入口的心数。

新增单元回归覆盖最后答对、第五次错误、末题错误、恢复、迟到/重复事件、最后判分与继续保存失败；浏览器矩阵必含 `placement-final-correct`、`placement-final-wrong`。真实首页检查还使用原始音频、实际 localStorage 和 Service Worker 验证反馈 → 刷新 → 继续 → 结算。

## 3. 跳过范围优先，不足时向前补题，再不足就缩短

本轮用户明确要求只取当前未通过分区（含）到目标分区（不含）之间的题。旧规则在[当时的用户要求与参考](../../references/duolingo/2026-09-08-placement/README.md)中包含更早课程，算法按约 70% 跳过范围、其余更早范围补题；语法锚点和题型补足也可能取更早的题。因此不是只改一处比例就完成，必须统一限制所有抽样路径。

用户后续已确认：“如果题库数量不足，可以再向前获取题库，如果还是不足，可以把题目数量降低。”

新策略 `skipped-first-v1` 按以下顺序取题：

1. 先从当前未通过分区（含）到目标分区（不含）中抽取。语法、题型和跨度锚点都限制在这个范围；只要这里足够 20 个独立词句，就完全不取更早课程。
2. 跳过范围不足时先取尽，然后从最近的前序分区逐章向前补充。
3. 全部可用词句仍不足 20 时，使用实际题数。继续按完整原句归一化去重，目标课程和后续课程始终排除。
4. 20 题仍是第 5 次错误失败；短测验沿用至少答对 80% 的门槛，允许错误数为 floor(n × 20%)，再错一次即失败。例如 6 题至少答对 5 题，显示 2 次机会。题库为空时说明页提示不可测试，不生成可通过的空记录。
5. 新策略标记只写入新测试。旧 v1/v2/v3 抽样算法冻结，无策略标记的旧记录继续恢复原题序、草稿和判分。不会因本次算法改变而清空已通过课程。

此前从 Lesson 21–22 跳至 Lesson 25–26 的样本有 8 题来自更早课程；该范围本就不足 20，因此最新要求允许这种补题。真正需要修复的是旧算法在范围足够时也固定混入约 30% 前序题，以及前序补题不是从邻近章节依次取题。新增失败测试分别检测这两个差异，避免把已获用户允许的情况继续误报为缺陷。

全部 2,556 个起点/目标组合已核验：193 个跳过范围不足 20 个独立词句；当前完整题库均可通过前序补足。1、4、5、6、19 题的缩短路径使用删减可用题目的隔离夹具，保留真实 catalog 题目、控制器、判分与存储。空库、短测验通过/失败、末题反馈、刷新恢复均有回归；缩短范围并不代表新增或修改教学内容。

## 4. 为什么“本次用时”变成“剩余机会”

该改动首次出现于 `6872844`（2026-09-09 13:10 +08:00）的结算重构，早于本轮无键盘发布。当时实施文档的理由是跳级要恢复完整测试、尚无可恢复的前台计时，于是第三卡改用剩余机会。这是助手自行选择的替代方案，不是用户明确下达的指标修改命令。

已回查原始用户消息：用户要求基于 Duolingo 重构结算、把“完成步骤”改为“完成题目”，并为“最佳连对”“本次用时”重新绘制图标。没有要求把用时换成机会。实现应补齐计时能力；不能将指标替换归因于用户。

第一轮本地修复曾恢复“本次用时”和已有秒表图标，并持久化本次测试的前台耗时。听题/作答期间计时，切后台暂停，返回路线停止，恢复后继续累计，最终判分冻结。旧完成记录没有耗时则显示“未记录”；旧进行中测试缺失此前计时的，明确提示只含恢复后的记录，不编造历史用时。

计时新增回归还真实发现两个问题：可见性保存未合并选择草稿会使草稿日志失效；草稿保存失败时后台时间会误计入。分别先得到失败，再修复草稿合并和独立于保存状态的暂停逻辑。异常退出只能恢复最近成功保存的计时点，不能声称故障前最后一毫秒也可恢复。

用户随后明确说：“本次用时可以改成剩余机会，但是图标的风格要保持一致。”因此当前跳级结算按这次授权采用剩余机会，配新的薄荷绿 imagegen 心形图标，与现有金色勾选、蓝色靶心统一绘画材质、透明边缘及 24/30/36px 显示尺寸。普通关卡用时指标不变。已有计时记录和后台暂停回归仍保留兼容，但跳级结算不再显示用时或缺失用时提示。

新图标生成有两次结果未通过透明度检查（烘焙棋盘背景），均未使用。选用第三次带真实 alpha 的生成结果，只做等比缩小与 WebP 编码，没有代码去底；生成记录见[图标提示词与素材清单](../settlement/metric-icons/prompts.md)。
