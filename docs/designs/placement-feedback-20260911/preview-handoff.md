## 后续交付核对

1. 服务检查通过后，还要读取用户实际预览标签的 `[data-manifest-sha256]`，与该预览地址当前 HTTP 入口的值比较。值不同即不能交付“页面已更新”；未取得标签证据时明确标记未确认。
2. 检查对应页面的实际文案、素材与成绩，不能仅检查源码中存在目标文案。旧标签先记录状态与保存证据，正常刷新后再核对；进行中的作答不能被自动刷新打断。
3. 刷新前后核对记录保持。结算刷新回到地图时，明确区分真实页面显示、历史成绩的只读组件复核及隔离测试结果。
4. `node scripts/check-local-preview.js 42878` 仍作为服务检查；它没有浏览器标签访问能力，不能单独作为已有标签更新通过的证据。交付记录必须同时留下标签版本与目标状态检查。
