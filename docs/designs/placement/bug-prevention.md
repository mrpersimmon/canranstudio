# 跳级实现的问题与防护

## 1. 新增节点标记的背景无法可靠核验

- 症状/复现：通过跳级后返回地图，四种尺寸均在“跳级通过”标签触发对比度无法判定；普通节点没有该标签。
- 原因：立体按钮采用父级伪元素，标签延伸到按钮外，自动核验无法确定该文字的实际绘制背景。仅给文字背景着色不足以消除父级伪元素的歧义。
- 先前为什么没发现：旧矩阵没有跳级完成状态；新加的该状态立即拦截。本次失败运行不算验收通过。
- 修复：按钮表面改为独立、无语义的实际元素，保留原来的尺寸、层叠和按压反馈；标记显式指定深色背景。
- 防护：保留所有对比度检查，不排除标签，不降低阈值。跳级成功地图成为发布前必验状态。
- 同类范围：普通节点、已完成、跳级通过、未来入口、全部章节地图一起纳入四尺寸检查。

## 2. 展开关卡介绍会遮住节点下方标记

- 症状/复现：跳级后点击已跳过节点，介绍弹层压在“跳级通过”标签上。
- 原因：新标签与原有弹层占据相同区域，初始地图检查无法覆盖展开状态。
- 修复：展开时隐藏节点下方的重复标记，在介绍中显示“跳级通过 · 还可以完整学习”；按钮的可访问名称仍保留通过状态。
- 防护：增加已跳过节点的展开检查，继续检查实际遮挡与对比度。
- 同类范围：当前、锁定、跳级、完成四种节点的介绍入口及底部操作。

## 3. 重试说明页可能沿用上一次的零颗心

- 症状/复现：失败后点击“再试一次”，进入新一轮说明页时仍取上次失败记录显示零次机会。
- 原因：说明页展示与已结束测试使用同一条历史记录，忽略“继续未完成测试”与“开始新测试”的区别。
- 修复：继续旧测试显示已保存的剩余机会；开始新测试的说明页显示五颗心，开始后再持久化新尝试。
- 防护：增加重试说明页及新测试的实际检查；恢复未完成测试的检查仍要求保留已扣心数。
- 同类范围：首次说明、继续说明、失败结果、重试说明、重试首题。

## 4. 目录定位被后加载样式覆盖

目录跳转也需作为独立入口验收：实际点击 Lesson 5 & 6 后，原定位使入口上沿为 128px，悬浮章节栏底部为 144px，遮住了按钮上沿。原因是章节锚点没有考虑悬浮统计栏与标题，旧检查从直接点击节点开始，没有走目录链接。现为章节设置手机/桌面的滚动留白；选择章节后关闭目录、将键盘焦点移到目标标题，再由原生锚点导航定位。四尺寸新增目录到跳级入口检查，同时要求目录关闭、按钮完整出现在章节栏之下。所有 Lesson 分区共享该修复，不更改关卡行距。

复查还发现后加载的 `expansion.css` 将章节滚动留白覆盖为 18px，使第一次在路线样式中设置的 68/92px 未生效。已移除这条重复规则，让路线样式成为该属性的唯一维护处；防护网检查最终计算后的真实位置，不能仅凭源文件出现了正确数值就通过。

## 5. 手表整句被误标为单词输入

- 症状/复现：真实浏览器中，中文“这是你的手表吗？”上方显示“写出英文单词”，输入框也提示只写单词；实际判分要求完整句子。
- 原因：编译器用来源编号是否含有 `-W` 来判断词汇。派生句编号 `NCE-U01-C-Q-WATCH` 同样含有该片段，因此被误判。
- 先前为什么没发现：抽题与判分检查验证了答案和来源范围，未验证题型提示是否符合语言目标；视觉检查能识别遮挡与对比度，不能单凭颜色判断文案含义。人工逐屏复核发现后，旧检查记录不再作为最终证据。
- 修复：在已审核的基础题内容中显式声明单词输入类型，编译器直接读取，禁止通过编号片段猜测。整句使用“翻译这句话”与“用英文写出整句话”。
- 防护：先加入重现测试并观察失败，再修复；全部 592 个题目检查答案类型合法性，专门校验单词 `watch` 和包含 `WATCH` 的完整问句。浏览器每题核对任务标题，并注入错误题型标题以确认检查能拦截。
- 同类范围：基础词汇、派生问句、填空、后续章节整句输入一起检查。

## 6. 进度与判分的持续防护

| 风险 | 本次机制 | 回归证据 |
| --- | --- | --- |
| 快速点击多扣心/多推进 | 每题保存唯一判分，动作携带尝试与题目身份 | 连续双击与迟到事件检查 |
| 刷新获得新题或恢复心数 | 持久化题序、回答、游标与草稿，按种子核验 | 刷新恢复判分反馈及草稿 |
| 未保存即显示成功 | 原子写入确认后更新结果与开放路线 | 最后一题写入失败与重试 |
| 跳过课文伪造“已听完” | 独立跳级记录，仅影响路线通过范围 | 原始 completed/results/sourceContacts 等逐项不变 |
| 抽到目标章节或重复题 | 题目来源章节校验，按原句去重，分段抽样 | 所有 71 个目的地的范围、数量和去重 |
| 重置选做题误清跳级 | 区分普通挑战重置与全课程重置 | 重置与撤销记录检查 |

最终运行结果在 [根验收记录](../../../design-qa.md) 更新；表内机制不能单独代替实际浏览器验收。

## 7. 发布回归中的点击替身误判目录链接

- 症状/复现：发布前完整运行 `npm run verify` 时，104 项中 103 项通过；音频页面测试在第一次点击时报 `lessonLink.closest is not a function`，发布因此停止，官网仍保留旧版本。
- 原因：该测试的 `closest()` 替身忽略选择器，对任意查询都返回按钮。页面新增目录链接分支后，替身把普通按钮报告为目录链接，测试在执行原有音频断言前中断。真实 DOM 按选择器匹配，不具有这个行为。
- 先前为什么没发现：功能阶段最后一轮只重跑了受影响的跳级与路线检查，未包含这个旧的页面音频替身；实际浏览器使用真实 DOM，也不会暴露替身自身的问题。完整发布回归保留了这项检查并成功拦截。
- 修复：仅当查询 `button[data-action]` 时返回按钮，其余查询返回 `null`；不修改页面事件分发，不删除或放宽音频速度、停止旧播放、真实结束与手动继续的断言。
- 防护：页面事件委托新增选择器时，同步检查其 DOM 替身是否按选择器匹配；完整发布校验必须通过，不能用局部通过或浏览器通过替代。
- 同类范围：搜索全部单元测试的 `closest` 替身，只有该文件使用了无条件返回；浏览器检查使用原生 `closest`，无需替换。
- 验证：修复前完整校验有上述失败，修复后该文件 1/1 通过。最终完整重跑、发布提交与官网检查单独保存到 `output/playwright/placement-release-*` 发布证据；这次局部通过本身不代表已发布。
