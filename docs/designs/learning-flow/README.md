## 本轮结果

上一轮375×667实页复查发现，已有结算页仍采用约158px导航，下一关答题使用56px导航，往返时内容跳动约100px；短题偏在上方，旧粗边框与不同页面承载方式割裂。此次按用户认可的方向先完成Lesson1–2，没有重画人物、重构题库或推广新风格到其他单元。

- [学习呈现适配器](../../../unit1-2/learning-flow.js)与[样式](../../../unit1-2/learning-flow.css)只由Lesson1–2加载。共用`practice-screen`继续支持Lesson3–6原单屏布局。
- 阅读、答题、结算、封面、词卡和原纪念卡统一导航；结果仍经过原奖励门禁，按钮和统计没有绕开得星确认。
- 短题采用居中的暖纸卡面，细边框和轻阴影；主按钮为同一绿色。题目卡高度按视口固定到本题，选中和反馈不重新换列或移动操作。
- 内容进入190ms、6px轻移；新对白160ms轻显。系统减少动态和已有`canran-award-book-v1:motion`偏好参与判断，原纪念卡星光、飞星和三卡统计仍由原组件控制。
- 课文对白在内部滚动，最后一句完整可见；横屏保留完整人物和持物位置。归还后手提包位于女士自身坐标中，不再按整页固定偏移。
- 返回与重练沿用原状态；更多菜单仅接管自身、学习记录和设置的关闭回焦，奖励关闭继续回到当前学习操作。
- 导航箭头与更多使用仓库已安装的Phosphor图标，源码和许可证说明见[导航图标](../../../assets/learning-ui/README.md)。

## 首错与修复

1. `test-learning-flow-before`在课文页准确复现旧导航158px，不能只以答题页一屏通过作为流程完成。
2. 首稿测试把Playwright的`boundingBox()`当成含`bottom`的DOMRect，产生NaN；修正为`y + height`，保留严格的按钮位置断言。
3. 小屏一题出现4px多余滚动，收紧卡面短屏上下内边距后，37题严格布局专项通过，没有放宽阈值。
4. 连续阅读时最后一句看不见，最初不能只归因于滚动动画。诊断记录显示父容器`scrollLeft=314`、对白区域x=-287：旧`flex-direction:column`和换列规则与88px操作区冲突。显式改为单行横向按钮组，并保留最后一句完整可见及父容器不横滚断言。`test-learning-dialogue-diagnostic*`保留首错和截图。
5. 统一承载后，通用close监听器会把奖励关闭焦点抢到更多。`test-learning-flow-focus-before`先复现，再将回焦限定到菜单相关弹层；两个引擎独立复验通过。
6. Windows工作区CRLF与Git存储LF导致最初原始JS字节比较失败；改按Git对象校验题目源码一致，二进制原图仍做逐字节比较，没有为通过检查改动题库。
