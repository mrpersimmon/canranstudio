# 本地页面验收台

## 使用方式

在仓库运行 `npm run preview:review`，打开 <http://127.0.0.1:4401/>。不需要登录。服务只接受本机访问，不是手机外网测试站。

1. 左侧选 Lesson 1–2、3–4 或 5–6；点击目录即可直达。
2. 搜索支持 Lesson、题号、题干及题型，搜索时跨三个单元；例如 `lesson3-4`、`第6题`、`配对`。
3. 初次浏览时，状态按钮跟随课内实际作答。手动点击题目状态后，绿色按钮表示选定的预设，后续支持的题自动沿用。比如选“答错”，本题可照常订正并检查答案，点课内“下一题”后直接展示新题的错答反馈。也可用验收台的“下一页”连续浏览。点“取消沿用”可恢复跟随作答。手机上可横向滑动状态栏。
4. 点击“上一页／下一页”，或在非输入框、非弹层中使用左右方向键连续浏览。焦点在状态按钮组内时，左右键切换状态，Home／End定位首末状态。搜索期间按搜索结果浏览，清空搜索后按全目录浏览。
5. 切换页面尺寸可查看 SE、两档 Pro Max、320 小屏、平板和电脑。适合窗口只缩放外层画面，课程内部仍使用标注的 CSS 宽高；100% 模式可滚动查看。
6. “复制本项链接”保存当前验收项、实际展示状态、设备、星数和手动选择的换题预设。刷新会恢复当前画面和后续题的选择。“重置本页”恢复当前项对应的演示预设；“刷新代码”重新加载源文件及课程包。修改验收服务器本身后须重启该本地进程。

关闭后重新打开会记住上次验收项。只记页面偏好，不记真实学生作答。

## 覆盖范围

三个单元共 **215 个目录入口、106 道原题**，包含封面、每组词卡、39句课文的逐句场景、阅读完成、每一道题、各轮结算／得星、纪念卡、书面练习、参考资料、记录与更多菜单。Lesson 1–2／3–4／5–6分别为67／68／80个入口。

纪念卡可查看0–5星；得星可查看第1–5颗星及重看效果。演示姓名为“验收同学”，已有满星示例使用固定演示日期。新得星仍由原组件生成时间。纪念卡图像、题库、判分逻辑、授星规则没有为验收重写。

不覆盖登录、账号设置、跨设备同步、官网纪念册首页与其他69个单元。验收状态用于检查呈现和交互，不能作为教材答案、独立作答材料、真实得分或学习记录迁移的验收证据。

课程结尾导航补充（2026-11-08）：结算页只提供重练与查看纪念卡；进入纪念卡页后才显示“返回首页／下一课”。“下一课”可在前三个教学单元之间打开相邻课程封面；“返回首页”打开验收台课程目录，并说明正式课程会返回学习旅程首页。纪念卡不再提供“星星进度”展示状态，旧`state=tasks`链接自动回到原卡。切换0–5星可核对顶部对应环节的绿色对号，已学数量仍按真实题目完成事实计算。正式账号路径及首页跳转另由`tests/login/course-ending.spec.js`验证。

## 隔离与实现约束

- 独立的 `scripts/review-bench.js` 监听127.0.0.1。只允许GET／HEAD、固定工具文件和三个单元课程包。其他账号API、数据库路径、仓库文件及外部Host均拒绝。
- 不启动账号服务器，不打开学生数据库，不加载登录适配器。课程iframe内的localStorage／sessionStorage由内存实现，每次重开页面重新初始化；父工具只存自己的页面偏好。
- `createCoursePackages`复用真实源码、原插图、原CSS和缓存加载流程。只在验收构建的内存副本接入演示身份、轮次状态及本地授星账本，匹配点漂移必须报错，不能悄悄展示错误状态。
- 允许iframe嵌入只发生在验收HTTP响应及其独立缓存worker；普通发布包仍保持原来的禁止嵌入策略。正式页面不含验收入口或验收适配代码。
- 换页保留上一画面，下一页准备好后再替换。同项的题目、结果、词义、中文、纪念卡和得星状态直接更新已有文档，不重复加载或校验整课；首次进入、换页、“重置本页”、或课内自行跳页后恢复原验收项，仍走完整初始化。
- 每次应用预设都重建内存示例轮次并清除旧示例记录、奖励账本及结果节点；保留原组件的状态校验、判分与动画。请求顺序、来源窗口和预览实例同时匹配才能确认就绪，旧页面迟到通知不能结束新页面的等待。状态弹层由原课程组件打开；奖励在画面可见后才开始。
- 教材活动或题目变动时从真实定义生成目录；state模型必须通过原题型状态校验。涉及账号／服务端流程仍用正式测试环境验证，不给验收台增加真实API。
- **当前位置是状态操作的依据**：外层目录选择和内层学习操作必须双向同步。题号来自练习控制器的显示游标，回看使用回看游标，不能只读本轮完成进度或解析界面文案。外层只更新位置元数据，不重建正在学习的页面；收到状态指令时再次核对实际位置。连续状态指令沿用已确认的位置，不能使用尚未送达的旧外层题号。

## 本轮发现与修正

1. 真实封面被 `:is(#cover,#lessonWorkspace)` 的ID级隐藏规则覆盖；原 `.learning-surface` 的优先级不足，旧的 `#cover{display:grid}` 也覆盖了共用纵向布局。先复现可见性断言失败，再给**活动封面**补齐相同层级的可见与布局选择器；其他非活动页面保持隐藏。
2. 书面练习应走原“更多”菜单中的展开项；直接展开页面内部副本不能代表学生实际看到的入口。验收适配改为打开原菜单再展开原有练习副本。
3. 首轮测试误把隐藏奖励模板与当前纪念卡一起匹配，并误写了提示节点的类名；更正定位到可见卡和真实提示节点，不修改产品为错误断言让路。
4. Node fetch会标准化Host，无法用它构造外部Host测试；用底层HTTP请求复现请求头并验证403。
5. WebKit首轮把多题型、多个设备放入同一180秒用例，累计初始化耗时导致超时；同一追踪中每次进入约6秒、已有断言逐项通过。进一步计时显示一次暖加载的原缓存提交校验约4.8秒，动画帧没有长等待。隐藏iframe节流的猜测未获得证据，试验样式已撤销。保留原缓存校验，按题型及“设备×单元”拆分用例、消除重复打开默认状态；单次加载仍使用已有30秒边界，不能将批量超时冒记为通过。按设备拆分后的一次聚合用例仍超时，已停止该批剩余重复检查，保留失败记录；最终每个设备／单元独立运行并通过。
6. 封面最终补丁只提升 `visibility/display` 两项的优先级，保留原本740px最大宽度与间距。Chromium的外层缩放令IntersectionObserver比率得到0.999998而非精确1；改为检查课程内部CSS坐标的完整容纳，允许0.01px浮点误差，未放宽实际按钮裁切标准。

## 状态按钮与原地切换（2026-11-03）

旧版 `choose → openFrame` 把每次状态变化当作新页面，导致资源已缓存也重走课程初始化、缓存提交校验和场景启动。先用同题切换记录文档请求及 `performance.timeOrigin`，确认一次状态变化产生一个新课程文档；并非按钮本身响应慢。

| 同一题“已选”切“答错”的本机样本 | 修改前 | 修改后首次检查 | 最终检查 |
| --- | ---: | ---: | ---: |
| Chromium | 1478ms | 181ms | 194ms |
| WebKit | 7639ms | 419ms | 447ms |
| 新课程文档请求 | 1 | 0 | 0 |

以上为本地条件下的单次样本，包含点击和界面确认耗时，不是所有机型的性能保证。得星的原有播放时长不计作资源加载失败；首次进课仍需要准备资源。

按钮组使用原生按钮和 `aria-pressed`，保持焦点，移动端44px点击高度、容器内横向滚动，不能让整页横向溢出。快速操作保留最后一次请求，旧讲解／结果／得星动画先取消，再恢复独立演示状态。实现仅位于验收构建内存副本；生产课程、原题稿及课程缓存协议没有修改。

新增 `tests/review/state-switch.spec.js`：先复现新文档加载与下拉控件，再验证同文档切换、可逆状态、快速连续点击、重复应用当前状态、键盘焦点、三必测手机尺寸、原纪念卡／得星及存储隔离。还复现了“切状态后立刻翻页，旧就绪通知提前清除新页等待”的竞态：WebKit真实操作失败，Chromium用旧窗口迟到通知稳定复现；随后要求消息同时匹配最新全局请求。

早期失败保留于 `output/review-bench/state-switch-before/`、`state-switch-race-before/`、`state-switch-race-reproduced/`。补充测试曾把词块题中的 `my coat.`误写为`my`按钮，修正到原题实际的`No.`，未改变教材内容；失败保留于`state-switch-reapply/`。

Chromium与WebKit各完成17项去重相关检查，含六类题型、三个单元自身状态、SE375×667／Pro Max430×932／440×956、快速操作与旧通知隔离。主体结果位于 `state-switch-regression-chromium/`、`state-switch-regression-webkit/`；最后的消息顺序修正另跑两引擎计时／快速操作／迟到通知6项（`state-switch-final/`），各单元状态用例另见`state-switch-units-final/`；其余复用本轮未受影响结果，没有重复计数。额外的跨课测试曾假设每课都有独立讲解状态，实际上Lesson5–6只提供自身具备的状态；修正测试按真实目录取值，失败保留在`state-switch-units/`。

Node4项及检查工作流28项通过。三课原题稿Git对象与上次记录一致；未改变生产课程及缓存源码，没有运行全量CI或实体手机验收，未提交／推送／发布。

## 验证记录

### 连续验收题目（2026-11-06）

此前外层翻页和目录选题总是取目标页面的第一个状态。课内自然换题则同步新题的实际状态，手动选择会被检查答案的反馈覆盖。现在把当前画面（`state`）与手动选择（`preset`）分开保存，旧定位链接仍按原状态打开。遇到不支持该预设的题目或阅读、结算等页面，先显示该项自己的状态，遇到下一道支持的题继续沿用。

课内前进时，每个练习按本轮ID和当前题ID只应用一次预设，沿用原判分、显示与回看组件。在当前题订正、关闭讲解、从历史题返回时可以继续操作。继承预设只准备新题所需的演示数据，之前各题的错误次数、订正和只读回看均可核对。自动打开讲解或全文前复核题号和当前请求，避免把上一题的弹层带到新题。

回归用例位于 `tests/review/question-preset.spec.js`，含三种必测手机尺寸下的“答错→再试一次→检查答案→下一题→回看订正”，以及“已选未检查→检查答案→换题”、刷新、取消、目录跳转与可选讲解。原问题在 `output/review-bench/question-preset-before/` 复现。

本轮影响范围内 Chromium 14 项、WebKit 10 项、Node 与检查工作流 32 项通过。结果保留在 `output/review-bench/question-preset-chromium/`、`question-preset-controls/`、`question-preset-webkit/`。尺寸模拟覆盖 iPhone SE 375×667、iPhone 14/15 Pro Max 430×932、iPhone 16 Pro Max 440×956。没有运行全量 CI、实体手机或官网验收。
