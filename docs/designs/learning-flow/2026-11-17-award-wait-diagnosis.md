# 得星动画前等待：定位与修复方案

历史诊断记录：下文保留当时的定位与初始方案。用户随后确认“本地计算、即时飞星、远端后台复核”，当前实现见[本机即时得星记录](2026-11-17-local-awards.md)。问题范围为完成答题后的纪念卡／飞星等待，不包含GIF保存。

## 已确认的等待链路

当前飞星由页面动画绘制，动画本身不需要每次下载一个新动图。真正的新星必须等服务器核验整轮零错证据，服务端仍应保留最终授星权。

1. 完成练习产生最终作答快照和授星证明。
2. `server/public/access-client.js` 的 `saveQueue()` 将它放入普通同步队列，固定等待400ms才执行`flush()`；如果已有请求在进行，还会排队，旧请求结束后额外等待400ms再处理新快照。
3. `core/award-reveal.js` 很快打开已有星数的卡片，进入`pending`，显示“正在确认星星，请稍候。”。新飞星只在收到`lesson-awards:synced`之后开始。
4. `pending`和`animating`都被设为不可关闭；`unit1-2/completion.js`同时隐藏结算内容与操作。因此网络确认越慢，用户被锁住越久。网络失败要等最长15秒请求超时才会触发现有退路。
5. 确认后才播放约1.6秒的飞行与落星。正常入场动画约220ms；这段正常动效不是本轮优先修改对象。

问题是把网络确认的等待和动画播放的保护规则混在了一起。仅加速飞星或重新制作图片不能解决这一等待机制。

## 测量结果

使用4个独立诊断账号，未修改用户的学习记录。已核对部署版本和四个关键文件SHA与本地一致。测量结束后诊断账号全部停用。

| 场景 | 完成点击至飞星开始 | 至可关闭弹层 | 说明 |
| --- | ---: | ---: | --- |
| 核验过的工作站网络，首次／第二次得星 | 481–504ms | 2.10–2.13s | 三档手机尺寸共6次新星；提交在425–433ms才开始，真实请求约50–71ms。 |
| 同页已得星环节复练 | 无新飞星 | 259–267ms | 4次重放沿用原星数，资源准备与卡片展示无需长等待。 |
| 工作站默认网络，真实首次得星 | 1.82s | 3.45s | 确认请求约1.40s；没有人为增加延迟。 |
| 人为给真实确认请求增加4秒延迟 | 4.55s | 6.17s | 卡片46ms即进入pending，直到确认后才开始飞星；响应和授星结果未伪造。 |

正常链路下，弹层DOM打开约21–39ms；字体在完成点击前约1.6–2秒或更早就准备完毕。这些样本的主要等待不是完成时重新下载字体或插图。

尺寸为Chrome设备预设：iPhone SE 375×667、iPhone14/15 Pro Max 430×932、iPhone16 Pro Max 440×956，均在Chromium中运行。默认网络和4秒延迟对照使用SE尺寸。完整数据见[计时记录](award-latency/measurements.json)。这些是模拟尺寸和受控链路测量，**不是用户安卓微信／夸克那一次操作的网络抓包**，不把受控4秒实验说成用户实测耗时。

## 推荐修复

### 1. 完成练习的同步优先发送

- 普通作答继续合并同步，避免每次点击都发请求。
- 新完成／新授星证明在本次同步操作结束后的微任务中合并最终快照并立即发送，包含`unitCompleted`和完整授星证明；不在`record()`刚写一半时抢先发送。
- 已有请求进行时保留最新待发送快照；前一个请求结束后优先发送完成快照，不再额外等待400ms。
- 保持现有单请求顺序、持久化待同步队列、重置代次与重试规则，避免并行覆盖、重复授星或丢记录。第一阶段不更改授星接口协议。

### 2. 区分“等待确认”和“正在飞星”

- 完成后立即显示明确反馈：“本轮已完成，星星同步中。”已有星数和原纪念卡继续正确展示。
- 网络正常时维持“纪念卡 → 飞星 → 本轮结算”的顺序和原来的画风。
- 确认超过约1秒后提供明确的继续入口，让用户先看本轮结果／继续下一站；后台仍保存与同步，不把慢请求标成已失败，也不预发星。
- 用户仍留在等待页时，确认后播放当前新星；已经继续学习或离开时，只更新星数和轻提示，不重新弹卡打断。
- 飞星已经开始后，保留原来的防误触规则。超时、断网或授星未获确认时，必须有可继续的状态，不能无限期锁住页面。

### 3. 增加专门的时序回归

- 目标：点击完成后200ms内开始显示完成反馈；弱网等待约1秒后有可用的继续入口。它们是实施验收目标，尚未声明修复后已达到。
- 覆盖快速成功、4／8秒慢确认、15秒超时、断网、后台切换、离开后迟到确认、重复响应与复练；检查星数、首次日期和学习记录不变，未确认不加星，已确认只增加一次。
- 在三档必测手机尺寸验证按钮、反馈和卡片完整；最后再用用户的安卓微信、夸克实测。
- 去掉固定队列等待能减少这部分开销，实际端到端改善仍需实施后重新测量，不能把计划数值当成已实现性能。

第一阶段预计集中在共用同步调度与得星弹层状态，不重做72张纪念卡、不改题目、评分条件或历史记录。方案实施后再同步到现行统一标准和测试站。
