## 1. 重构目标

把当前“题目很多、动作重复、故事因果松散”的验证版，重构为六至八岁孩子能够独立看懂、愿意继续、能在故事中真正调用英语的完整教学单元。四项学习功能仍须完整覆盖，但只作为内部验收维度，不固定显示成“词汇 → 课文 → 语法 → 应用”四关。

不可退让的事实：

- catalog 是教材文字、课程文案、角色、选项、答案、支架、音频与完成条件的唯一真源；页面不得复制课程内容。
- 教材 Source ID 必须完整覆盖，但不为每个 Source ID 单独出题；每个核心目标必须至少有一次主动形成性检索。
- 所有主线语言音频持续显示对应英文；只有当前有效请求的真实 `ended` 可以开放音频门禁。
- 微任务是最小原子保存和恢复边界；章节完成产生章节成果，完整教学单元成功保存并读回后才建设地标。
- 当天完成不等于长期掌握；跨日、变化情境、无支架成功才可形成掌握证据。
- 目标儿童是六至八岁、无需成人讲解的初学者；不能以抽象术语、未教英语、文字负担或成人推理制造难度。

手机端审查进一步确认，这不是单一阶段的样式缺陷：十五阶段主要只复用“左右小人物加底部白卡”和“空背景加底部白卡”两种外壳。固定像素人物、道具与任务卡在 360×640 发生挤压和内嵌滚动，手机横屏发生裁切，终幕三个同侧人物完全重叠。当前 `sceneMode` 只作为数据属性输出，并未选择真实场景构图；这些事实成为 V2 移动端架构的反例证据，不再作为继续修补 V0 的理由。

## 2. 当前候选的真实体验证据

本轮完整试玩与实现审查发现，当前十五阶段候选约包含四十二个内部步骤、六十一次最低操作、四十九段必听音频和十八个正式提交步骤；其中衣物听音步骤包含两次提交，因此合计十九次正式语义提交。主要问题不是“功能缺少”，而是学习功能被拆得过碎：

- `Yes, it is.` 同日出现七次，`Excuse me.` 五次；`watch` 跨三个阶段重复处理，`Is this your watch?` 被重新组织两次。
- 词汇接触、词音检索、词形检索、句型替换和归还动作被拆成连续小题，孩子感受到的是反复考试，而不是解决故事。
- 盖章、拉杆、点亮已有线索等纯仪式动作被计成阶段，进度数字却不能准确表示“已经完成”。
- 手提包、手表、外套和 car/house 被写成多个相似认领流程，导致同一男女角色的身份与因果不可信。
- 页面整体重绘会反复销毁和创建媒体节点；音频失败后的文案、重试入口和状态恢复还存在不一致。

这些数字只描述当前本地十五阶段候选，不是下一版应达到的配额。

## 4. 已由证据确定、无需再做产品选择的修复

以下项目不改变课程目标，属于可用性、事实一致性或既有原则的直接修复：

1. 保存失败界面必须真正提供可操作的重试入口，不能只有未接线的处理函数。
2. “重新开始整个单元”必须二次确认；普通重进、刷新和返回不得清空学习记录。
3. 进度只表示已完成的学习边界；最后成果尚未触发时不能提前显示完成。
4. 已完成单元再次进入时直接显示成果或可选回看，不重演开场后再要求一次点击。
5. 音频失败采用有限重试；失败后不得使用“刚才听到”之类伪造成功听取的文案，也不得记录声音接触。
6. 任何降级或场景切换都必须同步更新可见英文、提示与当前人物，不能留下上一任务内容。
7. 去除 `it` 指代题中的答案泄露，以及“找错误”却实际要求选择正确项等提示与判定矛盾。
8. 盖章、拉杆、点灯等纯仪式不计为学习微任务；只保留一个真正改变故事结果的最终行动。
9. 避免每次状态变化整体重建媒体节点；保持当前音频请求、焦点与可访问状态稳定。
10. V2 必须消除手机端对话排序区的内嵌滚动和过小文字；未激活探索项要给出可理解反馈，不能静默吞掉点击。V0 只保留为问题证据，不为此单独修补。
11. 设置层级与关闭入口必须始终可见、可操作；动作提示要与“按、拉、推”的实际交互一致。

## 9. 随机候选的工程语义

“使用随机数制作选项顺序”不允许页面临时调用随机数后再用位置判断答案。现行合同是：

- catalog 只声明稳定候选实体、正确关系和支架，不声明“正确答案在第几个”；
- 运行时在一次微任务尝试开始时生成或注入随机种子，并据此洗牌；页面只渲染运行时给出的顺序；
- 同一次尝试的重绘、音频回调和设备旋转不得改变顺序；冒险心归零并完整重启微任务时才生成新顺序；
- 自动测试可以固定种子复现任意顺序，并验证所有位置都不会改变答案、证据或纠错；
- 排序随机只防止记位置，不等于新增一份词音、词形或词性学习证据。

## 12. 由双通道决定产生的结构冲突

Lesson 1–2 除二十二份词汇结果外，还必须至少结算课文主人理解、礼貌引起注意、请求重复、归属问句、肯定确认、感谢与一次变化句型迁移。若继续坚持每个内部微任务最多两次正式提交，则至少需要十四至十六个原子恢复微任务，不能同时把内部微任务总数限制为 Q6 所选的七至九个。

这不必变成十四至十六张儿童页面：一个持续的故事场景可以在视觉上无缝包含多个短恢复微任务。需要明确区分：

- **故事场景**：孩子感受到的一段连续剧情和一个主要目的；
- **恢复微任务**：内部原子保存、冒险心归零重启和目标证据的短边界；
- **正式词汇结果**：一个词在一个通道上的独立结果，不能因同屏出现而合并或伪造。

第四轮据此决定七至九这个数字究竟约束儿童可见故事场景还是内部恢复微任务，并重新确认单元时长和双通道在三个物品场景中的排列方式；结果见下一节。
