# 登录冷却提示与管理员改名

## 已核实问题

2026-10-25 线上排查确认：管理员账号在17:27:34–17:27:42（北京时间）有十次验证失败，随后触发账号冷却；截止时间一直为17:42:34，重复请求没有顺延。17:42:45使用用户提供的凭据成功登录，指定学生也成功进入目录。日志不记录密码，不能判定当时输入的具体内容，也不能直接确认攻击者身份。

原页面始终显示“十五分钟后再试”，没有呈现已返回的剩余秒数，导致临近到期仍像需要重新等待十五分钟。此次修复显示实际剩余倒计时和明确的北京时间解除时刻。

## 行为与范围

- 学生登录、管理员／老师管理登录共用此提示。保留每来源120次／分钟、每账号12次／分钟、十五分钟窗口内十次验证失败的既有限制，不降低防护。
- 429保留`Retry-After`，返回原始`retryAt`、对应`serverTime`与限制范围。拒绝不会推迟原截止时间。普通错误继续使用统一信息，不额外暴露账号是否存在。
- 浏览器按服务器时间差倒计时，以单调时钟计算已过时间；解除时间明确标注“北京时间”。错误的设备日期不会造成漫长等待。
- 等待期间暂停该表单的登录按钮，到期恢复，由用户再次点击；不自动提交密码、不轮询服务器。后台恢复按已过时间重算，不逐秒累减。刷新后再次提交由服务器返回当前剩余时间，浏览器提示不是安全边界。
- 账号限制下允许改用另一账号，原账号限制保持；来源或容量限制不能通过改用户名解除。管理员沿用大小写敏感规则，学生学号沿用去空格、转小写规则。
- 每秒变化的数字使用`role=timer`及关闭实时播报的区域，避免屏幕阅读器每秒打断；提示开始与结束仍可播报。

## 管理员改名

新增本地命令`node server/manage.js rename-admin <当前用户名> <新用户名>`。执行前保存SQLite与配套`card-key`，切换时停止其他写入并再次备份；当前用户名不匹配、格式无效或与老师工号冲突时拒绝。

仅更新现有管理员行的用户名，密码散列原字节保留，撤销原管理会话，清除新旧管理员标识自身的冷却；保留来源预算、其他账号冷却、学生／教师会话及学习数据。存在受保护的初始账号单时同步更新用户名，不重新生成或打印密码。新用户名属于私有运营配置，不硬编码到前端或公开文档。

旧用户名不再有效。改名能减少针对默认用户名的尝试，不能替代强密码和登录限制，也不证明恶意请求停止。此次不重置学生密码，不执行`system-upgrade`，不清学习记录、星数、证书或领取日期。
