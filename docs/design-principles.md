# 探险猫的首要设计原则：以 Duolingo 为基准

状态：用户明确指定，2026-09-06 生效。适用于课程编排、题型、UI、人机交互、关卡、角色、声音和动效。后续设计与实现都以本文件为入口；用户新的明确要求优先。

**尽可能采用 Duolingo 已有且适合本课程的设计。拿不准时，先查它的实际做法，再做决定。**

## 先参考，再设计

1. 找到要解决的学习任务与对应活动：辨认、组织语言、回忆、对话行动或复习。
2. 先看用户提供的对应 Duolingo 页面，再看本目录已有题型及交互资料。不明确时补查 Duolingo 官方页面、公开产品演示或真实界面。
3. 在设计记录中标明参考出处、观察到的行为和本课程的采用方式。把截图观察、官方说明与推断分开。
4. 如因教材、儿童能力或运行条件需要调整，说明学习收益和与参考的差异。资料能解答的常规问题直接查明；只有影响方向且仍无法判断的事项再与用户讨论。

## 一套连续的体验

- 地图、关卡内部、课本、复习、反馈和异常页共享同一主题背景。当前用户指定的参考是深色主题，基础背景采用地图已有的 #141f23。
- 文字、轮廓、插画、选择状态和底部操作建立层级。输入区与反馈区可使用略亮的同色系表面；页面切换保持背景连贯。
- 每屏突出一个学习动作：简短题目、角色/学习内容、作答区域、固定且明显的主要操作。词块有可按下的轮廓和底边，已使用词块保留空位。
- 动作语义稳定：作答 → 检查 → 反馈 → 继续；互动故事按用户操作推进，听完一句也不会自动跳到下一句。
- 未选择、已选择、正确、需要重试、禁用和播放中各有清楚状态。颜色配合边界、图标、文字与位置共同表达含义。
- 所有猫猫保持身份一致、主体完整、轮廓清楚；深色页面使用适配背景的透明素材，教学图片使用正常混合显示。

## 图像美术与生成方式

- 用户明确指定：角色、物品、场景、装饰等图像类素材统一采用迪士尼绘画风格，使用 imagegen 能力生成。
- 以已确认的猫猫原图作为角色母版，保持身份、服装、比例、表情语言与绘画质感一致；新物品与场景沿用同一美术方向。
- 生成记录保留参考图、提示词、工具来源和最终素材路径。先核对主体完整、教学辨识度及缩小后的清晰度，再接入页面。
- 透明背景须检查实际 alpha，不能把棋盘格当成透明。用户本次已授权对现有素材做本地去白底，完整保留原角色；这属于生成后的素材整理。

## 教学与题型

- 以可使用的语言能力组织连续路线，复习是路线中的组成部分；前六课教材和 catalog 仍是内容依据。
- 根据目标逐步减少帮助：图片/选项辨认、词块组织、句子补全，再到适合学生的自主表达。题型变化服务于学习目标。
- 参考 Duolingo 的词块翻译、自由输入、部分翻译、填空、互动故事与即时反馈；本次参考截图不意味着立即新增所有题型。
- 新题需说清“考什么、已教什么、为何这个干扰项合理、错误后如何帮助”。减少同一目标的机械重复，把复习用于间隔检索和迁移。
- 教学音频清楚、手动触发且可重听；角色与反馈回应当前行为。动效引导注意、确认操作或庆祝真实进展。

## 验收约束

### Bug 必须留下原因与复发防护

用户于 2026-09-06 明确要求：所有要修复的 bug 都要总结原因，并制定后续不再犯相同问题的方案。

- 每次修复记录原始现象、影响范围、可复现步骤、直接原因，以及为什么既有检查没有拦住。
- 先建立能复现旧问题的检查，再修复；同时检查真实用户操作与最终可见结果，不能只断言代码没有报错。
- 将防护加入持续执行的检查或素材验收规则，列明覆盖范围与证据。不能只写“以后注意”。
- 检查相同组件、同类题型、快速操作、失败恢复及不同屏幕下是否存在同一原因；视觉或听感问题另行保留实际页面证据。
- 最终记录分别说明实现、自动检查、实际页面验收、提交、上线状态。不宣称能绝对杜绝所有问题。

当前案例见 [Lesson 分区与交互修复记录](designs/lesson-sections-and-interaction-fixes/README.md)。

修改前明确采用哪张参考、哪个状态；完成后在相同尺寸对照实际页面。至少比较字体、布局、色彩、图像和文案，以及课内外连续切换。

可读性检查保留对比度、图片加载与可见性、按钮遮挡、窄屏和异常状态要求。新设计可以更新明确的视觉目标，不能减少检查范围、忽略未决项或沿用过期通过记录。主题一致性作为独立故障注入检查。
